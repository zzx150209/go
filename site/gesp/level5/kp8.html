二分答案

08
GESP 5级知识字典 · 知识点 08

判断单调性，求最小可行值与最大可行值。

检索词：单调判定边界取值
08

二分答案不是在数组里找某个元素，而是在一段候选答案中寻找可行与不可行的分界。它先用 check 判断一个候选值，再利用真假结果的单调变化排除一半范围。本课用木材切段完整学习“最大可行答案”，同时用一个短对照辨清“最小可行答案”的相反方向。

知识范围与官方定位

对应五级大纲“二分答案”：理解答案域的单调性与判定函数，能区分最小可行值和最大可行值，并在正整数答案范围内正确处理边界、类型与复杂度。

本页只使用一级至五级已经学习的语法和能力；小知识点按页内编号连续查询，不设置前置完成门槛。

是什么
二分答案把每个可能答案看成一个候选，用 check(x) 标记它可行还是不可行，再寻找真假分界。
解决什么问题
当最优数值难以直接计算、逐个尝试又太慢，但一个候选容易判断时，它能快速找到最小可行值或最大可行值。
什么时候使用
必须同时具备明确的整数上下界和单调真假序列；“候选是整数”本身不够。
核心思想
先从具体数据证明单调性，再建立只负责判定的 check，最后按目标选择真时向左或向右。
C++ 实现方法
本课沿用闭区间 left<=right；木材长度候选从 1 到 maxLength，最大可行时 true 记录并向右，false 向左。

01 从查找位置到查找答案

上一页的二分查找在有序数组里找位置，本页继续沿用闭区间、取中点和用 mid±1 排除已检查候选的写法；新问题是怎样在“答案范围”里找到最优数值。

主问题：有 4 根长度分别为 8、7、6、5 的木材，要切出至少 7 段等长木材，每段长度必须是正整数，求最大的段长。依次尝试 1、2、3、4 时，最多可切 26、12、7、5 段，所以真假依次为真、真、真、假；最大可行长度是 3。

本教学程序支持 1≤n≤100000、1≤length[i]≤10^9、1≤k≤所有木材长度之和。若从 1 一直试到 10^9，每个候选又扫描 n 根木材，会做太多重复检查；我们要先证明真假只有一个分界，才有理由二分。

具体样例与推演

场景：四根木材长度为 8、7、6、5，需要至少 7 段，先逐个检查正整数段长。

  1. 段长 1 时可切 26 段，段长 2 时可切 12 段，段长 3 时可切 7 段，这三个候选都可行。
  2. 段长 4 时只能切 5 段，不可行；段长继续增大时，每根木材能切出的段数都不会增加。
  3. 因此候选 1～8 的真假是 true、true、true、false、false、false、false、false，目标是最右侧的 true，也就是 3。
  4. 若逐个检查最多 10^9 个候选，每次再扫描最多 100000 根木材，重复工作太多；真假只有一个分界才允许每轮排除一半。

适用结论：二分答案不是因为“答案是整数”就能使用，而是因为 check 真假具有单调分界；先证明分界，再二分。

错误反例：只要候选答案是整数，就一定可以二分。

为什么错：整数只说明候选可以排列；如果 check 结果真假交替，从中点排除一侧可能删掉真正答案。

怎样改：先在具体候选上写出真假，再证明候选变大时判定为什么只会朝一个方向变化。

02 判定函数 check

候选段长为 x 时，一根长度为 length[i] 的木材最多贡献 length[i]/x 段。把所有贡献相加，段数不少于 k 就可行；多出的段可以舍弃，因此条件必须是 pieces≥k，而不是 pieces==k。

check(x) 只回答候选 x 是否可行，不修改 left、right 或 answer。累计段数 pieces 初始为 0，每检查一根木材就加上它的贡献；一旦 pieces≥k，后面的贡献只会让段数更多，可以提前返回 true。

为什么可以二分？若 1≤y≤x，那么每根木材都有 length[i]/y≥length[i]/x，求和后也不会变少。因此 x 可行时更短的 y 都可行，x 不可行时更长的值都不可行，候选域一定是“真……真、假……假”。

具体样例与推演

场景：用候选段长 3 完整执行一次 check，并说明它为什么当且仅当候选可行。

  1. pieces 初始为 0；长度 8 贡献 8/3=2，累计变成 2。
  2. 长度 7 贡献 2，累计 4；长度 6 贡献 2，累计 6。
  3. 长度 5 贡献 1，累计 7，已经不少于 k=7，所以 check(3) 返回 true。
  4. 每根木材最多贡献 length[i]/x 段，求和正好是能切出的最大段数；总数不少于 k 时可舍弃多余段，总数不足时任何切法也凑不够，因此这个判断当且仅当 x 可行。
  5. 若 1≤y≤x，则每项 length[i]/y≥length[i]/x，所以 x 可行时 y 一定可行，单调性由此得到。

适用结论：check 只计算段数并返回真假；pieces 达到 k 可以提前 true，但它绝不修改二分边界。

错误反例：return pieces == k;

为什么错：候选 2 实际可切 12 段，多出的 5 段可以不用；等号会把这个可行候选错判为 false。

怎样改：使用 pieces>=k；用 S1 复测 check(2)=true、check(3)=true、check(4)=false。

03 最小可行答案

先做一个不写程序的方向对照：某容量的判定依次为 check(13)=false、check(14)=true、check(15)=true，目标是找第一个 true，所以答案是 14。

这种“假……假、真……真”的最小可行问题中，mid 为 true 时先记录 mid，再把 right 移到 mid-1，继续向左寻找；mid 为 false 时把 left 移到 mid+1。它只帮助辨认方向，不是本课的第二个程序。

具体样例与推演

场景：只用三个容量值辨认“最小可行”方向，不建立第二份完整程序。

  1. 容量 13 时 check=false，说明 13 以及更小值都太小。
  2. 容量 14 时 check=true，容量 15 时也为 true，真假形态是 false、true、true。
  3. 目标是第一个 true，所以答案是 14；mid 为 true 时记录它并继续向左，mid 为 false 时向右。

适用结论：最小可行寻找右侧 true 区间的最左端；最大可行寻找左侧 true 区间的最右端，先看真值形态再决定方向。

错误反例：最小可行时，check(mid) 为 true 就令 left=mid+1。

为什么错：这会离开更小候选并朝右走，得到的更像最大可行值；在 13假、14真、15真的例子里会错过 14。

怎样改：最小可行的 true 分支应记录 mid 并令 right=mid-1；用三个容量值复测必须得到 14。

04 最大可行答案

木材题的真值在左边，目标是最右侧的 true。用闭区间 [left,right] 保存尚未排除的正整数候选，用 answer 保存已经证实可行的最大值；answer 初始为 0，只表示“尚未记录”，不是合法候选。

  • 初始化 left=1、right=maxLength、answer=0。
  • 闭区间非空时，计算 mid=left+(right-left)/2。
  • 调用 check(mid)，逐根累计可切段数。
  • 若为 true，记录 answer=mid，再令 left=mid+1，去右侧寻找更大可行值。
  • 若为 false，令 right=mid-1，因为 mid 及更大候选都不可行。
  • 两个分支都会排除 mid，区间严格缩小；left>right 时停止。
  • 输出 answer。数据范围保证长度 1 一定可行，所以它最终至少为 1。

具体样例与推演

场景：在 S1 的正整数闭区间 [1,8] 中寻找木材的最大可行段长。

  1. 初始 answer=0。第 1 轮 mid=4，check 得到 5 段，false；4 以及更大的候选都不可行，right 变成 3。
  2. 第 2 轮区间 [1,3]，mid=2；前两根已累计 7 段而提前 true，记录 answer=2，left 变成 3。
  3. 第 3 轮区间 [3,3]，mid=3；四根累计 7 段，true，记录 answer=3，left 变成 4。
  4. 此时 left=4>right=3，区间为空并停止。answer 保存的 3 已可行，所有更大候选也已因 false 分支排除，所以它就是最右侧 true。

适用结论：true 时记录并向右，false 时向左；两个分支都排除 mid，保证区间严格缩小并在 left>right 时终止。

错误反例：if (check(mid)) right = mid - 1;

为什么错：木材题求最大可行值；mid 可行时向左只会寻找更小值，无法检查是否还有更大的 true。

怎样改：改为 answer=mid、left=mid+1；重跑 S1 的 4假、2真、3真三轮，结果必须为 3。

05 答案范围与边界

合法段长必须是正整数，所以下界是 1，上界是最长木材 maxLength。不能从 0 开始，更不能调用 check(0)，否则整数除法会除以零。

所有木材长度之和最多是 10^14，k 和累计段数 pieces 都可能超过 int，木材长度与二分区间也统一使用 long long；数组 length[100005] 用 1 到 n，下标 100000 仍在容量内。

二分最多进行 O(log M) 轮，M=maxLength；每轮 check 最坏扫描 n 根木材，所以总时间是 O(n log M)。静态数组保存 n 个长度，空间复杂度是 O(n)。单元素、k=1、k=总长度、left=right 和 10^9 极值都要单独检查。

具体样例与推演

场景：逐项检查木材程序的合法候选、类型、容量、复杂度和极端输入。

  1. 段长必须为正整数，因此 left=1；right=maxLength，因为任何段不可能长于原木。answer=0 只表示尚未记录，不会传给 check。
  2. D1 保证 k≤sum(length)，所以 x=1 一定可行；即使只有一根长度 1 的木材，闭区间 [1,1] 也会检查一次并把 answer 更新为 1。
  3. 100000 根木材都为 10^9 时，长度总和和 x=1 的段数都是 10^14，k 与 pieces 必须使用 long long；length[100005] 的最大使用下标 100000。
  4. 每轮 check 最坏扫描 n 根木材，二分轮数是 O(log M)，所以总时间 O(n log M)，而不是 O(log M)；保存数组需要 O(n) 空间。
  5. 极值复测：k=1 时答案为 10^9，k=10^14 时答案为 1；多余段测试还要确认 pieces>=k。

适用结论：候选从 1 开始，类型覆盖 10^14，复杂度计入每次 check；最小、重合、k=1、k=总长度和极值都要实际运行。

错误反例：long long left = 0; // 随后调用 check(0)

为什么错：pieceLength=0 会出现在除数位置，产生除零错误；0 只是 answer 的未记录标记，不能进入候选区间。

怎样改：令 left=1；复测单根长度 1、k=1 时只检查合法候选并输出 1。

典型例题

基础例题：木材切段的最大长度

题意：输入木材根数 n、需要的最少段数 k 和 n 根木材长度。数据满足 1≤n≤100000、1≤length[i]≤10^9、1≤k≤所有长度之和；每段长度必须是正整数，可以切出多于 k 段。求能切出至少 k 段时的最大段长。

示例输入：

4 7
8 7 6 5

示例输出：

3

说明：段长 3 时四根木材分别贡献 2、2、2、1 段，恰好 7 段，所以 3 可行；段长 4 时只能得到 5 段，所以 4 及更大值都不可行。闭区间三轮依次检查 4、2、3，最终记录 3。

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;

int n;
long long k;
long long length[MAXN];

bool check(long long pieceLength) {
    long long pieces = 0;
    for (int i = 1; i <= n; i++) {
        pieces += length[i] / pieceLength;
        if (pieces >= k) {
            return true;
        }
    }
    return false;
}

int main() {
    cin >> n >> k;

    long long maxLength = 0;
    for (int i = 1; i <= n; i++) {
        cin >> length[i];
        if (length[i] > maxLength) {
            maxLength = length[i];
        }
    }

    long long left = 1;
    long long right = maxLength;
    long long answer = 0;

    while (left <= right) {
        long long mid = left + (right - left) / 2;
        if (check(mid)) {
            answer = mid;
            left = mid + 1;
        } else {
            right = mid - 1;
        }
    }

    cout << answer << '\n';
    return 0;
}

典型应用：把需要段数改为 8

题意：仍使用长度 8、7、6、5 的四根木材，把目标改为至少 8 段，先手算 check(3) 和 check(2)，再判断最大可行长度。

示例输入：

4 8
8 7 6 5

示例输出：

2

解题说明：段长 3 只能得到 7 段，不可行；段长 2 能得到 12 段，可行。单调性保证更大的段长也不可行，因此最大可行值是 2。

常见错误

  • 模型错误：只因候选是整数就二分：症状：check 真假交替，程序可能排除真实答案；原因：没有单调分界；修复：先用具体候选写出真假并证明分母增大时段数不增；复测：检查 2、3、4 得到 true、true、false。
  • 判定错误：把至少 k 段写成恰好 k 段：症状：段长 2 可切 12 段却被判为不可行；原因：误写 pieces==k；修复：使用 pieces>=k，允许舍弃多余段；复测：S1 的 k=7、x=2 必须返回 true。
  • 边界方向错误：从 0 开始或 true 时向左：症状：前者会除以零，后者只能找到更小可行值；原因：把哨兵当候选或混用最小可行方向；修复：left=1，true 时记录并 left=mid+1；复测：S1 必须经历 4假、2真、3真并输出3。
  • 类型与复杂度错误：段数用 int 或只写 O(log M)：症状：极值累计溢出或低估运行量；原因：忽略最多 10^14 段以及每轮 check 扫描 n 项；修复：k、pieces 和区间值用 long long，复杂度写 O(n log M)；复测：100000 根 10^9 木材在 k=1 与 k=10^14 时分别输出 10^9 与1。

模型维度：没有单调证明就套模板

错误代码：

// 候选是整数，所以直接二分

错误原因：可观察症状是相邻候选的 check 真假可能来回变化，排除一侧时会同时删掉真实答案。精确原因是整数性不提供单调信息。

正确写法：

// 先列出具体真假，再证明 x 增大时总段数不会增加
// 复测：check(2), check(3), check(4) 应为 true, true, false

判定维度：把至少写成恰好

错误代码：

return pieces == k;

错误原因：S1 的 x=2 可切 12 段，会被错误判成 false；题目允许从 12 段中取 7 段。

正确写法：

if (pieces >= k) {
    return true;
}
// 复测：S1 的 check(2) 必须为 true

边界维度：把 0 当候选或走错方向

错误代码：

long long left = 0;
if (check(mid)) right = mid - 1;

错误原因：mid 可能为 0 并触发除零；即使未除零，最大可行问题在 true 时向左也会错过更大答案。

正确写法：

long long left = 1;
if (check(mid)) {
    answer = mid;
    left = mid + 1;
}
// 复测：S1 输出 3

类型与复杂度维度：忽略累计和 check 扫描

错误代码：

int pieces = 0;
// 时间复杂度 O(log M)

错误原因：极值下段数可达 10^14，int 会溢出；每一轮二分还要扫描最多 n 根木材。

正确写法：

long long pieces = 0;
// 总时间 O(n log M)，空间 O(n)
// 复测：100000 根 10^9 木材的两个极值

第 1 题二分答案需要判定结果具有什么性质？

答案：A
只有真假分界清晰，才能安全排除一半答案。 因此“随答案单调变化”正确，其余选项混淆了定义、条件或边界。
对应知识点：01 从查找位置到查找答案

第 2 题check(x) 的作用是什么？

答案：D
二分负责缩小范围，check 负责回答可行性。 因此“判断候选答案 x 是否可行”正确，其余选项混淆了定义、条件或边界。
对应知识点：02 判定函数 check

第 3 题寻找最小可行值时 check(mid) 为真，通常怎样做？

答案：C
mid 可行，但更小答案也可能可行。 因此“记录 mid 并继续向左”正确，其余选项混淆了定义、条件或边界。
对应知识点：03 最小可行答案

第 4 题寻找最大可行值时 check(mid) 为真，通常怎样做？

答案：B
mid 可行，还要尝试更大的可行值。 因此“记录 mid 并继续向右”正确，其余选项混淆了定义、条件或边界。
对应知识点：04 最大可行答案

第 5 题二分答案开始前首先要确定什么？

答案：A
正确范围与单调方向决定更新规则和边界。 因此“答案上下界和单调方向”正确，其余选项混淆了定义、条件或边界。
对应知识点：05 答案范围与边界
