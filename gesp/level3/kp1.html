数据编码

01
GESP 3级知识字典 · 知识点 01

确认每个数使用的二进制位数，判断能表示的整数范围。

检索词：二进制位数整数范围

本课先记住

  • 核心结论： 一串 0 和 1 必须结合固定位宽和编码规则才能确定真值；8 位补码能表示 -128 到 127。
  • 常用语法： 本课不新增 C++ 语法；常用判断规则是先确认位宽和编码方式，负数补码再按“首位判负 → 逐位取反 → 加 1 → 恢复负号”读回真值。
  • 最小示例： 8 位 -5 的原码、反码、补码依次是 10000101、11111010、11111011。
  • 关键易错点： 不能丢掉前导 0 或符号位，也不能把无符号位串直接当成有符号补码；计算前先检查数值是否落在当前位宽的范围内。

知识范围与使用边界

先看一个具体问题：同样是 8 个二进制位，10000000 按无符号数读取是 128，按原码读取是 -0，按反码读取是 -127，按补码读取却是 -128。位串本身没有变，改变答案的是位宽和编码规则。本课要解决的就是：怎样写出正负整数的固定 8 位编码，又怎样从位串读回正确真值。

计算机只能保存 0 和 1。要把整数放进有限个二进制位里，必须先约定：一共有多少位、最高位代表什么、负数怎样编码。本课只讨论固定宽度的有符号整数，重点是原码、反码和补码；以 8 位为例学习判断表示范围和把补码读回真值。

固定宽度不是装饰。5 可以写成 101，也可以写成 8 位的 00000101；两种写法数值相同，但后者才说明“这个数占 8 位”。位数一旦确定，最左边就是最高位，不能随意添删。下面所有二进制串都按 8 位阅读，缺少的高位用 0 补齐。

这里的“位”就是 bit（比特），一个 bit 只能保存 0 或 1。在常见 GCC/OJ 环境中，连续 8 个 bit 组成 1 byte（字节），所以一个 8 位编码正好占 1 字节；N 位一共能够排出 2^N 种不同位串。位串怎样对应真值，还要看题目把它解释为无符号数、原码、反码还是补码，不能只凭“有多少种”直接判断正负范围。

真实 C++ 类型的大小用 sizeof(类型) 查看，结果的单位是字节。在常见 GCC/OJ 环境中，sizeof(char) 是 1，sizeof(int) 通常是 4，也就是一个 int 通常占 32 位；但本课的 8 位例子是为了把编码过程完整写开，并不表示 C++ 的 int 只有 1 字节。遇到具体题目时，优先使用题目明确给出的位宽。

本课的目标是：看见一个 8 位数，先判断它是正还是负，再按补码规则得到十进制真值；也能把一个在范围内的十进制整数写成 8 位补码。这里不要求把函数、指针、作用域或递归作为掌握内容。实际 C++ 中整数类型的位宽由实现决定，因此示例只展示确定的位串与普通算术，不依赖移位负数等容易产生歧义的写法。

  • 已经会用： 整数的正负、加减法，以及 5 = 4 + 1 这类小整数算术。本页需要的二进制位权会随例子直接说明，不假定已经学完下一页的进制转换。
  • 本课新学： 固定 8 位下的正负编码动作；原码、反码、补码的差异和补码用途；补码范围、真值读取与越界判断。
  • 暂不展开： C++ 对象在内存中的真实字节顺序、有符号整数溢出的语言规则、位运算语法、浮点数编码，以及函数、指针、作用域和递归。

01 原码、反码与补码

先从正数开始。正数的原码、反码和补码完全相同：符号位为 0，其余位写出数的二进制。例如十进制 5 的二进制为 101，写成 8 位就是 00000101。因此 +5 的原码、反码、补码都是 00000101。

负数才会出现差别。对 -1 到 -127，先写出与其绝对值对应的 8 位正数表示；把最左位改为 1 得到原码；除符号位外其余每一位 0、1 互换得到反码；反码再加 1 得到补码。以 -5 为例，过程必须完整写出：

02 三种编码的差异

理解三种编码时，可以把它们看成逐步改进的三种方案。先从最直观的想法开始：留出最高位表示正负，其余位保存绝对值，这就是原码。原码容易读写，但如果把所有位直接送入普通二进制加法器，结果不一定符合有符号整数运算。

以 4 位表示为例，原码中的 +1 是 0001，-1 是 1001。直接相加得到 0001 + 1001 = 1010。若仍按 4 位原码解释，1010 表示 -2，而不是应有的 0。问题在于：原码的最高位只负责标记符号，不能和其余位一起按普通二进制权值参加加法。

一种改进思路是把负数除符号位外的各位取反，得到反码。4 位反码中，-1 是 1110，于是 0001 + 1110 = 1111。这个结果在反码中表示“负零”；反码确实改善了正负数运算的对应关系，却保留了 0000（正零）和 1111（负零）两种零。相同的数值有两种编码，会让判断和运算规则不够统一。

补码在负数反码的基础上再加 1。4 位补码中的 -1 是 1111，所以 0001 + 1111 = 1 0000。在固定 4 位中只能保留低 4 位，结果为 0000，正好是 0。此时最高位也成为数值权值的一部分，正数和负数能够使用同一套定宽加法规则。

03 补码的运算与范围

补码最重要的作用，是把减法转成加法：a - b 可以按 a + (-b) 处理。仍用 4 位补码验证 5 - 3：+5 是 0101，-3 是 1101，相加得到 0101 + 1101 = 1 0010；保留低 4 位 0010，结果就是 2。这样，加法和减法都可以复用同一套定宽加法电路，不需要为原码的符号位另外设计一套加减规则。

不过，“保留低 4 位”有明确前提：题目正在讨论固定 4 位，并且真实结果 2 落在 4 位补码的范围 -8 到 7 内。补码并不会让溢出消失；如果真实结果超出当前位宽的范围，截去高位后可能得到另一个数，必须另行判断是否溢出。

回到 8 位，11111011（-5）与 00000101（+5）相加得到 1 00000000；固定 8 位保留低 8 位就是 00000000。这与前面的 4 位示例遵循同一条规则，也说明补码为何能让正数和负数共用加法过程。

三种编码的 8 位范围并不完全相同：

把 8 位推广到 N 位后，补码只有一个 0，表示范围是 -2^(N - 1) 到 2^(N - 1) - 1。代入 N = 8，得到 -128 到 127；总数仍是 256 个，恰好对应全部 2^8 种位串。左端比右端多一个绝对值，是因为补码没有“负零”，把这个编码位置留给了 -128。

原码和反码都存在“正零”和“负零”两种编码，这会让同一个数值 0 有两种写法；补码把 0 统一为 00000000，并把空出来的一个编码用于 -128。

因此，上面的“绝对值 → 原码 → 反码 → 补码”对 -1 到 -127 适用，不能机械套到 -128：128 的绝对值需要 8 个数值位，已经放不进“1 位符号 + 7 位数值”的 8 位原码或反码。8 位补码则把 10000000 用作 -128，从而获得 -128 到 127 的完整范围。

从补码角度看，首位为 0 时，有 7 个数值位可变化，得到 00000000 到 01111111，即 0 到 127；首位为 1 时，得到 10000000 到 11111111，即 -128 到 -1。注意负数比正数多一个：10000000 表示 -128，但没有对应的 +128。

读补码真值有两条稳定规则。首位是 0，它是非负数，直接按二进制权值展开；首位是 1，它是负数，可以“按位取反再加 1”，得到绝对值后加负号。还可以把最高位看成 -128，其余七位仍按 64、32、16、8、4、2、1 相加。两种方法应该给出同一个答案。

04 补码转换与真值

下面把 -5 的编码过程逐行跟踪。每次都保留 8 位，才不会把符号位和数值位混在一起。

现在反向读 11111011。首位是 1，先确定它一定是负数；取反得到 00000100，再加 1 得到 00000101，其绝对值为 5，所以真值是 -5。不能把 11111011 直接当作无符号数 251，也不能只把首位删掉后读成 123。

从位串一步步读回 -5

另一种心算方法是权值法：11111011 = -128 + 64 + 32 + 16 + 8 + 2 + 1 = -5。最高位不是 +128，而是 -128；这是补码读真值最容易遗漏的一点。对于 10000000，权值法立刻得到 -128，也解释了 8 位补码范围的左端点。

典型例题

例题：某题给出 8 位补码 10110110，求它表示的十进制真值；再判断十进制 130 能否用 8 位补码表示。

第一问，首位为 1，所以它是负数。按位取反：01001001；再加 1：01001010。01001010 = 64 + 8 + 2 = 74，故原补码的真值为 -74。用权值法核对：-128 + 32 + 16 + 4 + 2 = -74，结果一致。

第二问，8 位补码范围为 -128 到 127，130 大于 127，不能表示。不要因为 130 的无符号二进制可以写成 10000010 就认为可行；若把这个 8 位串按补码读取，它的真值是 -126，已经不是 130。题目只要强调“有符号 8 位补码”，就必须先做范围判断。

再看一个加法检查：-5 的补码为 11111011，+5 的补码为 00000101。逐位相加会产生第 9 位进位，保留 8 位结果 00000000，即 0。固定宽度意味着超出范围的高位不能保存在这个 8 位格子中；在真实程序里，是否溢出及其后果要看类型和语言规则，做题时先按题目给定的位宽分析。

完成这类判断的成功标准

完成上面的典型例题后，可以按四点检查自己的过程：先写清“8 位补码”这一解释规则；编码前先判断十进制数是否在 -128 到 127；读负数补码时保留 8 位写完取反和加 1；最后用最高位 -128 的权值法复核，两种读法必须得到同一个真值。四点都能在纸面过程里找到，才算完成判断。

把补码当成普通二进制

× 错误写法11111011 = 128 + 64 + 32 + 16 + 8 + 2 + 1 = 251，所以它表示 251
✓ 正确写法11111011 = -128 + 64 + 32 + 16 + 8 + 2 + 1 = -5

原因：251 是把该位串按无符号整数读取的结果。题设若说明是 8 位补码，最高位的权值应为 -128，位串表示的是负数。

检查方法：先看题目给的是无符号数、原码还是补码；编码规则不同，同一串 0 和 1 的真值也不同。

对这道错解做一次复验：按 8 位补码权值计算，11111011 = -128 + 64 + 32 + 16 + 8 + 2 + 1 = -5，与取反加一的结果一致；无符号读法得到的 251 不能作为本题答案。

常见错误

  1. 忘记固定宽度。 现象：把 5 写成 101 后直接取反。原因：三位位串没有为 8 位题目保留符号位。修正：先写成 00000101，再保持 8 位完成后续步骤。复验：逐行数位数，每一行都必须正好有 8 位。
  2. 混淆三种编码。 现象：把 11111010 当成 -5 的补码。原因：只完成了取反，还没有执行最后的加 1。修正：按原码、反码、补码顺序写出 10000101 → 11111010 → 11111011。复验：用取反加一读回，最终绝对值应为 5。
  3. 负数补码少加了 1。 现象：由 00000101 取反得到 11111010 后立即停下。原因：把反码误认为补码。修正：在反码基础上再加 1。复验：11111010 + 1 = 11111011，再与 -5 的标准过程核对。
  4. 只看剩余七位。 现象：删掉 11111011 的首位后把后七位读成 123。原因：补码的最高位也参与数值计算，不能只当正负标签删掉。修正：使用 8 位取反加一，或把最高位按 -128 计算。复验：两种方法都应得到 -5。
  5. 把 -128 套入普通负数步骤。 现象：试图先写 +128 的 8 位原码再转换。原因：一位符号加七位数值只能保存绝对值 0 到 127。修正：记住 8 位补码把 10000000 专门用于 -128。复验：按权值计算 -128 + 0 = -128。
  6. 漏掉表示范围。 现象：把 130 写成 10000010 后说它是 8 位有符号补码。原因：没有先检查 -128 到 127 的范围。修正：编码前先做范围判断，超出范围就回答“不能表示”。复验：10000010 按补码读回是 -126，不是 130。
  7. 混用无符号与补码读法。 现象：同一道题中一会儿把最高位算作 128，一会儿算作 -128。原因：没有固定解释规则。修正：计算第一行先写清“无符号”或“8 位补码”。复验：10000000 按无符号、原码、反码、补码应分别得到 128、-0、-127、-128。

关联学习

下一页“进制转换”会系统讲怎样在二、八、十、十六进制之间转换；本课只使用读懂固定 8 位所需的最小位权。后面的“位运算”会讲怎样逐位处理 0 和 1；本课先负责确定这些位应按哪一种有符号编码解释。两页都不能代替本课的位宽、符号和范围判断。

本课小结

本课只收束三个核心：先固定 8 位再做正负编码；用原码、反码、补码的运算差异理解补码用途；读补码时先判符号和范围，再用取反加一或最高位负权值法复核真值。只要位宽、规则或范围没有写清，后面的计算就不能算完成。
