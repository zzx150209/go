复杂度分析

10
GESP 8级知识字典 · 知识点 10

分析常见算法复杂度，按数据范围选择算法。

检索词：复杂度范围判断

知识范围与官方定位

官方八级要求理解算法的时间效率，能够分析循环、递归和常见算法的时间复杂度，并根据数据规模判断程序是否可行。复杂度描述的是输入规模增大时操作次数的增长速度，不等于程序实际运行的秒数。

01 常见时间复杂度

常见增长速度从慢到快大致为：

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

分析时保留增长最快的项并省略常数。例如 3n²+10n+5 记为 O(n²)。这不是说低次项不存在，而是当 n 很大时，最高次项决定主要增长趋势。

02 顺序、分支与循环

顺序执行的几段代码，复杂度取其中增长最快的一段；if...else 通常看最坏情况下较慢的分支。

  • 单层循环执行约 n 次，通常是 O(n)。
  • 两层循环都执行约 n 次，通常是 O(n²)。
  • 循环变量每次乘 2，如 i = i * 2，通常执行约 log₂n 次。
  • 嵌套循环不能只看层数，还要看每层的实际边界。例如内层执行 i 次，总次数是 1+2+...+n，仍为 O(n²)。

03 数据范围与可行性

同一个算法在不同数据范围下结论不同。若 n=1000，n² 约为一百万，常常可以接受；若 n=100000，n² 达到一百亿，通常不可行。

判断时还要考虑常数、输入输出、语言和评测环境，因此不能把某个操作次数当作绝对边界。稳妥做法是先估算数量级，再给速度较慢的操作留出余量。

04 常见算法的复杂度

算法或操作 常见时间复杂度
数组按下标访问 O(1)
扫描整个数组 O(n)
二分查找 O(log n)
常见高效排序 O(n log n)
邻接矩阵 Dijkstra O(n²)
Floyd O(n³)
枚举全部子集 O(2ⁿ)

表中的结果要结合具体实现使用。例如使用不同图存储结构时，Dijkstra 的复杂度也会不同。

操作次数追踪。 外层让 i 从 1 增加到 n，内层让 j 从 1 增加到当前的 i。内层次数依次为 1、2、…、n，总次数是 n(n+1)/2，所以是 O(n²)，不是看到两个循环就机械写 n×n。

规模判断要落到数量级：n=20 时枚举全部子集约有 2^20≈10^6 个，可能可行；n=100000 时 O(n²) 约为 10^10 次，通常不可行。对同一张 n=300 的稠密图，朴素 Dijkstra 约按 n² 增长，而 Floyd 按 n³ 增长，是否需要任意两点答案会直接影响选择。

逐段具体推演（对应 01—04）。

01 增长速度。 n=5 时，线性操作约 5 次，平方约 25 次，枚举子集约 2⁵=32 次，全排列约 5!=120 次。n=10 时 10!=3628800，阶乘增长很快，通常只适合很小的 n。

02 代码结构。 两个先后执行的循环各跑 n 次，总次数是 n+n=2n，所以为 O(n)；两层完整嵌套才是 n×n=n²。若内层只跑到 i，总次数为 1+2+...+n=n(n+1)/2，仍是 O(n²)。

03 数据范围。 n=1000 时，n²=10⁶；n=100000 时，n²=10¹⁰。同一段双循环从可能可行变成通常不可行，判断依据是操作数量级，不是代码行数。

04 常见算法。 对 n=300 的稠密图，邻接矩阵 Dijkstra 约做 300²=90000 级别的扫描；Floyd 约做 300³=27000000 次状态检查。只求一个起点时前者更合适，需要任意两点答案时才考虑后者。

典型例题

下面程序中，第一段循环执行 n 次，第二段双重循环执行 n² 次，总次数约为 n+n²，所以时间复杂度为 O(n²)。若 n=100000，就应寻找只扫描一次或 O(n log n) 的方法。

#include <bits/stdc++.h>using namespace std;
int main() {    int n;    cin >> n;    long long count = 0;
    // 第一段独立循环执行 n 次。    for (int i = 1; i <= n; i++) {        count++;    }    // 第二段是完整双重循环，共执行 n×n 次。    for (int i = 1; i <= n; i++) {        for (int j = 1; j <= n; j++) {            count++;        }    }
    cout << count << '\n';    return 0;}

常见错误

顺序循环相乘反例。 先扫描 n 个数求和，再扫描 n 个数求最大值，两段各执行 n 次。错误写成 O(n²) 是把先后执行误当嵌套；实际总次数约 2n，省略常数后为 O(n)。

  • 只数循环层数，不检查循环边界和变量变化。
  • 把两个先后执行的循环复杂度相乘。
  • 认为 O(n²) 在任何数据范围下都一定超时。
  • 忽略递归分支数和递归深度。
  • 把复杂度写成实际运行秒数，或认为同复杂度的程序一定同样快。
