顺序结构

08
GESP 1级知识字典 · 知识点 08

按顺序完成输入、计算和输出，并通过变量变化检查。

检索词：顺序执行变量追踪

本课先记住

  • 核心结论： 顺序结构按书写顺序逐条执行，每条语句都读取当时的变量值并留下新状态；程序语句不是同时成立的数学方程。
  • 常用流程： 先读入数据，再按题意计算中间量，最后按要求输出；修改变量时在每条语句执行后记录一次状态快照。
  • 最小示例： a = 2; a = a + 3; 先把 2 保存到 a，第二句再读出 2 并写回 5，最终 a = 5。
  • 关键易错点： 交换两个变量时不能先覆盖旧值；单位换算要用余数继续拆分，输出也必须在正确的执行时刻读取变量。

知识范围与官方定位

本页对应 GESP C++ 一级大纲中的“顺序结构”。前面已经学过变量怎样保存当前值、赋值怎样先算右侧再写左侧；现在把多条语句连成一条真实执行路线。

本页集中解决三个问题：

  1. 为什么顺序结构是程序的默认执行方式？
  2. 每执行一条语句，变量状态怎样一步步变化？
  3. 怎样用输入、手算、状态表和实际输出验证一段顺序程序？

本页所有主过程都沿一条路线执行，不使用条件选择，也不重复执行某段代码。分支和循环会在后面的课程中分别学习。

01 从上到下执行

顺序结构是一条连续路线

程序进入 main 后，如果没有分支、循环等结构改变路线，普通语句会按照书写顺序从上到下执行。前一条语句执行完成，下一条才开始；后一条看到的是前面已经留下的新状态。

进入 main   ↓执行第 1 条语句，更新程序状态   ↓执行第 2 条语句，读取更新后的状态   ↓继续执行后面的语句   ↓return 0; 结束 main

这里说的是 main 代码块内本次实际走到的普通语句。头文件、命名空间和注释不作为运行时普通语句执行；return 0; 一旦执行，会立即结束 main，不会再继续执行它后面的语句。

三条语句不能同时计算

看下面的执行链：

int a = 3;a = a + 2;a = a * 4;

正确过程是：

  1. 第一行建立 a，当前值为 3。
  2. 第二行读取当时的 3，计算 3 + 2 = 5，再把 5 写回 a。
  3. 第三行读取刚刚得到的 5，计算 5 * 4 = 20，再把 20 写回 a。

最终 a = 20。如果第三行仍拿初值 3 计算，就会得到错误的 12；如果先算乘法再回头加 2，也违背了程序的语句顺序。

顺序程序不能像一组数学方程那样同时成立。每个赋值号都是一次发生在具体时刻的写入。

一条语句完成后，状态才交给下一条

可以把每条语句看成一次状态转换：

执行前状态 ──当前语句──→ 执行后状态执行后状态 ──下一语句──→ 新的执行后状态

第二行执行完之前，a 还是 3；第二行完成后，a 才变成 5。第三行必须从这个最新状态开始。

这种“上一行产出、下一行使用”的关系，是顺序结构最重要的因果关系。

02 变量变化追踪

状态表记录每行执行后的快照

读一段顺序程序时，可以画变量状态表。表格的一行表示“当前语句已经完整执行以后”，而不是语句执行到一半的临时猜测。

仍用前面的三条语句：

已完成的语句 右侧怎样计算 执行后 a
int a = 3; 用 3 初始化 a 3
a = a + 2; 读取旧值 3，计算 3 + 2 5
a = a * 4; 读取新值 5，计算 5 * 4 20

状态表直接回答了自测题：三条语句执行完以后，a 是 20。

多个变量怎样记录

每个变量占一列。当前语句只修改其中一个变量时，其他列沿用上一行的值。

假设初始有 x = 2、y = 5，接着执行 x = y;、y = 8;：

已完成的语句 x y 说明
完成初始化 2 5 两个变量都有确定值
x = y; 5 5 把 y 当时的 5 复制给 x
y = 8; 5 8 只修改 y，x 不会自动跟着变化

表中没有被当前语句修改的格子也要保留，避免误以为变量“重新变回初值”或“自动联动”。

画状态表的固定步骤

  1. 按程序出现顺序列出需要追踪的变量。
  2. 从 main 内第一条相关语句开始，不跳行。
  3. 先用上一行状态计算当前语句右侧。
  4. 当前语句写回哪些变量，就更新哪些列。
  5. 其他变量照抄上一行的当前值。
  6. 遇到输出语句，记录此刻真正输出的内容。

如果某个变量还没有初始化或赋值，不要给它随意填 0，应标成“尚无可安全读取的值”，并检查程序是否会在读取它之前完成赋值。

03 输入、计算、输出

顺序程序常见的三段职责

许多一级计算题可以整理成三段：

阶段 要回答的问题 常见语句职责
输入 题目给了哪些数据，顺序是什么？ 把外部数据读入变量
计算 需要哪些公式和中间量？ 读取当前值，计算并保存结果
输出 最终交出哪些量，格式怎样？ 按题目顺序输出结果

“三段式”是职责划分，不要求每段只能写一行。一个问题可能需要先算多个中间量，再统一输出。

从题意写成语句

以“输入长方形的长和宽，输出面积与周长”为例：

  1. **输入量：**长 length、宽 width；
  2. 面积公式：area = length * width；
  3. 周长公式：perimeter = (length + width) * 2；
  4. **输出要求：**先面积，空一格，再周长。

自测题问“哪条语句能计算并保存面积”，应选择：

area = length * width;

area = length + width; 公式错误；area == length * width; 只是在比较；length * width = area; 把不能接收赋值的计算结果放到了左边。

先核对范围和中间结果

假设题目约定 length、width 都是 1 到 30000 的整数：

  • 最大面积：30000 * 30000 = 900000000；
  • 最大周长：(30000 + 30000) * 2 = 120000。

两个最大中间结果都没有超过常见 32 位 int 上限，因此本例使用 int 安全。若题目范围改变，要重新估算，不能因为样例很小就默认类型一定合适。

输出也有执行时刻

输出语句读取的是执行到那一刻变量中的当前值。如果在计算面积之前就输出 area，它可能尚未得到正确值；如果计算后又修改了 area，输出看到的会是修改后的新值。

因此，输入、计算、输出的先后次序决定了数据是否已经准备好，不能只把它们当作页面上的三个区块。

04 临时变量交换

为什么直接互相赋值会丢数据

假设开始时 x = 3、y = 5，希望交换为 x = 5、y = 3。如果直接写：

x = y;y = x;

第一行已经用 5 覆盖了 x 原来的 3；第二行再读取 x 时，只能读到 5。最后两个变量都会是 5，旧的 3 已经丢失。

已完成的语句 x y 问题
初始状态 3 5 目标是交换
x = y; 5 5 旧 x = 3 已被覆盖
y = x; 5 5 已经找不回 3

用临时变量保住即将被覆盖的旧值

正确顺序是：

int temp = x;x = y;y = temp;

逐步追踪：

已完成的语句 temp x y
初始状态 尚未建立 3 5
int temp = x; 3 3 5
x = y; 3 5 5
y = temp; 3 5 3

temp 的职责只是在覆盖 x 之前保存旧值。执行完三条语句后，x、y 已经完成交换。

这个例子说明，顺序不是可以随意调换的外观。int temp = x; 必须发生在 x = y; 之前，否则要保护的数据已经丢失。

05 单位换算

除法取完整单位，取余保留剩余量

把总秒数拆成“小时、分钟、秒”时，每一步都使用上一步留下的状态：

int totalSeconds = 3723;int hour = totalSeconds / 3600;int rest = totalSeconds % 3600;int minute = rest / 60;int second = rest % 60;

按照顺序执行：

已完成的语句 计算 新得到的状态
hour = totalSeconds / 3600 3723 / 3600 hour = 1
rest = totalSeconds % 3600 3723 % 3600 rest = 123
minute = rest / 60 123 / 60 minute = 2
second = rest % 60 123 % 60 second = 3

结果是 1 小时 2 分 3 秒。可以反向检查：1 * 3600 + 2 * 60 + 3 = 3723。

为什么分钟要从 rest 中计算

totalSeconds / 60 得到的是总共包含多少个完整分钟，其中包括那 1 小时里的 60 分钟。若目标是分别输出“小时部分、分钟部分、秒部分”，分钟必须从不足一小时的 rest 中继续拆。

顺序关系是：

总秒数  ├─ 除以 3600 → 完整小时  └─ 对 3600 取余 → 不足一小时的秒数 rest                         ├─ 除以 60 → 完整分钟                         └─ 对 60 取余 → 最后秒数

这条依赖链决定了 rest 必须先算，minute 和 second 才能使用它。

用自测数据快速验证

若总秒数为 125：

  • minute = 125 / 60 得 2；
  • second = 125 % 60 得 5；
  • 反向检查：2 * 60 + 5 = 125。

所以结果是 2 分 5 秒。若总秒数正好为 120，余数为 0，结果是 2 分 0 秒；这里的 0 表示恰好整除，是正确状态。

写顺序程序的统一方法

面对一题输入—计算—输出问题，可以走下面六步：

  1. **列输入：**写清数据数量、顺序、含义和范围。
  2. **列目标：**明确最后输出哪些值，顺序和格式是什么。
  3. **写公式：**把题意拆成一个个能执行的计算步骤。
  4. **排顺序：**确保每个变量在第一次读取前已经有确定值；保护会被覆盖的旧值。
  5. **查范围：**估算输入、乘积、总和等中间结果，选择合适类型。
  6. **做验证：**记录一组输入，先手算期望结果，再画状态表，最后与实际输出逐字比较。

这六步能同时检查“公式是否正确”和“语句是否放在正确时刻”。只盯着最后一行答案，很难发现问题到底从哪一步开始。

任务 关键动作 最直接的验证方式
追踪语句 从上到下，一行完成后再进入下一行 每行执行后更新状态表
计算问题 输入 → 计算 → 输出 手算与实际输出比较

典型例题

继续完成长方形任务：输入长和宽，输出面积和周长。输入范围均为 1 到 30000。

完成程序

#include <bits/stdc++.h>using namespace std;
int main() {    int length;    int width;    cin >> length >> width; // 按“长、宽”的顺序读取两个数据
    int area = length * width; // 面积等于长乘宽    int perimeter = (length + width) * 2; // 周长先算长加宽，再乘 2
    cout << area << " " << perimeter << endl; // 按“面积 空格 周长”输出    return 0;}

用输入 3 5 验证。

第一步：先手算期望输出

  • 面积：3 * 5 = 15；
  • 周长：(3 + 5) * 2 = 16；
  • 题目要求输出“面积 空格 周长”，所以期望输出为 15 16。

第二步：画状态表

已完成的语句 length width area perimeter 当前输出
cin >> length >> width; 3 5 尚未建立 尚未建立 无
int area = length * width; 3 5 15 尚未建立 无
int perimeter = (length + width) * 2; 3 5 15 16 无
cout << area << " " << perimeter << endl; 3 5 15 16 15 16 并换行

第三步：运行并逐字比较

实际输入：

3 5

实际输出应为：

15 16

手算结果、状态表和实际输出三者一致，普通样例通过。还要补充边界数据：

输入 期望输出 检查目的
1 1 1 4 最小范围、长宽相等
1 8 8 18 长宽不相等，检查周长括号
30000 30000 900000000 120000 最大范围与中间结果

这些数据都沿同一条顺序路线执行。变化的是输入和变量值，语句顺序没有改变。

顺序程序的验证清单

发现输出不对时，不要同时改很多行。按证据逐项检查：

检查项 要问的问题 可用证据
输入 数量、顺序和当前值是否正确？ 原始输入、输入后的状态表
公式 每个表达式是否符合题意？ 手算过程、单位和括号
顺序 使用变量前是否已经准备好？ 逐行状态表
覆盖 旧值是否在保存前就被赋值覆盖？ 交换过程中的前后状态
范围 输入和中间结果是否能放进类型？ 最大值估算
输出 内容、顺序、空格和换行是否准确？ 期望文本与实际文本逐字比较

修正后用同一组失败数据重新运行，确认错误现象真的消失；再补一组边界数据，避免只修好了一个样例。

引导练习（不记录进度）

令 a = 4、b = 7，使用临时变量交换。先填写三个状态：保存旧 a 后 temp = 4；执行 a = b 后 a = 7；执行 b = temp 后 b = 4。

成功标准： 状态表最后必须是 a = 7、b = 4，且任何一步都能找到尚未丢失的旧值。完成后不看提示独立完成页末“整页综合测试”；提交后逐行重画错题的变量快照。

常见错误

把多条赋值当成同时成立的方程

错误： 用初值 3 同时计算 a = a + 2; 和 a = a * 4;。

检查： 每执行一行就更新状态。第三行必须读取第二行留下的 5。

输入变量还没准备好就开始计算

错误： 把面积计算放在 cin 之前，或读取未初始化变量。

检查： 顺着程序找每个变量的第一次读取，确认此前已有输入、初始化或赋值。

面积公式或赋值方向写错

错误： 写成 area = length + width;、area == length * width; 或 length * width = area;。

检查： 先手算公式，再确认左侧是接收结果的变量，使用的是赋值号 =。

交换时先覆盖旧值

错误： 直接执行 x = y; y = x;。

检查： 画三列表，确认第一步已用 temp 保存旧 x。

单位拆分重复计算大单位

错误： 已算出小时后，仍直接用总秒数除以 60 得分钟部分。

检查： 先对 3600 取余得到 rest，再从 rest 中拆分钟和秒。

公式正确，输出顺序或格式错误

错误： 题目要求“面积 周长”，却输出“周长 面积”，或擅自加提示文字。

检查： 把期望输出写成完整文本，与实际输出逐字符比较。

只测普通样例，不估算最大中间结果

错误： 样例能算对就认为类型安全。

检查： 代入输入上限，分别计算乘积、总和等可能出现的最大值。
