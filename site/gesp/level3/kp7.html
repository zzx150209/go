枚举算法

07
GESP 3级知识字典 · 知识点 07

确定枚举范围与判断条件，逐个检查并统计或更新最优解。

检索词：枚举范围条件判断

本课先记住

核心结论

枚举法适合候选数量有限、每个候选都能逐个判断的问题。先确定要枚举的对象、完整范围和尝试顺序，再由题目条件判断当前候选是否合法。最后按题意统计、输出或维护答案，做到不重复、不遗漏，并保证循环一定结束。

常用语法

常用写法是用 for 循环依次生成候选，在 if 中判断合法性；只找第一个答案时，可以在命中后用 break 停止。若一个量能由另一个量直接推出，例如 rabbit = heads - chicken，就不必再为它增加一重循环。

最小示例

寻找 0 到 5 中的偶数时，让 x 从 0 逐个增加到 5，每轮检查 x % 2 == 0；通过判断的候选依次是 0、2、4。

关键易错点

  • 把 < 和 <= 写混，漏掉上界或下界。
  • 能直接推导第二个量时仍写双重循环，造成重复候选。
  • 候选还没通过全部条件就计数，或没有依据就提前 break。
  • 只写循环而不先估算候选总数，可能让枚举次数过大。

知识范围与使用边界

枚举法把有限范围内的候选按确定顺序逐个生成，再用同一组条件判断是否合法，并按题意处理答案。本课只处理范围能够证明、候选数量可以接受的问题；若没有可靠上界，不能写无限尝试的循环。

基本路线是：确定范围 → 逐个尝试 → 判断条件 → 处理答案。写循环前必须说清五件事：枚举对象是什么、范围两端在哪里、尝试顺序怎样、合法条件是什么、命中后如何处理。

本课使用三级已经学过的变量、分支、循环、字符串与一维数组，不引入函数封装、指针、递归、二维数组、排序、搜索、动态规划或新的容器。

01 枚举思想与适用条件

枚举不是“随便试几个数”，而是让每一轮循环都对应一个明确候选。只要候选范围有限、判断规则明确，并且逐个检查的次数能够接受，就可以考虑枚举。

第一个课程核心是：先确定对象、有限范围与尝试顺序。对象决定“每轮在试什么”，范围保证“不漏端点且一定结束”，顺序则决定候选怎样依次出现。

循环层数取决于“有几个量必须独立尝试”。如果第二个量能由第一个量直接推出，它就不是独立选择，不应机械增加一重循环。

候选次数要用乘法估算。例如 x 有 5 种取值、y 有 4 种取值，双重枚举最多检查 5 × 4 = 20 个候选；若 z 还有 3 种取值，三重枚举最多检查 5 × 4 × 3 = 60 个候选。不能只看每一层都不大，却忽略相乘后的总量。

枚举对象与范围

枚举对象常见有两种：数值和下标。枚举数值时，循环变量本身就是候选；枚举下标时，循环变量表示位置，要通过 a[i] 或 s[i] 取得该位置的内容。

边界要从题意推导。允许 0 时必须从 0 开始；上界也可能成为合法候选时应使用 <=。枚举下标则通常使用 < n，因为长度为 n 时最后一个合法下标是 n - 1。

尝试顺序也要与题意一致。寻找最小合法值时，通常从小到大枚举；只要范围完整，顺序不会改变“有哪些合法候选”，却会影响“第一个找到的是谁”。

03 候选、范围、判断与处理

第二个课程核心是：由条件推导候选，再判断它是否合法。先把题目中的量分成“需要尝试的量”和“可以计算出来的量”，能直接计算的就不再枚举。

以鸡兔同笼为例，已知总头数 heads 和总腿数 legs。自然想法是同时尝试鸡数和兔数，再检查头数、腿数两个条件；但只要鸡数确定，兔数就由总头数唯一推出：

rabbit = heads - chicken

因此只需让 chicken 从 0 到 heads，每轮计算 rabbit，再检查 chicken * 2 + rabbit * 4 == legs。这种形成过程把双变量尝试收束成单重枚举：没有漏掉任何可能的鸡数，也不会为同一个鸡数重复生成兔数。

同样地，寻找满足 x + y = target 的非负整数对时，可以枚举 x，再计算 y = target - x。如果交换顺序算不同方案，就让 x 从 0 到 target；如果交换顺序算同一种方案，可以再证明并限制 x <= y，但不能凭感觉把范围砍半。

写任何枚举前，都用下面五问完成规则：

  1. 对象： 每轮候选是什么，例如一个数、一个下标或一对位置。
  2. 范围： 每个需要尝试的量从哪里到哪里，端点是否包含。
  3. 顺序： 候选按什么次序出现，顺序是否影响首解或去重。
  4. 判断： 当前候选必须通过哪些题目条件。
  5. 处理： 合法时是计数、输出、记录首解，还是更新最优答案。

这里“推导”只负责生成当前候选的一部分，“判断”才决定整个候选是否合法。即使 rabbit = heads - chicken 能保证头数正确，仍要检查腿数；不能把“算得出来”误当成“已经合法”。

04 合法性判断

生成候选之后，要把题目条件逐条翻译成判断。只有通过全部条件的候选，才能计数、输出或用于更新答案；少检查一个条件，就可能把不合法候选当成答案。

例如“寻找第一个能同时被 2 和 3 整除的整数”，当前候选 x 必须同时满足 x % 2 == 0 和 x % 3 == 0。若只检查其中一个条件，答案就不再符合原题。

判断与处理要分开理解：

  1. 先计算由候选得到的中间量。
  2. 再检查所有合法条件。
  3. 只有判断为真时才处理答案。
  4. 判断为假时跳过本轮，继续尝试下一个候选。

条件剪枝是“提前排除已经能证明不合法的候选”。例如要求 x + y = 8 且 x、y 都是非负整数时，若已经算出 y < 0，就能直接跳过；但不能因为“看起来不像答案”而停止整个循环。

计数、最优答案与首解停止

只找首解时，break 必须放在候选已经通过全部条件之后。若题目要求全部方案、方案总数或最优答案，就不能在第一次命中后无依据 break。

最优值不能随意初始化为 0，因为合法候选可能全部为负数。稳妥做法是用首个合法候选初始化，或者先用 found 记录“是否已经有答案”，以后再比较更新。

官方真题中可能出现压缩写法 out[cnt++] = x;，它表示先用当前 cnt 写入，再让 cnt 增加。三级主教学优先拆成“先写入、再 cnt++”两步。写法 count += height[i] > 135 ? 1 : 0; 表示条件成立加 1，否则加 0；本课只要求能识别，日常编程仍优先使用完整 if。

05 枚举次数与复杂度

枚举能否使用，不只看代码有几行，还要估算候选总数。单重循环的次数看区间长度；多重循环的次数通常是各层次数相乘。

若 n = 5，完整枚举五个下标只检查 5 次；枚举所有有序下标对最多检查 5 × 5 = 25 次。若 n = 100000，两层完整循环接近一百亿次，就不再是“小范围逐个检查”。

估算时按下面顺序：

  1. 计算每一层候选个数，注意两端是否包含。
  2. 将独立循环层的次数相乘。
  3. 再考虑直接推导、范围缩小或条件剪枝能否减少实际检查。
  4. 确认即使走到最大边界，循环也会在有限步后结束。

例如 heads 满足 0 <= heads <= 100 时，chicken 从 0 到 heads 最多只有 101 个候选。由 chicken 直接推出 rabbit 后，不需要再乘一次 101；这正是先辨认独立变量的价值。

枚举范围与去重

缩小范围之前必须给出证明。可靠方法包括：

  • 范围证明： 根据非负、上下界或数量关系排除不可能的值。
  • 直接推导： 用已经枚举的量唯一算出另一个量，例如 y = target - x。
  • 条件剪枝： 当前候选已经违反必要条件时，跳过剩余判断。
  • 统一表示： 当交换顺序仍是同一方案时，只保留一种顺序。

从数组中选两个不同位置且不区分顺序时，使用 j = i + 1，让每一对位置只出现一次。这里的去重依据是 j 永远大于 i，不是凭经验删掉一半候选。

目标和 target = 8、x 和 y 都为非负整数，且 (x, y) 与 (y, x) 算同一种方案时，可以统一要求 x <= y：

x y = 8 - x 是否保留 原因
0 8 是 x <= y
1 7 是 x <= y
2 6 是 x <= y
3 5 是 x <= y
4 4 是 x <= y
5 3 否 与 (3, 5) 重复
6 2 否 与 (2, 6) 重复
7 1 否 与 (1, 7) 重复
8 0 否 与 (0, 8) 重复

因此只枚举 x 从 0 到 target / 2，就能保留五种无序方案。若题目区分顺序，后四个候选也有独立意义，此时不能使用这一范围。

枚举范围与去重追踪

追踪枚举时，不要只抄变量值，要记录“本轮候选怎样得到、判断是否通过、答案是否变化、下一步去哪里”。这样才能检查范围是否漏端点、候选是否重复，以及 break 是否有依据。

鸡兔同笼主样例会完整追踪 chicken = 0 到 5。阅读追踪时重点核对：

  1. 初始化时还没有合法方案。
  2. 每轮先由 heads - chicken 推出 rabbit。
  3. 再计算实际腿数并判断。
  4. 命中后输出和计数，但因为题目要检查完整范围，所以继续循环。
  5. chicken 增加到 6 时，循环条件失败，程序停止。
  6. 若整个范围都没有命中，才输出“没有满足条件的候选”所对应的 No。

这份追踪只解释输入 5 14 的真实执行，不把一个样例误写成对所有输入的证明。范围完整性、去重与必然停止仍要由前面的规则单独说明。

典型例题

鸡兔同笼：从两个未知量收束为一次枚举

D1 数据边界与程序接口

程序读入两个整数 heads 和 legs，分别表示总头数与总腿数，约束为：

  • 0 <= heads <= 100
  • 0 <= legs <= 400

鸡数只能从 0 到 heads，因此最多检查 101 个候选。鸡数、兔数、腿数与 solutionCount 的最大值都远小于 int 的表示范围，使用 int 安全。

固定头数和腿数后，若有解，鸡数和兔数只能组成一组答案；程序最大输出是一组数对，否则输出 No。输出的数对顺序是“鸡数 兔数”。

把 rabbit = heads - chicken 代入腿数式，可得 actualLegs = 4*heads - 2*chicken。chicken 每增加 1，actualLegs 就减少 2，因此同一个 legs 在完整枚举中至多命中一次，这也说明程序不会输出两组不同答案。

S1 主样例

输入：5 14

输出：3 2

这表示共有 5 个头、14 条腿时，有 3 只鸡和 2 只兔。

算法形成链

最自然的想法是同时尝试 chicken 和 rabbit，再检查头数与腿数。但这会把两个量都当成独立选择，产生许多头数本来就不对的候选。

观察头数等式：

chicken + rabbit = heads

只要 chicken 已经确定，就能唯一推出：

rabbit = heads - chicken

于是只枚举 chicken，从 0 到 heads，也就是枚举鸡的数量；每轮先算 rabbit，再计算实际腿数 actualLegs，最后判断 actualLegs 是否等于 legs，也就是总腿数符合题意。一般枚举题可能得到无解、唯一解和多种方案；本题固定一组 heads 和 legs 时，由于 actualLegs = 4 * heads - 2 * chicken，chicken 每增加 1，实际腿数就减少 2，所以至多命中一次。这样每个可能的鸡数恰好出现一次，对应的兔数也唯一，因此不会漏、不会重；chicken 超过 heads 后循环条件失败，程序一定停止。

八步执行方法

  1. 读入 heads 和 legs。
  2. 将 solutionCount 初始化为 0，表示还没有合法方案。
  3. 让 chicken 从 0 开始，逐个尝试到 heads。
  4. 用 rabbit = heads - chicken 推出当前兔数。
  5. 计算 actualLegs = chicken * 2 + rabbit * 4。
  6. 若 actualLegs == legs，输出当前 chicken 和 rabbit，并让 solutionCount 增加 1。
  7. 命中后仍继续检查剩余鸡数，验证完整范围。
  8. 循环结束后，若 solutionCount 仍为 0，输出 No。

完成程序

程序只有 chicken 是独立枚举量。rabbit 和 actualLegs 都由当前候选计算得到；只有腿数完全相等时才输出和计数。若所有候选都失败，solutionCount 保持 0，最后输出 No。

常见错误

  1. 范围漏掉端点。 现象：上界恰好是答案时程序找不到。→ 原因：没有先判断端点是否属于合法范围，把 <= 误写成 <，或忘记从 0 开始。→ 修正：从题意写出闭区间或下标区间，再翻译成循环条件。→ 复验：分别用下界合法、上界合法和空范围附近的数据检查。

  2. 能推导第二个量时仍用双重枚举。 现象：同一个鸡数配出很多不满足头数的兔数，候选数量明显增多。→ 原因：没有利用 rabbit = heads - chicken。→ 修正：只枚举 chicken，由头数等式唯一推出 rabbit，再检查腿数。→ 复验：确认每个 chicken 只生成一个 rabbit，候选最多为 heads + 1 个。

  3. 计数位置错误。 现象：solutionCount 等于循环次数，或不合法候选也被算入。→ 原因：在合法性判断之前执行了 solutionCount++。→ 修正：只有候选通过全部条件时才输出并计数。→ 复验：使用一个无解输入，结果必须保持 0 并输出 No。

  4. 没有依据就 break。 现象：找到第一个候选后立即停止，漏掉后面的合法方案或更优答案。→ 原因：没有区分首解、全部方案、计数和最优值任务。→ 修正：只有题目明确要首个答案时，才在完整判断和记录之后 break。→ 复验：准备一个有多个合法候选的输入，确认全部方案题仍会检查到范围末端。

  5. 同一方案正反各记一次。 现象：不区分顺序的 (2, 6) 和 (6, 2) 同时出现。→ 原因：候选没有统一表示，仍完整枚举两个顺序。→ 修正：证明交换顺序等价后，限制 x <= y，或让位置对使用 j = i + 1。→ 复验：逐项检查输出，任意两项都不能只交换顺序就完全相同。

  6. 最优值错误地初始化为 0。 现象：所有合法候选都为负数时，程序却输出不存在的 0。→ 原因：初值不是来自合法候选，也没有记录是否已经找到答案。→ 修正：用首个合法候选初始化，或用 found 区分“还没有答案”和“已有最优值”。→ 复验：使用全负候选和完全无解两类数据，二者必须得到不同且正确的处理。

  7. 忽略多层循环次数相乘。 现象：每一层范围看似不大，程序整体却运行很久。→ 原因：只看单层次数，没有计算 A × B 或 A × B × C。→ 修正：编码前先算候选总数，再寻找直接推导、可靠缩界或条件剪枝。→ 复验：代入最大输入估算最坏候选数，确认在题目限制内可以完成。

去重范围必须来自题意

× 错误写法只因为两个数能交换，就随手把循环范围减半
✓ 正确写法先确认交换顺序是否仍是同一方案，再用 x <= y 或 j = i + 1 保留唯一表示

原因：题目可能区分顺序；即使不区分，也要说明保留哪一种统一表示。

检查方法：用 target = 8 列出全部候选，检查缩小范围后是否既无重复又无遗漏。
