递归把一个问题交给规模更小的同类问题处理；每条调用路径都要有直接回答的出口，并且严格走向出口。

知识范围与官方定位

对应五级大纲“递归”：理解递归函数含义、出口、严格推进、栈帧调用与返回，能识别阶乘、斐波那契、汉诺塔的递归形状，并用递归枚举和递归树分析时间、空间。

本页只使用一级至五级已经学习的语法和能力；小知识点按页内编号连续查询，不设置前置完成门槛。

是什么
递归函数不是“无限调用自己”，而是在当前合同下把更小的同类部分交给下一帧，出口直接完成最小状态。
解决什么问题
它能把“逐层决定、完成后回到原处继续”的问题写得清楚，例如阶乘的返回、汉诺塔的分步和本课的二进制串枚举。
什么时候使用
只有能写出精确函数含义、可到达出口和严格变小的下一状态时才使用；三者任缺一个都不能开始写递归。
核心思想
每个栈帧独立保存自己的参数和继续位置；共享 answer 数组保存当前路径，但只有 answer[0..pos-1] 是本帧承诺有效的前缀。
C++ 实现方法
先公开 0≤n≤20，再写 search(pos) 的前缀合同、pos==n 的出口和 pos+1 的推进；每个非叶帧固定先 0、返回本帧后再 1。

01 递归的三个必要部分

一段递归先要写清函数合同：它当前解决什么同类问题。例如 search(pos) 的合同是：在 answer[0..pos-1] 已固定后，补全所有合法的后缀。合同清楚，调用者才知道这一层完成后会得到什么。

第二部分是出口：遇到可以直接回答的最小状态就停止调用。第三部分是严格推进：每次递归后，离出口必须更近。若 factorial(n) 的出口是 n==1，却错误调用 factorial(n+1)，参数看似在变化却永远到不了出口。

具体样例与推演

场景：先不写代码：为 search(pos) 补全函数合同、出口和严格推进；再用错误的 factorial(n+1) 检查“变化”不等于“靠近出口”。

  1. 合同：answer[0..pos-1] 已固定，search(pos) 要枚举每一种合法后缀；因此 pos 不是任意数字，而是下一位的位置。
  2. 出口：pos==n 时 n 位都已经确定，直接输出一行并 return；n=0 也在 search(0) 直接输出一行空行。
  3. 推进：非出口只能调用 search(pos+1)，因为已确定的位置从 pos 个增加到 pos+1 个，必会到 n。

适用结论：自检题：把“函数完成什么、最小状态是什么、下一层为何更近”各说一句；三句缺一句就不要写递归。

错误反例：factorial(n+1)，因为 n 确实变化了。

为什么错：出口是 n==1，而正整数 n 每次加 1 后离 1 更远；调用会持续增加直到栈耗尽。

怎样改：改为 factorial(n-1)，并逐条检查每次递归的度量都严格朝出口减小；枚举中这个度量是 n-pos。

02 调用与返回过程

每次调用都有自己的栈帧：参数、局部状态和“子调用结束后从哪一句继续”。它们不是同一个会互相覆盖的 n。计算 factorial(4) 时，4、3、2 的栈帧分别暂停在 4×?、3×?、2×?；factorial(1) 直接给出 1。

返回时沿相反方向恢复：factorial(2) 得到 2×1=2，factorial(3) 得到 3×2=6，factorial(4) 得到 4×6=24。子调用只回到紧挨着它的父调用的下一句，不会直接跳回 main()，也不会跳到另一条分支。

具体样例与推演

场景：完整追踪 factorial(4)：用每帧的参数、等待表达式和返回位置解释调用 4→3→2→1 与返回 1→2→6→24。

  1. factorial(4) 的帧保存 n=4，暂停在 4×factorial(3)；它调用的不是“修改同一个 n”，而是新建 n=3 的帧。
  2. factorial(3) 暂停在 3×factorial(2)，factorial(2) 暂停在 2×factorial(1)，factorial(1) 命中出口直接返回 1。
  3. 回到 factorial(2) 的调用后一行，得到 2；再回到 factorial(3) 得到 6；最后回到 factorial(4) 得到 24。每次都只回到直接父帧。

适用结论：手算题：写出 factorial(3) 的三帧和返回值；答案是帧 3、2、1，返回 1、2、6。子调用返回是函数关系，不是人物倒着移动。

错误反例：进入 n=1 后，所有等待的 n 都变成 1。

为什么错：每个调用有独立参数副本；若父帧的 n 丢失，返回时就不可能计算 2×1、3×2、4×6。

怎样改：画栈帧表：当前函数、参数、等待的表达式、子调用返回后的位置；不要把不同帧合成一个变量。

03 经典递归模型

识别递归时先看“同类但更小”。阶乘是一条单分支链：n 变成 n-1。朴素斐波那契会同时调用 n-1 和 n-2，因此有两条分支，并可能重复计算同一个小问题；这里先识别形状，不学习记忆化或动态规划。

汉诺塔的形状是：先移动 n-1 个小盘，再移动最大盘，再移动 n-1 个小盘；两次递归处理的都是更小规模。它们共同需要出口和严格推进，但分支数不同，不能把复杂度一概而论。

具体样例与推演

场景：识别三个模型，不新增完整程序：阶乘、朴素斐波那契和汉诺塔分别有几条更小子调用。

  1. 阶乘：一个 n-1 子问题，是单分支链；出口后把子答案乘回 n。
  2. 朴素 Fibonacci：需要 n-1 与 n-2 两个更小答案，树会分叉，且不同分支可能重复到达相同小问题；这里只识别重复，不引入记忆化。
  3. 汉诺塔：两次调用都只移动 n-1 个盘，中间单独移动最大盘；这是“调用—中间动作—调用”的形状。

适用结论：识别题：看到“先处理 n-1、做一次当前动作、再处理 n-1”应想到汉诺塔形状；看到“两个更小答案相加”应想到 Fibonacci 形状。

错误反例：汉诺塔先递归移动 n 个盘到辅助柱。

为什么错：规模仍是 n，原问题没有缩小，永远到不了只剩一个盘的出口。

怎样改：两次递归都写成 n-1；把最大盘的单独移动放在两次调用之间。

04 递归枚举

本课主任务：输入 n（0≤n≤20），按字典序输出所有长度为 n 的二进制串，每行一个。n=0 时空串也是一种完整方案，因此恰好输出一行空行；n=20 时有 1048576 行，输出量本身已经很大。

把 answer[0..pos-1] 看作当前已经选好的前缀。search(pos) 只决定第 pos 位及其后缀：pos==n 说明 0 到 n-1 全部确定，才输出；否则先写 0 并进入下一层，子调用返回本层后再写 1 并进入下一层。更深位置可能留下旧字符，但当前层只承诺前缀 answer[0..pos-1] 有效，旧后缀会被后续选择覆盖。

每个叶子从根开始都作出 n 次固定位置的 0/1 选择，所以每个长度 n 串恰好对应一条根到叶路径；路径不同，至少有一位选择不同，因此不会重复输出。

具体样例与推演

场景：以 S1：n=3 为主样例，先形成规则，再按 E1 完整执行。自然语言步骤：读入 n；调用 search(0)；若 pos==n 输出；否则写 0、调用并返回；写 1、调用并返回；根帧返回 main 后结束。

  1. 进入 search(pos) 前，只有 answer[0..pos-1] 有效。pos=2、前缀 01 时，本帧只决定 answer[2]，先产生 010，再从同一帧继续产生 011。
  2. E1 的 ENTER 顺序为 ε、0、00、000、001、01、010、011、1、10、100、101、11、110、111；八个 OUTPUT 正好是 000 到 111。
  3. RETURN 顺序为 000、001、00、010、011、01、0、100、101、10、110、111、11、1、ε→main。物理数组中更深位置可保留旧值，但它不属于当前有效前缀。

适用结论：引导题：n=2 时写出所有输出和返回链；答案是 00、01、10、11，叶子先返回 00、01、再 0、再 10、11、再 1、最后 ε。独立题：把每位候选改成 A、B，长度 2 时按 A 在前列出 AA、AB、BA、BB。

错误反例：每写完一位就输出 answer。

为什么错：后缀尚未确定，或仍是上一条路径留下的物理字符；会输出半成品、旧值或重复方案。

怎样改：只在 pos==n 输出下标 0 到 n-1；子调用返回后先恢复父帧，再执行它的第二个选择。

05 递归树与复杂度

递归树的结点是一帧 search(pos)，边是一条调用。每个非叶结点先走 0 再走 1，所以叶子正好是 2^n 个完整串，0 分支在前保证 000、001、…、111 的字典序。整棵树的调用结点数是 O(2^n)，但每个叶子还要写 n 个字符。

因此本题时间应写成输出敏感的 O(n·2^n)，不能只写 O(2^n)。answer[25] 在 n≤20 时最多写到下标 19；同时活动的栈帧是 search(0) 到 search(n)，最多 n+1=21 层。答案数组 O(n)，递归栈也 O(n)。

具体样例与推演

场景：从 n=3 的八片叶子推广到 n=20，分别统计递归树结点、输出字符和同时活动的栈帧。

  1. 每一层都有 0、1 两个选择，深度 n 的叶子数为 2^n；每片叶子与一个长度 n 串一一对应。
  2. 树的调用结点数是 O(2^n)，但叶子输出每次要写 n 个字符，所以总时间是 O(n·2^n)。n=5 有 32 行；n=20 有 1048576 行，连换行共 22020096 个字符。
  3. 同时活动的只是一条根到叶路径：search(0) 到 search(n)，最多 n+1 帧。n≤20 时 answer[25] 只写到 answer[19]，答案数组和调用栈均为 O(n)。

适用结论：自检题：为什么时间不是 O(n)？答案：n 是一条路径深度，而完整程序要访问指数数量的分支并写出指数数量的行。下一步可到“复杂度分析”把递归树与其他数量级放在一起比较。

错误反例：有 n 层递归，所以所有运行时间都是 O(n)。

为什么错：这只数到一条路径；每个非叶结点还会分出两个子调用，完整树有 2^n 个叶子。

怎样改：把“调用结点数 O(2^n)”和“输出每叶 n 字符，所以 O(n·2^n)”分开写；空间只数同时存在的一条路径。

典型例题

基础例题：递归输出二进制串

题意：输入整数 n（0≤n≤20），按 0 在前、1 在后的字典序输出全部长度为 n 的 0/1 串，每行一个。

示例输入：

3

示例输出：

000
001
010
011
100
101
110
111

说明：先把 n 读入，再从 search(0) 开始。每一帧只承诺 answer[0..pos-1] 已固定：pos==n 时输出完整串并立刻 return；否则当前位置先写 0、调用并返回，再写 1、调用并返回。answer[25] 对 n≤20 安全，最大写入下标为 19；n=20 有 1048576 行、22020096 个含换行的输出字符，最多同时有 21 个 search 栈帧。

#include <bits/stdc++.h>
using namespace std;

int n;
char answer[25];

void search(int pos) {
    if (pos == n) {
        for (int i = 0; i < n; i++) {
            cout << answer[i];
        }
        cout << '\n';
        return;
    }

    answer[pos] = '0';
    search(pos + 1);
    answer[pos] = '1';
    search(pos + 1);
}

int main() {
    cin >> n;
    search(0);
    return 0;
}

典型应用：用阶乘看清“暂停—返回—继续”

题意：按 factorial(n) 的合同计算 factorial(4)，出口为 factorial(1)=1，其他情况返回 n×factorial(n-1)。

示例输入：

4

示例输出：

24

解题说明：调用依次进入 4、3、2、1；1 直接返回 1，随后各自恢复等待的表达式：2×1=2、3×2=6、4×6=24。这里没有第二个完整程序，只用函数合同辨认调用与返回。

常见错误

  • 漏写出口：症状：调用层数不断增长直至栈耗尽；原因：没有直接答案。修正：在 pos==n 输出后立刻 return；重新测试 n=0。
  • 出口后没有 return：症状：出口还会继续写 answer[n]；原因：完成方案后落入了下面的递归语句。修正：输出换行后立即 return；重新测试 n=1。
  • pos 没有严格推进：症状：search(pos) 反复调用自己；原因：规模没有靠近 pos==n。修正：两次调用都写 search(pos+1)；重新测试 n=2。
  • 过早输出：症状：输出短串或混入旧后缀；原因：尚未固定所有位置。修正：只在 pos==n 输出 0 到 n-1；重新测试 n=3。
  • 第二个分支仍写 0：症状：一半方案重复、含 1 的方案缺失；原因：返回本层后没有改写 answer[pos]。修正：第二次调用前写 1；重新测试 n=2。
  • 分支顺序颠倒：症状：111 出现在 000 前；原因：先递归 1。修正：固定先 0 后 1；重新测试 n=3。
  • 写 answer[n]：症状：越过最后合法位置或得到半成品；原因：把 pos==n 当作还能选择的位置。修正：出口只输出并返回；重新测试 n=0。
  • 混淆不同栈帧：症状：认为子调用返回后 pos 已经变了；原因：把每帧的参数当成同一个变量。修正：按“父帧暂停—子帧完成—父帧继续”追踪；重新测试 n=3。

漏写出口或出口后继续执行

错误代码：

if (pos == n) { print(); }
answer[pos] = '0';

错误原因：症状是 n=0 仍写 answer[0]，或调用越来越深。出口必须直接完成并离开当前帧。

正确写法：

if (pos == n) {
    print();
    return;
}

没有严格推进

错误代码：

search(pos);

错误原因：症状是同一个 pos 无限重入；下一帧没有比当前帧更接近 pos==n。

正确写法：

search(pos + 1);

过早输出或写错第二分支

错误代码：

cout << answer << '\n';
answer[pos] = '0';

错误原因：症状是短串、旧后缀或重复输出；完整串只能在出口输出，第二次选择必须改成 1。

正确写法：

if (pos == n) { print(); return; }
answer[pos] = '0'; search(pos + 1);
answer[pos] = '1'; search(pos + 1);
