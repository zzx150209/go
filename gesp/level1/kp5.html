程序基本概念

05
GESP 1级知识字典 · 知识点 05

掌握标识符、关键字、常量、变量、赋值与表达式。

检索词：变量常量标识符表达式

本课先记住

  • 核心结论： 变量由类型、名称和当前值组成；表达式先按括号与优先级得到结果，赋值再把结果保存到左侧变量。
  • 常用语法： 定义并初始化可写 int count = 0;，固定值可写 const int DAYS = 7;，后续赋值写 count = count + 1;。
  • 最小示例： int a = 2; int b = a + 3; 先取得 a 的当前值 2，算出 5，再把 5 保存到 b。
  • 关键易错点： 普通局部变量必须先初始化再读取；= 表示赋值而不是相等判断，连续赋值要从右向左解释。

知识范围与官方定位

本页对应 GESP C++ 一级大纲中的“程序基本概念”。前面已经学过完整程序骨架和输入输出；现在要弄清程序里的数据叫什么、放在哪里、怎样变化。

本页集中解决三个问题：

  1. 一个变量怎样由名字、类型和当前值组成？
  2. 声明、初始化和赋值分别发生了什么？
  3. 表达式怎样读取变量的当前值，算出结果，再把结果保存起来？

数据类型的范围、精度和转换由基本数据类型系统讲解；运算符种类、优先级和结合方向由基本运算负责。本页只把变量从“建立”到“改变”的过程讲清楚。

先看一句简单代码：

int score = 60;

它包含四个关键信息：

部分 身份 作用
int C++ 关键字，也是这里的数据类型 说明 score 按整数保存和解释
score 程序员起的标识符 给这个变量一个可引用的名字
60 整数字面量常量 提供最初要保存的值
= 初始化写法的一部分 在变量建立时把右侧结果作为初值

执行这条定义以后，可以把变量状态记成：名字是 score，类型是 int，当前值是 60。

01 标识符

标识符是程序中的名字

程序需要用名字指向变量等对象，这类名字叫标识符。score、studentCount、total_price 都是标识符。

一级题目通常按下面的规则判断：

  1. 只使用英文字母、数字和下划线 _；
  2. 第一个字符不能是数字；
  3. 不能使用 C++ 关键字；
  4. 区分大小写，score、Score 和 SCORE 是三个不同名字。

逐个判断几个例子：

名称 是否可作一级普通标识符 原因
number_of_students 可以 只含字母和下划线，开头不是数字
score2 可以 数字不在开头
360AntiVirus 不可以 以数字开头
Man&Woman 不可以 含有 &
student score 不可以 含有空格
break 不可以 break 是 C++ 关键字

C++ 还涉及其他字符规则以及以下划线开头的保留名称。一级编程建议直接使用字母开头的清楚名称，不需要用下划线开头去试探边界。

三步判断一个名称是否合法

看到一个候选名称时，可以按固定顺序检查：

  1. **查开头：**第一个字符是字母或下划线吗？如果是数字，立即不合法。
  2. **查其余字符：**是否只由字母、数字、下划线组成？空格、&、- 等不能直接放进普通标识符。
  3. **查关键字：**整个名称是否正好是 C++ 关键字？

例如 score2 三步都通过；2score 在第一步就失败；student-score 在第二步失败；while 在第三步失败。

合法还不够，名字还要能表达用途

a、x1 可能合法，但在较长程序中不一定容易理解。一级程序也应尽量让名字说明保存的内容：

含义 较清楚的名称 容易造成的问题
学生人数 studentCount 写成 x 后，稍后很难确认它保存什么
总价 totalPrice 写成 price 容易与单价混淆
是否准备好 ready 写成 number 看不出真假含义

命名不改变计算结果，却会直接影响检查变量和调试的速度。

02 关键字

关键字已经由 C++ 规定用途

关键字是 C++ 语言保留的单词，编译器会按规定含义理解它们。一级常见关键字包括：

用途 常见关键字
数据类型与逻辑值 int、double、char、bool、true、false
条件与循环 if、else、switch、case、for、while、do
流程和返回 break、continue、return
声明相关 const、using、namespace

关键字不能再次当作变量名。例如：

int int = 3;

第一个 int 表示整数类型，第二个位置本应填写变量名；但第二个 int 仍会被编译器当作关键字，所以这行不能通过编译。可以改为：

int number = 3;

常见名称不一定是关键字

经常出现，不代表它属于 C++ 关键字：

名称 实际身份
main 具有特殊规则的程序入口名称，不是关键字
cin、cout 标准库中的输入输出对象名称
endl 标准库提供的输出操纵符名称
score 程序员自己选择的标识符

因此，在 double、else、while、endl 中，前三个是关键字，endl 不是。

C++ 区分大小写。把 int 改成 Int 并不会创造“同一个整数关键字”；Int 只是另一个名称，而且编译器不会自动把它理解成 int。

03 常量

字面量把固定值直接写进代码

直接写在代码中的固定值叫字面量常量，常见形式有：

写法 本页先这样认识 书写边界
10、-3 整数值 没有小数点
3.14 浮点值 带小数点
'A' 单个字符 使用单引号
true、false 逻辑真、逻辑假 两者也是 C++ 关键字
"GESP" 一段文字 使用双引号，不能当成单个 char

它们可以参与初始化或表达式。例如 int count = 10; 中的 10 为 count 提供初值；price * 2 + 5 中的 2 和 5 直接参与计算。

各种字面量具体属于什么类型、能表示多大范围，放在“基本数据类型”页理解。本页先认清写法和用途。

用 const 给固定值起名字

如果一个固定值会多次使用，可以给它一个有含义的名字，并用 const 限制后续修改：

const int bonus = 5;

这行建立了名为 bonus 的具名常量：

  • 名字：bonus；
  • 类型：const int；
  • 值：5；
  • 约束：建立后不能再通过赋值改变。

本页这种局部 const 对象应在定义时给出初值。后面再写 bonus = 8; 会编译失败，因为它违背了“不允许修改”的约束。

const 没有把数字 5 变成另一种数据。它做的是：让名为 bonus 的对象保持建立时的值，防止程序后面误改。

什么时候用字面量，什么时候用具名常量

一次性、含义非常直接的值可以写成字面量。一个值在题目中有明确含义、会重复出现或不应被修改时，具名常量更容易检查。

例如“每盒固定装 12 支笔”可以写：

const int pensPerBox = 12;int totalPens = boxCount * pensPerBox;

看到 pensPerBox 就知道 12 表示每盒数量；如果以后题目改成每盒 10 支，只需检查这个固定含义的位置。

04 变量与初始化

变量由名字、类型和当前值组成

变量可以理解为程序中一个有名字、能保存数据的对象。查看一个变量时，总要同时问三件事：

组成 要回答的问题 例子 int age = 12;
名字 后面的代码用什么名称找到它？ age
类型 这份数据按什么规则保存和解释？ int
当前值 执行到此刻，它里面保存什么？ 12

变量的类型在定义后固定，当前值可以被后续赋值改变，也可以一直保持不变。“变量”表示它允许变化，不表示它每次运行都必须变化。

声明、定义和初始化的区别

在本页的简单局部变量中：

int age;

这行告诉编译器“这里有一个名为 age、类型为 int 的变量”，并建立这个变量。它既完成了声明，也完成了定义，但还没有给普通局部整数一个可安全读取的初值。

下面这行同时建立变量并给出初值：

int age = 12;

这叫初始化。执行完成后，age 已经拥有确定状态：名字是 age，类型是 int，当前值是 12。

初始化只发生在变量建立时。变量已经存在以后再写：

age = 13;

这是赋值，它把当前值从 12 改为 13，并没有重新定义一个新的 age。

写法 发生了什么 执行后的状态
int age; 声明并定义变量，没有给可靠初值 名字和类型确定，值不可读取
int age = 12; 定义并初始化变量 age 当前值为 12
age = 13; 给已经存在的变量赋新值 类型仍为 int，当前值变为 13

为什么不能读取未初始化的普通局部变量

在 main 内写下 int score; 后，不能直接把 score 用于输出、比较或计算。对本页这种未初始化的普通局部整数，读取其不确定值会导致未定义行为：程序结果没有可靠保证，不能根据某次运行猜它“默认等于 0”。

错误过程是：

int score;cout << score;

安全做法是先让它得到确定值：

int score = 0;cout << score;

检查变量时，不只看“是否写过变量名”，还要沿执行顺序确认：在第一次读取之前，它是否已经初始化或赋值。

05 赋值与连续赋值

赋值先算右边，再写左边

赋值号 = 的任务是：先得到右侧结果，再把结果保存到左侧变量。

int score = 60;score = 85;

第一行建立并初始化 score；第二行才是后续赋值，用 85 覆盖旧值 60。类型没有改变，改变的是当前值。

当左右两边都出现同一个变量时，仍按“先右后左”执行：

int a = 5;a = a + 2;

执行第二行的过程是：

步骤 动作 a 的状态
1 读取右侧 a 的旧值 仍为 5
2 计算 5 + 2 得到结果 7，尚未写回
3 把 7 保存到左侧 a 当前值变为 7

这里不是在解数学方程“a 等于 a + 2”。= 表示一次有先后顺序的写入操作，所以同一个变量能够由 5 变成 7。

赋值复制当前值，不会建立自动连接

假设依次执行：

int a = 2;int b = 5;a = b;b = 8;

执行 a = b; 时，程序读取 b 当时的值 5，再把 5 保存给 a。接着把 b 改成 8，并不会自动把 a 一起改成 8。

执行后 a b
初始化完成 2 5
a = b; 5 5
b = 8; 5 8

普通整数赋值复制的是当时的值，不是给两个变量拴上一根永久连线。

连续赋值从右边开始

自测中会遇到连续赋值，因此要能识别它的执行顺序：

int a;int b;a = b = 3;

赋值运算按右结合解释，等价于分成两步：

b = 3;a = b;

第一步先让 b 得到 3；这一赋值表达式的结果再交给左边，于是第二步让 a 也得到 3。最终 a = 3、b = 3。

若写成 int a = b = 3;，b 仍必须提前定义。只在这一行定义了 a，并不会顺便定义 b。

一级主程序优先使用分步写法，因为执行顺序更容易检查。连续赋值需要会读，不必为了缩短一行而频繁使用。

= 和 == 的职责不同

a = b;a == b;
  • a = b：把 b 的当前值写入 a，会修改 a；
  • a == b：判断两者是否相等，得到真或假，不负责修改 a、b。

两者只差一个等号，程序作用却完全不同。具体关系运算放在“基本运算”页展开。

06 表达式

表达式会产生一个结果

表达式由常量、变量、运算符以及必要的括号组成，计算后得到一个结果。例如：

表达式 需要读取什么 得到什么
a + b a、b 的当前值 两数之和
price * count 当前单价和数量 总价数值
score >= 60 score 的当前值 真或假
(a + b) * 2 a、b 的当前值 先求和再乘 2 的数值

只计算 a + b 不会自动修改 a、b。要保存结果，需要初始化一个新变量，或赋值给已经存在的变量。

从当前值到结果，再保存

假设当前状态是 price = 8、count = 3、bonus = 5，执行：

int total = price * count + bonus;

真实过程可以拆成四步：

步骤 当前动作 结果
1 读取 price、count、bonus 的当前值 8、3、5
2 计算 8 * 3 24
3 计算 24 + 5 29
4 用结果 29 初始化 total total = 29

表达式先产生结果，保存动作随后发生。若只写 price * count + bonus;，虽然表达式可以算出 29，却没有把这个结果交给一个后续要用的变量。

变量变化后，旧结果不会自动重算

继续上一例。total 已经得到 29 后，把 price 赋成 10：

price = 10;

此时 price 变为 10，total 仍是之前保存的 29。只有再次执行：

total = price * count + bonus;

程序才会用当前值 10、3、5 重新计算，得到 35 并覆盖 total。

这条边界很重要：变量保存的是某次执行得到的结果，不是会随公式右侧自动更新的数学符号。

括号和优先级决定计算顺序

表达式中有多个运算符时，先处理括号，再按运算符优先级和结合方向计算。例如 price * count + bonus 先乘后加；(price + bonus) * count 先算括号，结果会不同。

本页追踪的重点是“取当前值 → 按规则计算 → 保存结果”。完整的算术、关系、逻辑、赋值优先级表放在“基本运算”页。拿不准时，优先补括号或拆成多条直白语句。

建立变量时的统一检查顺序

从题意建立一个变量，可以按下面的顺序检查：

  1. 它保存什么？ 先确定现实含义，例如单价、数量、总价。
  2. 叫什么？ 选择合法且能说明用途的标识符。
  3. 用什么类型？ 根据数据形式和范围选择；具体范围查“基本数据类型”。
  4. 初值从哪里来？ 来自固定值、输入，还是另一个表达式？
  5. 以后允许改变吗？ 不应修改的固定值可以使用 const。
  6. 第一次读取前有确定值吗？ 没有就先初始化或赋值。

例如“每盒 12 支笔，盒数可以变化”：

题意中的量 合适写法 判断
每盒支数 const int pensPerBox = 12; 固定含义，不应修改
盒数 int boxCount = 3; 当前值为 3，以后可能改变
总支数 int totalPens = pensPerBox * boxCount; 由当前两个值计算并保存

知识点速查表

概念 例子 关键判断
标识符 studentCount 字母开头、字符合法、不是关键字、区分大小写
关键字 int、return C++ 已规定用途，不能用作变量名
字面量常量 10、3.14、'A'、true 把固定值直接写进代码
具名常量 const int bonus = 5; 定义时给值，后面不再赋新值
变量 int age; 具有名字、类型和当前值状态
初始化 int age = 12; 建立变量时给初值
赋值 age = 13; 先算右侧，再覆盖左侧当前值
表达式 price * count + bonus 读取当前值，按规则计算出结果

典型例题

下面用一个程序验证本页最容易混淆的边界：变量改变以后，之前保存的表达式结果不会自动更新。

完成程序

#include <bits/stdc++.h>using namespace std;
int main() {    int price = 8;    int count = 3;    const int bonus = 5;
    int total = price * count + bonus; // 首次计算总价并把结果保存到 total    cout << total << endl;
    price = 10; // 只修改 price，已经保存的 total 不会自动更新    cout << total << endl;
    total = price * count + bonus; // 按当前价格重新计算，并用新结果覆盖 total    cout << total << endl;    return 0;}

程序不需要输入，输出为：

292935

逐步追踪：

顺序 执行内容 price count bonus total 本次输出
1 完成三个初始数据的建立 8 3 5 尚未建立 —
2 用 8 * 3 + 5 初始化 total 8 3 5 29 —
3 输出 total 8 3 5 29 29
4 price = 10; 10 3 5 29 —
5 再次输出尚未重算的 total 10 3 5 29 29
6 重新计算并赋值给 total 10 3 5 35 —
7 输出新的 total 10 3 5 35 35

第二行输出仍是 29，正好证明 total 没有与右侧公式永久绑定。第三行变为 35，是因为重新执行了表达式，并把新结果赋给 total。

引导练习（不记录进度）

依次执行 int a = 2; int b = a; a = 5;。每句后记录两个变量的当前值：第二句把当时的 2 复制给 b，第三句只修改 a，所以最终 a = 5、b = 2。

成功标准： 能说明赋值复制的是执行当时的值，不会建立自动连接。完成后不看提示独立完成页末“整页综合测试”；提交后按“右侧求值 → 左侧写回”重新推演每道错题。

常见错误

变量名不符合规则

错误： 使用 2score、student-score、break 作为变量名。

检查： 依次查开头、其余字符和关键字；再确认大小写是否与定义时一致。

读取未初始化的普通局部变量

错误： 只写 int score; 就参与输出或计算。

后果： 读取这种不确定值会造成未定义行为，结果不能信任，也不能假定为 0。

检查： 沿执行路径找到第一次读取，确认此前已经初始化或赋值。

把初始化和赋值混成一件事

错误理解： 认为 int age = 12; 与后面的 age = 13; 都在重新创建变量。

检查： 看这一行是否同时出现类型和新变量名。建立时给值是初始化；变量已经存在后改值是赋值。

把 = 当成数学等号

错误理解： 看到 a = a + 2; 就认为等式不可能成立。

检查： 按时间顺序读：取旧值、算右侧、写回左侧。相等比较使用 ==。

认为赋值会让两个变量永久联动

错误理解： 执行 a = b; 后再改 b，以为 a 也会跟着变。

检查： 在每次赋值后记录两个变量的当前值。普通整数赋值只复制执行当时的值。

从左向右误读连续赋值

错误： 把 a = b = 3; 理解成先处理 a = b。

检查： 按右结合拆为 b = 3;、a = b;。若写 int a = b = 3;，还要确认 b 已提前定义。

只改公式里的变量，却忘了重新计算结果

错误： price 已变化，却直接使用上一次保存的 total。

检查： 找到产生 total 的表达式，确认在所需的最新变量值出现后，它是否再次执行并写回结果。
