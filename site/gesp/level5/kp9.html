贪心算法

09
GESP 5级知识字典 · 知识点 09

完成贪心选择、排序后构造，并用交换论证说明正确性。

检索词：贪心选择交换论证
09

贪心算法会在每一步先作出一个当前选择，再继续处理剩余部分。关键不在“挑最大的或最小的”，而在于找到能够证明安全的选择标准。本课只围绕活动选择，学习怎样从冲突区间中选出尽量多的活动。

知识范围与官方定位

对应五级大纲“贪心算法”：理解局部最优与全局最优的区别，能设计并检验贪心策略，并能说明一个局部选择为什么不会破坏整体最优。

本页只使用一级至五级已经学习的语法和能力；小知识点按页内编号连续查询，不设置前置完成门槛。

是什么
贪心算法每一步确定一个不再撤销的选择，再在剩余候选中重复同样动作；每一步都必须有安全依据。
解决什么问题
本课用它解决活动选择：从若干半开区间中挑出尽量多的互不重叠活动，只输出最大数量。
什么时候使用
只有当选择标准明确，并且能证明当前选择可以换进某个最优方案而不使答案变差时，才使用贪心。
核心思想
先按 finish 升序、同 finish 时 start 升序得到完整候选顺序，再用交换论证证明这一步安全，最后在剩余活动中重复选择。
C++ 实现方法
用 Activity 数组保存开始、结束时间；比较函数先比较 finish，同 finish 时比较 start，随后顺序扫描，start>=lastEnd 时选择并更新状态。

01 贪心思想与适用条件

有 n 个活动，每个活动占用半开区间 [start, finish)。半开区间不包含右端点；本题把“互不重叠”定义为所选活动按执行先后排列后，每个后续活动都满足 start≥前一个活动的 finish，所以 [1,3) 与 [3,5) 可以首尾相接。目标是选择尽量多的活动。

本教学程序支持 0≤n≤1000、-10^9≤start≤finish≤10^9，只输出最多活动数，答案在 0 到 n 之间。输入允许 start=finish，这种活动仍按同一先后关系参加判断，不另设特殊规则。数组容量是 1005，n=1000 时实际使用下标 0 到 999，不会越界。

主样例按 [6,8)、[2,5)、[1,3)、[4,6) 的乱序输入。若直接沿用输入顺序，先选 [6,8) 会失去前面三个可用活动；若先选“开始最早”的 [1,10)，又会挡住 [2,3)、[3,4)、[4,5)。输入顺序和开始得早都不是可靠依据。真正要保留的是后续可用时间：当前活动结束得越早，留给后面的时间越多。

具体样例与推演

场景：主样例输入顺序为 [6,8)、[2,5)、[1,3)、[4,6)，目标是选择最多个互不重叠活动。

  1. 如果只按输入顺序先选 [6,8)，前面的三个活动都会被浪费，所以输入顺序没有提供可靠信息。
  2. 再看短反例 [1,10)、[2,3)、[3,4)、[4,5)：若先选开始最早的 [1,10)，只能得到 1 个活动；这条规则也不可靠。
  3. 把候选按结束时间观察，最早结束的是 [1,3)；选它以后，从时刻 3 起仍有 [4,6)、[6,8) 可以继续选择。
  4. 较早结束不会占用更多后续时间，由此先得到 finish 从小到大的主顺序；输入允许零长度活动，所以 finish 相同时还必须按 start 从小到大排列，完整顺序缺一不可。

适用结论：贪心规则必须来自题目目标与样例观察。本题要最大化活动数，所以每一步优先保留后续时间，而不是优先开始早、持续短或沿用输入顺序。

错误反例：看到区间题就直接按开始时间排序。

为什么错：[1,10) 开始最早，却会挡住 [2,3)、[3,4)、[4,5)；按开始时间选择只能得到 1 个，最优可以得到 3 个。

怎样改：先用短反例排除错误规则，再从“为后面留下更多时间”推出结束时间优先。

02 策略设计与正确性

完整的候选顺序是：先按 finish 从小到大排列，finish 相同时再按 start 从小到大排列。每次查看当前尚未处理的活动；若它的 start≥lastEnd，就选择它并把 lastEnd 更新为它的 finish，否则跳过。第二个排序条件不是为了好看：若合法输入依次是 [2,2)、[1,2)，只比较 finish 可能先扫描零长度活动 [2,2)，选中后 lastEnd=2，[1,2) 因 1<2 被跳过，只选到 1 个；按 start 升序会先扫描 [1,2)，再扫描 [2,2)，两个都能选中。

为什么完整顺序安全？先固定当前边界 L，只看 start≥L 的可接活动。取一个活动数最多的方案，设它的第一个活动是 B；完整顺序排第一的可接活动是 A。若 A.finish<B.finish，把 B 换成 A 后，原来能接在 B 后面的活动仍能接在 A 后面，活动数不会减少。若两者都在时刻 f 结束，就单独看这一组：两个 start<f 的活动会重叠，最多选一个；任意个零长度活动 [f,f) 都可以排在它后面。start 升序会先放置可接且开始更早的普通活动，再放置 [f,f)，既不会减少这一组能选的数量，处理完后边界仍是 f，也不会减少未来可接活动。

这种把最优方案中的选择换成贪心选择且答案不变差的说明叫交换论证。完整顺序同时处理了结束时间更早的交换和同结束时间的正确扫描次序；选定当前活动后，只处理 start≥它的 finish 的剩余活动，并重复同一理由。仅有局部最优不足以保证贪心正确；还必须证明这个局部选择能够安全地进入某个全局最优方案。仅有最优子结构不足以保证贪心正确；剩余问题仍是同类问题，并不能单独说明当前选择一定安全。

具体样例与推演

场景：设 A 是当前可接活动中按“finish 升序、同 finish 时 start 升序”排第一的活动，用交换论证检查“先选 A”是否安全。

  1. 先看完整顺序为什么不能少第二关键字：合法输入按 [2,2)、[1,2) 给出时，只比较 finish 可能先选 [2,2)，令 lastEnd=2，再因 1<2 跳过 [1,2)，只能选 1 个。
  2. 同 finish 时按 start 升序后，先选 [1,2)，再由 2≥2 选 [2,2)，一共选 2 个；同结束时先选开始更早的活动不会推迟结束时刻，还为同结束的零长度活动留下正确扫描顺序。
  3. 固定当前边界 L，取一个活动数最多的方案，设第一个活动为 B。若 A.finish<B.finish，把 B 换成 A 后，原来接在 B 后面的活动仍能接在 A 后面，活动数量不减。
  4. 若 A 与 B 都在时刻 f 结束，就检查整个同结束组：start<f 的活动彼此重叠，最多选一个；零长度活动 [f,f) 可以全部接在它后面。start 升序会先处理可接且开始更早的普通活动，再处理 [f,f)，这一组不会少选，处理后的边界仍是 f。
  5. 因此完整顺序既不会减少同结束组的数量，也不会推迟未来活动的可用起点。选定当前活动后，只处理 start≥它的 finish 的剩余活动，并重复同一完整顺序和同一交换论证。

适用结论：交换论证必须绑定完整顺序：finish 决定不会推迟后续起点，同 finish 时的 start 升序保证零长度活动不会反过来挡住同结束的普通活动；同结束组和未来候选都不变差，才能安全确定当前选择。

错误反例：剩余问题形式相同，所以当前随便选择一个活动也会最优。

为什么错：剩余问题形式相同只说明可以继续求解；它没有证明当前选择不会挡住更好的方案。

怎样改：先证明当前选择能换进某个最优方案，再在同类剩余问题上重复选择。

03 排序后选择

先把算法写成不依赖代码的完整步骤：①读入活动；②按 finish 从小到大排序，同 finish 时按 start 从小到大排序；③令 selected=0，并把 lastEnd 设成比所有合法开始时间都小的值；④逐个检查排序后的活动；⑤start≥lastEnd 时选择它，同时更新 selected 和 lastEnd，否则保持状态并跳过；⑥扫描完 n 个活动后返回 selected。

程序先定义 struct Activity，其中 start 保存开始时间，finish 保存结束时间；Activity activities[1005] 保存输入的 n 个活动。compareByFinish(left, right) 是命名比较函数：先比较 finish，结束时间相同时再比较 start；返回 true 表示 left 应排在 right 前面。这个第二关键字会把 [1,2) 排在 [2,2) 前面，是允许零长度活动时保证正确扫描顺序的一部分。

调用 sort(activities, activities + n, compareByFinish) 时，activities 表示数组开头，activities+n 表示前 n 项之后的位置。sort 会直接改变数组前 n 项的顺序，不会生成副本；排序完成后，主样例的乱序活动变为 [1,3)、[2,5)、[4,6)、[6,8)，而 [2,2)、[1,2) 会变为 [1,2)、[2,2)。

selectMaximumActivities(Activity activities[], int n) 接收活动数组和数量。selected 表示已经选择的活动数，初值为 0；lastEnd 表示上一个已选活动的结束时间。合法开始时间最小为 -1000000000，所以用更小 1 的 -1000000001 作哨兵，能保证第一个候选按真实条件判断，也能让 n=0 时直接返回 0。

扫描时先取当前活动的 start 和 finish。条件 start≥lastEnd 成立，说明当前活动可以接在已选安排后面，于是 selected++ 并令 lastEnd=finish；条件不成立就跳过，两个状态都不变。输入即使满足 start=finish，也继续使用这一个判断，不另开特殊分支。

排序耗时 O(n log n)，扫描耗时 O(n)，总时间复杂度为 O(n log n)。活动数组保存 n 个记录，占 O(n) 规模的存储；常见 GCC/OJ 环境中的 sort 还会使用 O(log n) 级调用栈，整体存储仍由活动数组主导为 O(n)。答案最大为 1000，时间与哨兵都在 int 范围内。

具体样例与推演

场景：按最终程序的完整顺序执行主样例：先按 finish 升序，同 finish 时按 start 升序；本例排序后为 [1,3)、[2,5)、[4,6)、[6,8)。

  1. 初始化 selected=0、lastEnd=-1000000001，下一步检查 [1,3)。
  2. 当前 selected=0、lastEnd=-1000000001；[1,3) 满足 1≥-1000000001，选择后 selected=1、lastEnd=3，下一步检查 [2,5)。
  3. 当前 selected=1、lastEnd=3；[2,5) 的开始时间 2<3，与已选活动冲突，所以跳过，状态不变，下一步检查 [4,6)。
  4. 当前 selected=1、lastEnd=3；[4,6) 满足 4≥3，选择后 selected=2、lastEnd=6，下一步检查 [6,8)。
  5. 当前 selected=2、lastEnd=6；[6,8) 满足 6≥6，半开区间允许端点相接，选择后 selected=3、lastEnd=8。
  6. 所有 4 个候选已经检查完毕，循环停止，函数返回 selected=3，main 输出 3。正确性仍由上一节的交换论证保证。

适用结论：每轮只根据 start≥lastEnd 判断当前活动；选择时同时更新 selected 和 lastEnd，跳过时两个状态都不变，扫描完全部候选后答案就在 selected 中。

错误反例：比较函数返回 left.start<right.start，把活动按开始时间排。

为什么错：开始最早不是已经证明安全的策略；程序顺序一变，执行账本和交换论证都无法支持代码。

怎样改：先比较 left.finish 与 right.finish；只有结束时间相同时才比较 start，并用 [2,2)、[1,2) 核对它们必须排成 [1,2)、[2,2)。

04 反例与适用边界

交换论证只证明“活动数量最大”这个模型中的最早结束策略，不能把“每次挑眼前最大或最小”机械搬到别的问题。面值为 1、3、4，要凑出 6 时，每次取不超过余额的最大面值会得到 4+1+1，共 3 枚；真正的最优方案是 3+3，只要 2 枚。这个反例说明未经证明的局部选择可能破坏全局最优。

一个成功样例只能帮助检查执行过程，不能代替一般正确性证明；一个合法反例却足以否定声称“对所有输入都正确”的策略。面对新的贪心题，要重新写清候选顺序、可行条件、状态更新和安全理由。

具体样例与推演

场景：检验“凑金额时每次取不超过余额的最大面值”这个看似合理的局部策略。

  1. 硬币面值为 1、3、4，目标金额为 6；第一步取最大面值 4，余额变成 2。
  2. 余额 2 只能再取 1 和 1，于是得到 4+1+1，共 3 枚。
  3. 直接选择 3+3 只用 2 枚，因此“每次取最大”在这个合法输入上不是全局最优。
  4. 这个反例否定的是未经证明的通用策略，不影响已经通过交换论证证明的活动选择策略。

适用结论：贪心策略不能按关键词套用。先写出局部选择，再用证明检查它是否安全；找出一个合法反例时，就应停止使用该规则。

错误反例：主样例输出 3，所以任何按结束时间排序的区间题都能直接套用。

为什么错：本课证明依赖“目标是活动数量最大、区间按时间冲突”这些条件；目标或约束改变后，原交换步骤可能不再成立。

怎样改：回到新题的目标和限制，重新检查候选顺序、可行条件、状态更新与交换理由。

典型例题

基础例题：选择最多不重叠活动

题意：输入 n 个活动。每行按 start、finish 给出半开区间 [start, finish)，满足 0≤n≤1000、-10^9≤start≤finish≤10^9，输出最多可选活动数。

示例输入：

4
6 8
2 5
1 3
4 6

示例输出：

3

说明：排序后依次得到 [1,3)、[2,5)、[4,6)、[6,8)。程序选择第 1、3、4 个候选，跳过与 [1,3) 重叠的 [2,5)，最终输出 3。前文已经先讲清结构体字段、比较函数、数组排序、哨兵、判断和完整执行；下面是与该过程一致的唯一完整程序。

#include <bits/stdc++.h>
using namespace std;

const int TIME_BEFORE_ALL = -1000000001; // 比最小合法开始时间小 1

struct Activity {
    int start;
    int finish;
};

Activity activities[1005]; // n 最大为 1000，下标 0 到 999 都安全

bool compareByFinish(Activity left, Activity right) {
    if (left.finish != right.finish) {
        return left.finish < right.finish;
    }
    return left.start < right.start;
}

int selectMaximumActivities(Activity activities[], int n) {
    sort(activities, activities + n, compareByFinish);

    int selected = 0;
    int lastEnd = TIME_BEFORE_ALL;

    for (int index = 0; index < n; index++) {
        int start = activities[index].start;
        int finish = activities[index].finish;

        if (start >= lastEnd) { // 半开区间允许当前活动与上一活动首尾相接
            selected++;
            lastEnd = finish;
        }
    }

    return selected;
}

int main() {
    int n;
    cin >> n;

    for (int index = 0; index < n; index++) {
        cin >> activities[index].start >> activities[index].finish;
    }

    cout << selectMaximumActivities(activities, n) << '\n';
    return 0;
}

典型应用：用短反例排除开始最早策略

题意：仍然选择最多活动，比较“开始时间最早”和“结束时间最早”两种规则。

示例输入：

4
1 10
2 3
3 4
4 5

示例输出：

3

解题说明：先选开始最早的 [1,10) 只能得到 1 个活动；按结束时间依次选择 [2,3)、[3,4)、[4,5)，可以得到 3 个。这个反例只排除错误规则，正确策略仍要靠交换论证说明。

执行追踪：用四个边界场景复核排序、哨兵与相接判断

输入场景关键判断状态变化最终结果
n=0没有候选，不进入扫描selected 保持 0，lastEnd 保持 -1000000001输出 0
只有 [-5,-2)-5>=-1000000001，成立selected: 0→1，lastEnd=-2输出 1
[-5,0) 与 [0,2)第二个活动 0>=0，成立selected: 1→2，lastEnd=2输出 2
输入顺序为 [2,2)、[1,2)同 finish 时按 start 升序，先检查 [1,2) 再检查 [2,2)先选 [1,2) 得 lastEnd=2；再由 2>=2 选 [2,2)，selected: 0→1→2输出 2；反向输入也相同

追踪结论：哨兵严格小于最小合法开始时间，能接住负时间；半开区间允许端点相接，所以判断必须保留等号。允许零长度活动时，同 finish 按 start 升序也是正确性所需规则，不能省略。

测试案例

类型输入 / 场景预期结果检查目的
基础测试[1,3) [2,5) [4,6) [6,8)选择 3 个：[1,3)、[4,6)、[6,8)同时验证一次冲突跳过、一次普通选择和一次端点相接。
边界测试n=0；只有 [-5,-2)；[-5,0) [0,2)；以及按两种输入顺序给出的 [2,2) [1,2)前三组分别输出 0、1、2；同结束零长度活动的两种输入都输出 2，实际扫描顺序都是 [1,2)、[2,2)验证空集合、负时间安全哨兵、端点相接，以及同 finish 时必须按 start 升序。
反例测试[1,10) [2,3) [3,4) [4,5)开始最早只能选 1 个，结束最早可选 3 个用可复算结果否定错误的开始时间优先策略。

常见错误

  • 把局部直觉当作证明：先写清交换或替换理由；一个样例不能证明所有输入都正确。
  • 比较函数按开始时间排序：本题已经证明安全的是结束时间最早；主关键字写错会使候选顺序和证明脱节。
  • 同结束时不比较开始时间：输入允许零长度活动；[2,2) 若排在 [1,2) 前面只能选 1 个。完整规则必须在 finish 相同时按 start 升序，使两个活动都能选中。
  • 把 lastEnd 初始化为 0：开始时间可以为负数，这会错误跳过所有在 0 之前开始的首个候选。
  • 选择后忘记更新 lastEnd：只有选中活动时才令 lastEnd=finish，否则后续判断会沿用旧边界。
  • 把端点相接判为冲突：半开区间中 start==lastEnd 可以选择，条件应写成 start>=lastEnd。

比较函数按开始时间排序

错误代码：

return left.start < right.start;

错误原因：开始最早的长活动可能挡住多个短活动；排序关键字一变，交换论证就不再支持程序。

正确写法：

if (left.finish != right.finish) {
    return left.finish < right.finish;
}
return left.start < right.start;

结束时间相同就直接判为同序

错误代码：

return left.finish < right.finish;

错误原因：输入允许零长度活动；若 [2,2) 在 [1,2) 前面，前者会把 lastEnd 设为 2，后者随即因 1<2 被跳过，答案从 2 变成 1。

正确写法：

if (left.finish != right.finish) {
    return left.finish < right.finish;
}
return left.start < right.start;

选择后没有更新结束边界

错误代码：

if (start >= lastEnd) {
    selected++;
}

错误原因：lastEnd 仍是旧值，后面的活动可能与刚选中的活动重叠，却被程序错误选入。

正确写法：

if (start >= lastEnd) {
    selected++;
    lastEnd = finish;
}

把结束边界从 0 开始

错误代码：

int lastEnd = 0;

错误原因：本题允许负时间，例如 [-5,-2) 本应可选，却会因为 -5<0 被错误跳过。

正确写法：

int lastEnd = -1000000001;

把端点相接写成严格大于

错误代码：

if (start > lastEnd) {
    selected++;
}

错误原因：半开区间 [a,b) 不占用 b 时刻；start==lastEnd 的活动能够衔接，严格大于会少选合法活动。

正确写法：

if (start >= lastEnd) {
    selected++;
    lastEnd = finish;
}
