排序算法

08
GESP 4级知识字典 · 知识点 08

掌握冒泡、插入、选择排序的过程与稳定性。

检索词：冒泡排序选择排序

排序按指定关键字重新排列数据。需要按成绩、编号或数值大小组织结果时，可以使用排序；四级重点是亲手追踪冒泡、插入和选择排序，而不是直接调用库函数。

本课先记住

核心结论

冒泡让极值逐趟到边界，插入把当前元素放进已排序区，选择每趟挑出未排序区的最小元素；三者最坏通常为 O(n²)。

常用语法

if (values[i] > values[i + 1]) { // 相邻两项逆序时才需要交换
    int temporary = values[i]; // 暂存左侧值，防止被覆盖
    values[i] = values[i + 1]; // 把较小值放到左边
    values[i + 1] = temporary; // 把原左值放到右边
} // 完成一对相邻元素的升序调整

最小示例

int values[4] = {0, 3, 1, 2}; // 采用 1 下标，0 号位置占位
// 从左向右比较一趟后为 1、2、3，最大值 3 到达末尾

关键易错点

  • 冒泡访问 values[i+1] 时循环到末尾导致越界
  • 插入排序右移前没有保存当前值
  • 选择排序只记最小值却没有记录最小值下标

这节课要会什么

学完后，你能在同一组数据上逐趟执行冒泡、插入和选择排序，写出正确边界，并判断稳定性。

从这个场景开始

整理一手数字卡片时，可以反复交换相邻逆序卡片，也可以把新卡插入已排好部分，还可以每次挑出最小卡放到前面。三种动作分别形成三种基础排序。

知识范围与官方定位

四级需要掌握冒泡排序、插入排序和选择排序，理解比较、交换或移动过程，能够估算复杂度并识别稳定性。

算法是怎样形成的

  1. 任务是把 4 2 5 1 3 排成升序。先尝试只看相邻卡片：4>2，所以交换；4<5，不交换；5>1、5>3，继续交换。走完一遍后，5 一定到了最右边。
  2. 右端的 5 已经就位，不必再碰。对前四个数重复相邻比较，每趟都把未排序区最大值送到右端，这就形成冒泡排序。
  3. 还可以把左边当成已经排好的区域。开始只有 [4]；拿到 2 时，把更大的 4 右移，再把 2 放进空位，左侧变成 [2 4]。
  4. 每次先保存当前值，再右移所有比它大的元素，最后插入空位；已排序区每轮扩大一个位置，这就形成插入排序。
  5. 第三种想法是先找“接下来应该放谁”。在 4 2 5 1 3 中找到最小值 1，把它与第一个位置交换，左端的 1 立即就位。
  6. 之后只在剩余区域继续找最小值并放到区域开头，每趟确定左端一个位置，这就形成选择排序。
  7. 三种方法都只交换或移动原有元素，不会凭空增加或漏掉数据；当未排序区为空时停止。它们最坏通常为 O(n²)，稳定性要看相等元素是否被跨越。

01 排序目标与稳定性

排序先确定关键字和方向。按整数升序要求前项不大于后项；结构体可以按 score 等某个成员作为关键字，移动时仍要保持整个对象完整。

待排序数据都放在内存中处理称为内排序；数据量太大、过程需要外部文件参与称为外排序。四级编程核心是数组上的三种内排序。

稳定性只讨论“关键字相等的不同记录”原相对顺序是否保留。冒泡使用严格大于才交换、插入使用严格大于才右移时可以稳定；直接交换远处最小值的选择排序通常不稳定。

  • 原顺序为 (2,A)、(2,B)、(1,C)，A 在 B 前
  • 选择排序第一趟把 (1,C) 与首项交换，得到 (1,C)、(2,B)、(2,A)
  • 两个关键字同为 2 的记录从 A-B 变成 B-A，所以这份选择排序不稳定

02 冒泡排序

从左到右比较相邻元素，左大右小时交换。一个较大元素可能连续向右移动；一趟结束后，未排序区最大值一定到达右端。

end 表示本趟未排序区的最后位置，内层必须满足 i<end 才能安全访问 i+1。每完成一趟，end 左移；若整趟没有交换，说明当前数组已经有序，可以 break。

  • 初始：4 2 5 1 3
  • 第 1 趟：2 4 1 3 5，最大值 5 到末尾
  • 第 2 趟：2 1 3 4 5
  • 继续处理未排序区，最终得到 1 2 3 4 5
for (int end = n; end >= 2; end--) { // end 是当前未排序区右边界
    bool changed = false; // 记录本趟是否发生过交换
    for (int i = 1; i < end; i++) { // 比较到 end-1，保证 i+1 不越界
        if (values[i] > values[i + 1]) { // 相邻元素逆序时交换
            int temporary = values[i]; // 暂存左值
            values[i] = values[i + 1]; // 较小的右值移到左边
            values[i + 1] = temporary; // 原左值移到右边
            changed = true; // 标记本趟确实改变了序列
        } // 结束当前相邻对判断
    } // 完成本趟全部相邻比较
    if (!changed) { // 本趟零交换表示数组已经升序
        break; // 立即停止不必要的后续趟数
    } // 结束提前终止判断
} // 冒泡排序结束

03 插入排序

始终维持 values[1..i-1] 已经有序。先把 values[i] 保存为 current，再从有序区右端向左寻找位置；比 current 大的元素依次右移，最后把 current 放进留下的空位。

while 条件要先检查 position>=1，再访问 values[position]。只在严格大于时右移，相等记录不会跨过 current，因此可以保持稳定。

  • 初始有序区：[4]
  • 插入 2 后：[2 4] 5 1 3
  • 插入 5 后：[2 4 5] 1 3
  • 继续插入 1、3，最终得到 [1 2 3 4 5]
for (int i = 2; i <= n; i++) { // 依次把第 i 个元素插入左侧有序区
    int current = values[i]; // 右移之前保存待插入值
    int position = i - 1; // 从有序区最右端开始检查
    while (position >= 1 && values[position] > current) { // 边界合法且前项更大时右移
        values[position + 1] = values[position]; // 给 current 腾出一个位置
        position--; // 继续向左寻找插入点
    } // 条件首次失败时，position+1 就是插入位置
    values[position + 1] = current; // 把保存的元素放入空位
} // 全部元素插入后数组升序

04 选择排序

每一趟先假设 start 位置最小，再扫描 start+1 到 n；发现更小元素时只更新 minimum 下标。扫描结束后才交换一次，把真正最小值放到 start。

即使一趟只交换一次，寻找最小值仍要查看整个未排序区，所以最坏比较次数仍为二次数量级。远距离交换可能跨过相等记录，因此通常不稳定。

  • 初始：4 2 5 1 3
  • 第 1 趟选到最小值 1：1 2 5 4 3
  • 第 2 趟最小值已经是 2：1 2 5 4 3
  • 继续选择未排序区最小值，最终得到 1 2 3 4 5
for (int start = 1; start < n; start++) { // 每趟确定 start 位置的元素
    int minimum = start; // 先假设未排序区首项最小
    for (int i = start + 1; i <= n; i++) { // 扫描未排序区其余位置
        if (values[i] < values[minimum]) { // 找到更小元素时更新候选
            minimum = i; // 保存最小元素下标而不只保存数值
        } // 结束当前元素比较
    } // 扫描结束后 minimum 指向本区最小值
    int temporary = values[start]; // 暂存未排序区首项
    values[start] = values[minimum]; // 把最小值放到已确定位置
    values[minimum] = temporary; // 把原首项放到最小值原位置
} // 完成所有选择排序趟数

05 三种排序的比较

三种算法最坏时间复杂度通常都是 O(n²)，额外空间都是 O(1)。这说明增长数量级相同，不表示每组数据做的操作完全一样。

冒泡交换相邻元素，插入移动有序区，选择扫描并记录最小下标。稳定性必须结合严格比较与实际移动方式判断，不能只背算法名字。

结构体数组排序时，比较的是某个成员，交换或移动的必须是整个结构体对象。下面用已经讲清的选择排序按 score 升序排列，姓名和分数才不会错位。

  • Alice 88、Bob 95、Carol 91 按 score 升序后是 Alice 88、Carol 91、Bob 95
  • 只交换 score 会让姓名与成绩错配；交换整个 Student 才保持同一对象的成员关系
  • n=5 时，最坏情况下三种排序都要进行数量级约为 5² 的比较或移动
  • 数据接近有序时，带提前结束的冒泡和插入排序可能少做很多工作
  • 选择排序每趟仍要扫描未排序区寻找最小值，但交换次数通常较少
for (int start = 1; start < n; start++) { // 逐趟确定结构体数组左端位置
    int minimum = start; // 保存当前最低分学生的下标
    for (int i = start + 1; i <= n; i++) { // 扫描剩余学生对象
        if (students[i].score < students[minimum].score) { // 只比较 score 关键字
            minimum = i; // 更新最低分对象的完整下标
        } // 结束当前学生比较
    } // 完成本趟最低分查找
    Student temporary = students[start]; // 暂存整个学生对象
    students[start] = students[minimum]; // 把最低分学生对象放到 start
    students[minimum] = temporary; // 把原 start 对象整体放回空位
} // 完成结构体数组选择排序

典型例题

用冒泡排序完成升序排列

教学程序约定 1≤n≤100、每个元素在 int 范围内，使用 1 下标冒泡排序后输出。

完成程序

#include <bits/stdc++.h> // 引入本程序需要的标准库
using namespace std; // 允许直接使用 cin、cout、string 等标准库名称

int main() { // 主函数是程序的入口
    int n; // 定义待排序元素数量
    cin >> n; // 读入元素数量
    int values[105] = {}; // 创建 1 下标数组并初始化为 0
    for (int i = 1; i <= n; i++) { // 遍历所有待排序位置
        cin >> values[i]; // 读入第 i 个元素
    } // 结束数组输入循环

    for (int end = n; end >= 2; end--) { // 每趟把未排序区的最大值放到 end
        for (int i = 1; i < end; i++) { // 比较未排序区中的每一对相邻元素
            if (values[i] > values[i + 1]) { // 发现相邻元素不满足升序
                int temporary = values[i]; // 暂存左侧元素，防止交换时丢失
                values[i] = values[i + 1]; // 把较小的右侧元素移到左边
                values[i + 1] = temporary; // 把原左侧元素放到右边
            } // 结束本次是否交换的判断
        } // 结束当前一趟的相邻比较
    } // 结束所有冒泡排序趟数

    for (int i = 1; i <= n; i++) { // 按顺序遍历排序后的数组
        if (i == n) { // 判断当前元素是否为最后一个输出项
            cout << values[i] << '\n'; // 输出末元素并结束本行
        } else { // 尚未到末元素时使用空格分隔
            cout << values[i] << ' '; // 输出当前元素和一个空格
        } // 结束输出格式判断
    } // 结束结果输出循环
    return 0; // 返回 0，表示程序正常结束
} // 结束 main 函数
示例输入
5
4 2 5 1 3
示例输出
1 2 3 4 5

解题与执行过程

  1. 初始数组是 4 2 5 1 3，比较条件 values[i] > values[i + 1] 表示目标为升序。
  2. 第一趟相邻比较后得到 2 4 1 3 5，最大值 5 到达末尾。
  3. 第二趟只检查前 4 个位置，得到 2 1 3 4 5；后续每趟继续缩小未排序区。
  4. 所有趟完成后数组为 1 2 3 4 5，输出时按下标 1 到 n 访问。

常见错误

内层循环访问 i+1 越界

错误写法：冒泡内层写 i <= end 后仍访问 values[i + 1]。原因：i = end 时访问越过当前范围。正确写法：保证 i < end。

排序趟数和未排序区不缩小

错误写法：每一趟都重复检查整个数组末尾。原因：已就位元素被无谓重复处理。正确写法：让 end 或 start 随趟数缩小未排序区。

插入前没有保存 current

错误写法：先右移 values[i - 1] 覆盖 values[i]，之后才读取待插入值。原因：原值已经丢失。正确写法：右移前先保存 current。

选择排序只保存最小值、不保存下标

错误写法：只记 minimumValue，最后不知道和哪个位置交换。原因：交换需要位置。正确写法：保存 minimum 下标，再交换 values[start] 与 values[minimum]。
