模拟算法

08
GESP 3级知识字典 · 知识点 08

按题目规则保存状态并逐步推进，得到最终结果。

检索词：状态保存规则推进

本课先记住

核心结论

模拟法把题目给出的过程按原顺序执行，并把下一步仍要使用的信息保存在状态变量中。只保存完成任务所需的最小状态，并给出明确初值；严格按照 day++ → 上爬 → 立即判断 → 未到才下滑 的顺序更新；先处理边界和停止条件，再从最终状态输出答案。

常用语法

本课只使用三级已经学过的变量、分支、循环、break、一维数组、字符串、取模和位运算。典型的一轮写法是：先修改状态，再用 if 判断是否停止；只有未停止时，才执行本轮剩余操作。

最小示例

青蛙清晨高度是 0，白天上爬 5 米后到达 5 米；因为 5 < 15，夜晚才下滑 2 米，下一天从 3 米开始。这个小过程已经包含“读旧状态、更新、判断、决定下一步”。

关键易错点

  • 最后一天到达井口后不再下滑，不能把每一天都简单写成 up - down。
  • 第一天已经到达时，即使 up <= down，答案仍是 1，不能误判为 Impossible。
  • 候选状态必须先检查再写回；计分板累加、光标移动和字符串分割也遵守同一原则。

知识范围与使用边界

模拟法不是背模板，而是把题目的每条规则变成可核对的一次动作。一次完整模拟可以概括为：读取当前状态 → 执行一次操作 → 更新状态 → 判断是否结束。本课只处理规则明确、状态数量少、能够用三级已学语法逐步执行的问题，不引入自定义函数、指针、二维数组、容器、排序、递归、搜索或状态机术语。

贯穿全课的代表问题是青蛙爬井：一口井深 target 米，青蛙白天上爬 up 米；若已到达井口就立即结束，否则夜晚下滑 down 米。程序输出首次到达所需天数；永远无法到达时输出 Impossible。

教学程序公开支持：1 <= target, up, down <= 1000000。最多只输出一个不超过 target 的正整数或单词 Impossible；循环中的高度小于 target + up，最大不超过 1999999，所以 int 安全。

01 模拟思想

模拟时先问：下一步还需要知道什么？青蛙问题只需要井深 target、白天上爬量 up、夜晚下滑量 down、当前高度 height 和已经开始的天数 day。其中前三个量来自输入，后两个量会在执行中变化。

主样例 S1 的输入是 15 5 2，输出是 5。第一天从高度 0 开始，上爬到 5，没有到达 15，才下滑到 3；后一天必须从 3 接着算，不能回到初值 0。

这说明模拟法的关键不是循环写几层，而是后一轮必须读取前一轮完成后的真实状态。

枚举与模拟的区别

枚举法和模拟法都可能使用循环，但每一轮含义不同。枚举法每轮检查一个候选，重点是不重不漏；模拟法每轮执行一条操作或一个时刻，重点是状态变量与更新顺序。青蛙问题的一轮表示“一天”，不是在猜一个答案。

如果一道题先枚举候选、再对候选执行若干规则，要分别说清两部分职责，不能因为都使用循环就把它们混为一种方法。

状态变量与更新顺序

只保存下一步确实需要的信息，叫作最小状态。height 只表示当前高度，初值为 0；day 只表示已经开始了几天，初值为 0。进入新一天时才执行 day++，白天上爬时才改变 height。

当前分数、当前位置、当前字符，都是下一步还要继续使用的信息；在别的模拟题里，它们同样应由职责清楚的状态变量保存。

三个核心必须连在一起理解：最小状态让我们知道保存什么；更新顺序让我们知道什么时候修改；停止条件让我们知道什么时候不再执行下一步。

边界处理与环形移动

先看青蛙问题的两个边界。若 up >= target，第一天完成，夜晚是否下滑已经没有意义。若第一天还没到达，也就是 up < target，并且 up <= down，每个完整昼夜都没有正增长，以后也无法到达，因此准确的无解条件是 up < target && up <= down。

这个条件不能简写成 up <= down。例如输入 5 5 5，白天已经到达 5 米，答案是 1，不是 Impossible。

其他模拟题也要先按题意确定边界。普通光标越界时可能“无效即不动”，环形位置则可能回到另一端。只有题目明确规定首尾相连时，才使用取模；Z 向后移动 28 位，实际移动 28 % 26 = 2 位，过程是 Z → A → B。

模拟状态更新

从错误直觉形成正确规则

最自然的想法是把每一天都看成净增加 up - down。困难在于最后一天到达井口后不再下滑：若把最后一天也减去 down，就改变了题目规定的停止时机。

在 S1 中，第 4 天清晨高度为 9，上爬后是 14，还没到 15，所以必须下滑到 12；第 5 天从 12 上爬到 17，已经到达，此时立即停止。这个具体动作告诉我们，判断必须放在上爬之后、下滑之前。

因此每轮都重复同一条规则：day++ → 上爬 → 立即判断 → 未到才下滑。无解分支在循环前结束；进入循环的分支要么第一天到达，要么满足 up > down，每个未完成昼夜都会取得正增长，所以程序一定停止。

八步执行方法

  1. 读入 target、up 和 down。
  2. 若 up < target && up <= down，输出 Impossible 并结束。
  3. 将 height 和 day 都初始化为 0。
  4. 开始新一天，执行 day++。
  5. 白天上爬，执行 height = height + up。
  6. 若 height >= target，立即 break，本日不再下滑。
  7. 只有尚未到达时，执行 height = height - down，再进入下一天。
  8. 循环停止后输出 day 和换行。

用同一框架看五类迁移题

下面只迁移“状态、更新、判断”的框架，不建立第二套完整算法。每个片段都依赖它自己的题意和公开范围。

计分板中，score[0] 表示第 0 位玩家，数组下标约定必须始终一致。光标题目中，若候选越界，正式位置和字符都保持不变。字符串分割中，pos 指向分隔符开头，下一轮要同时跳过分隔符本身。这些都是“先读当前状态，再按题意决定是否写回”的具体应用。

状态更新顺序追踪

下面是 C1 对 S1 的完整线性执行。每一行的“候选天”是操作级追踪；同一行中的清晨、上爬、判断、下滑和下一步是状态级追踪。

从任意一行都能预测下一行：判断为假，才用下滑后的高度开始下一天；判断为真，就直接输出并停止。形成推演回答“为什么这样排顺序”，这张账本回答“这个顺序实际怎样运行”，两者不能互相代替。

典型例题

青蛙爬井：输入、输出与职责

输入三个整数：target 是井深，up 是白天上爬高度，down 是未到达时夜晚下滑高度。height 从 0 开始保存当前高度，day 从 0 开始保存已经开始的天数；无解判断必须先于循环，循环内的到达判断必须先于下滑。

完成程序

程序与八步方法逐项对应。首日到达不会进入无解分支；进入循环后，每轮要么到达并停止，要么在完整昼夜后取得正增长。因此合法输入不会无限循环，输出就是首次到达时的天数。

常见错误

  1. 把每天都写成净增长。 现象：样例天数偏大或最后一天高度被再次减小。→原因：到达后仍计算 up - down。→修正：先上爬再判断，未到才下滑。→复验：5 5 3 必须输出 1。
  2. 把判断放在下滑之后。 现象：15 5 2 第 5 天上爬到 17 后又变成 15。→原因：没有在白天到达时立即停止。→修正：把 if (height >= target) 放在下滑之前。→复验：追踪第 5 天的“未到才下滑”必须是不执行。
  3. 首日到达仍判无解。 现象：5 5 5 输出 Impossible。→原因：只检查 up <= down。→修正：无解条件写成 up < target && up <= down。→复验：5 5 5 输出 1。
  4. 无解不等号写错。 现象：10 3 3 进入死循环。→原因：把 up <= down 错写成 up < down。→修正：净增长为 0 也无法到达。→复验：10 3 3 输出 Impossible。
  5. 把累加写成覆盖。 现象：同一玩家后一次得分抹掉旧分数。→原因：写成 score[player] = value。→修正：读取当前分数后使用 score[player] += value。→复验：初值 4 再加 4 应得到 8。
  6. 候选状态未检查就写回。 现象：光标可能保存越界位置。→原因：先修改 position，再检查是否合法。→修正：先计算 nextPosition，检查通过后再执行 position = nextPosition。→复验：位置 4 再向后 1、有效范围 0 到 4 时仍保持 4。
  7. 后一步读取旧值。 现象：Q5 得到的分数不是 8。→原因：没有先完成 code ^= 2。→修正：严格按输入顺序写回每一步状态。→复验：code 为 6、分数为 4 时，先得到 4，再累计为 8。

到达后仍下滑会破坏真实停止时机

× 错误写法每一天都先执行 height = height + up - down
✓ 正确写法day++，上爬，立即判断；只有未到达时才下滑

原因：最后一天白天已经到达井口，题目规定立即结束；合并更新会多执行一次本不该发生的下滑。

检查方法：把题目中的时间顺序写在代码旁，再逐项核对每个判断位于哪个动作之前。
