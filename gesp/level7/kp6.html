图的存储

06
GESP 7级知识字典 · 知识点 06

掌握邻接矩阵、邻接表与链式前向星。

检索词：邻接矩阵邻接表

知识范围与官方定位

官方七级大纲要求掌握图的存储。存储方式不会改变图本身，但会改变判断一条边、枚举相邻点和占用空间的代价。本页覆盖邻接矩阵、邻接表和链式前向星入门。

01 邻接矩阵

用 edge[u][v] 表示 u 到 v 是否有边。无向图要同时设置 edge[u][v] 与 edge[v][u]。邻接矩阵判断两点是否直接相连很方便，空间复杂度为 O(n^2)，适合顶点较少或较稠密的图。

具体推演： 无向图有边 1—3 时，把 edge[1][3] 和 edge[3][1] 都设为 1。随后查询 1 与 3 是否直接相连，只需读取一个数组位置；查询 1 与 2 得到 0，表示没有直接边，但不能据此断言两点之间一定不存在经过其他顶点的路径。

02 邻接表

vector<int> graph[N] 中，graph[u] 保存 u 的所有相邻点。存储无向边也要加入两个方向。邻接表空间通常为 O(n+m)，枚举某个顶点的邻边只访问实际存在的边，适合稀疏图。

具体推演： 依次加入无向边 1—2、1—3 后，graph[1]=[2,3]、graph[2]=[1]、graph[3]=[1]。枚举顶点 1 只访问两个真实邻点，不必扫描所有顶点；若漏存反向边，枚举顶点 2 时就会错误地看不到顶点 1。

03 链式前向星入门

链式前向星使用数组模拟邻接表，四个常见数组各有明确职责：

  • head[u]：顶点 u 当前第一条出边的编号，没有出边时为 -1；
  • to[index]：编号为 index 的边到达哪个顶点；
  • next[index]：同一起点的下一条边编号；
  • w[index]：这条边的权值；无权图可以不使用。

加入有向边 u -> v 时，先令 to[index] = v、next[index] = head[u]，再令 head[u] = index。枚举 u 的出边时，从 head[u] 开始不断跳到 next[index]，直到 -1。无向边仍要调用两次加边过程。

具体推演： 初始 head[1]=-1。加入编号 0 的边 1→2 后，to[0]=2、next[0]=-1、head[1]=0；再加入编号 1 的边 1→3 后，to[1]=3、next[1]=0、head[1]=1。从边号 1 开始沿 next 走到 0，枚举顺序就是 3、2。

04 存储选择与建图规则

频繁判断任意两点是否有边可考虑邻接矩阵；稀疏图中枚举邻点可用邻接表或链式前向星；只按输入顺序枚举全部边时也可直接保存边集。建图前还要确认顶点编号范围、图是否有向、是否带权、是否可能有重边或自环。带权邻接矩阵的“没有边”不能总用 0 表示，因为合法边权也可能为 0。

具体推演： n=1000、m=1200 时，邻接矩阵需要约一百万个位置，而邻接表只保存表头和约 2400 条无向邻接记录，后者更合适。若输入是一条权值为 0 的边 1—2，再用矩阵值 0 表示“无边”，就无法区分这条合法零权边，因此必须另设存在标记或哨兵。

知识点速查表

结构 空间 擅长
邻接矩阵 O(n^2) 快速判断两点是否直接相连
邻接表 O(n+m) 枚举某个顶点的实际邻边
链式前向星 O(n+m) 用固定数组枚举顶点出边

典型例题

基础例题

无向图只有一条边 1—2。使用邻接矩阵时设置 edge[1][2] = edge[2][1] = 1；使用邻接表时把 2 加入 graph[1]，同时把 1 加入 graph[2]。两种结构表示的是同一张图，只是查询方式和空间不同。

典型应用例题

读入无向图并输出每个顶点的相邻点：

#include <bits/stdc++.h>using namespace std;
int main() {    int n, m;    cin >> n >> m;    vector<int> graph[1005];    // 无向边必须在两个端点的邻接表中各保存一次。    for (int i = 1; i <= m; i++) {        int u, v;        cin >> u >> v;        graph[u].push_back(v);        graph[v].push_back(u);    }    // 逐个顶点枚举邻接表，只访问真实存在的邻接记录。    for (int u = 1; u <= n; u++) {        cout << u << ":";        for (int i = 0; i < graph[u].size(); i++) {            cout << " " << graph[u][i];        }        cout << endl;    }    return 0;}

建图与枚举总时间复杂度为 O(n+m)，空间复杂度为 O(n+m)。

加边追踪

依次加入无向边 (1,2)、(1,3)，邻接表和链式前向星的变化如下：

操作 邻接表变化 链式前向星中顶点 1 的边链
初始 graph[1] 为空 head[1] = -1
加入 (1,2) 的 1 → 2 graph[1] = [2] to[0] = 2，next[0] = -1，head[1] = 0
加入 (1,3) 的 1 → 3 graph[1] = [2,3] to[2] = 3，next[2] = 0，head[1] = 2

链式前向星采用头插法，所以从 head[1] 枚举时会先看到新加入的 3，再沿 next 看到 2。无向边的反向记录也要分别加入对应端点。

建议测试案例

测试类型 输入或条件 预期结果
基础 n = 3，边为 1 2、1 3 顶点 1 的邻点包含 2 和 3
边界 n = 1, m = 0 唯一顶点的邻接表为空
易错 有向边 1 → 2 只存一个方向，不能自动加入 2 → 1

常见错误

错误做法 为什么错 正确方法
无向边只存一个方向 从另一端遍历时会漏边 分别保存 u → v 和 v → u
顶点使用 1 下标，数组只开到 n 下标 n 会越界 数组至少开到 n + 1
稀疏大图仍使用邻接矩阵 O(n^2) 空间可能无法容纳 改用邻接表或链式前向星
忘记把 head 初始化为 -1 无法正确识别边链结束 建图前统一初始化 head
先覆盖 head[u] 再保存旧表头 原有出边会丢失 先令 next[index] = head[u]，最后更新 head[u]
用合法边权表示“没有边” 零权边等情况会被误判 使用单独标记或不可能混淆的哨兵值

错误反例推演

初始 head[1]=0，表示顶点 1 已有一条边。新增边号 1 时若先写 head[1]=1，再写 next[1]=head[1]，就会得到 next[1]=1，边链永远指向自己，旧边号 0 也丢失。正确顺序先保存 next[1]=0，再更新 head[1]=1，枚举才能得到新边和旧边。

关联学习

图的遍历通常使用邻接表枚举相邻点；选择存储结构时要同时考虑后续算法的访问方式。
