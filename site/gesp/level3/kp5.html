一维数组

05
GESP 3级知识字典 · 知识点 05

按位置编号访问元素，完成统计、查找和最值更新，并检查下标范围。

检索词：下标访问范围检查

本课先记住

  • 核心结论： 数组最多能放多少个元素，叫作容量；这次实际用了多少个，叫作元素个数。元素在数组中的位置编号，叫作下标。数组的开头、末尾以及允许访问的最小和最大下标，都是需要检查的边界。
  • 常用语法： 用 int a[100] = {}; 声明定长数组；0-based 的前 n 项是 a[0] 到 a[n - 1]，遍历写成 for (int i = 0; i < n; i++)。
  • 最小示例： int score[5] = {72, 80}; 会把前两项设为 72、80，其余三项自动设为 0；本次若只使用两项，循环仍只走 i < 2。
  • 关键易错点： a[n] 已越过本次有效元素；只有 n 等于容量时，a[n] 才越过数组本身。写程序时既要检查 n 不超过容量，也要按本次实际元素个数控制访问。

知识范围与使用边界

先看一个具体问题：要保存 30 名同学的成绩，若分别声明 30 个变量，输入、统计和查找都会写成大量重复语句。一维数组把一组同类型、有顺序的数据放在连续的位置中，再用编号访问其中一项，循环就能按同一规则处理全部数据。

本课只解决三个核心问题：怎样声明数组并安全访问有效位置；怎样在遍历中维护计数、查找和最值状态；怎样根据访问式和值域反推相邻、移动、标记和计数的合法范围。七个稳定知识区继续完整保留，但都服务于这三个核心。

本课使用编译时已经确定长度的原生一维数组，输入数据最多 100 项。输入输出、变量、分支和循环沿用已经学过的写法，不重新展开。

核心概念

核心一：安全存取。 先分清固定容量、实际元素个数 n 和合法位置，再读写数组。

核心二：遍历维护状态。 i 决定本轮访问哪一项，计数器、查找位置或最值变量保存已经处理部分的结果。

核心三：从访问式和值域反推限制。 看见 a[i - 1]、a[i + 1] 或 cnt[value]，要先证明这些位置不会超出可用范围。

数组元素类型一旦确定，每个位置都按同一种类型解释；数组长度也必须在编译时确定。本课使用的原生数组是固定长度，不能在运行中把 int a[5] 自动扩展成 int a[6]，所以要先根据题目数据范围预留足够容量。

数组占用的总字节数按“容量 × 每个元素的字节数”计算。在常见 GCC/OJ 环境中，一个 int 通常占 4 字节，因此 int a[5] 通常占 5 × 4 = 20 字节，int a[100] 通常占 100 × 4 = 400 字节。int 的准确大小由编译器和平台决定，所以程序应使用 sizeof 核对，不能把 4 当作所有环境永远不变的语言规则。

实际元素个数 n 不会改变数组已经分配的容量。即使 int a[100] 本次只读入 n = 7 个数，这个数组仍为 100 个 int 位置预留空间；循环只应访问 a[0] 到 a[6]。因此“分配多少空间”看容量，“本次处理多少数据”看 n，两项要分别检查。

对在当前作用域中声明的原生数组，可以用 sizeof 计算容量：

sizeof(a) 得到整个数组占用的字节数，sizeof(a[0]) 得到一个元素占用的字节数，二者相除就是元素个数。这个公式只适用于当前作用域中完整的原生数组，不要把它当成适用于任何变量的通用求长度公式。

把循环写到 i <= n 会多访问一项

× 错误写法有 n 个元素时使用 for (int i = 0; i <= n; i++) 访问 a[i]
✓ 正确写法0-based 遍历写为 i = 0 到 i < n；需要前一项的相邻扫描写为 i = 1 到 i < n。

原因：最后一次 i 等于 n，而有效的最后一项是 a[n - 1]；a[n] 已越过有效数据。

检查方法：先写出最后一次循环要访问的下标，再反推循环条件。

常见错误

  1. 把容量当成元素个数。 现象：声明 int a[100] 后总是处理 100 项。原因：100 只是最多可放的位置数，本次有效数据由 n 决定。修正：输入前检查 n，遍历只走 i < n。复验：n = 3 时只访问 a[0] 到 a[2]。
  2. 混用两套编号。 现象：输入写进 a[0] 到 a[n - 1]，输出却从 a[1] 开始。原因：0-based 与 1-based 混在同一段代码里。修正：一段程序只采用一套约定。复验：逐项写出第一个和最后一个实际访问的位置。
  3. 循环写成 i <= n。 现象：最后一轮访问 a[n]。原因：最后一个有效位置是 n - 1。修正：0-based 遍历使用 i < n。复验：代入 n = 5，最后一次循环应为 i = 4。
  4. 输入前不检查 n。 现象：n = 101 时仍向容量 100 的数组写入。原因：循环开始前没有验证实际元素个数。修正：先判断 n < 1 || n > CAPACITY。复验：n = 0 和 n = 101 都输出 Invalid。
  5. 空数据仍读取首项。 现象：n = 0 时执行 maximum = a[0]。原因：首项并不是本次有效数据。修正：在初始化最值前排除空数据。复验：只有 1 <= n <= CAPACITY 才进入读数和最值循环。
  6. 相邻扫描从 0 开始。 现象：第一轮尝试访问 a[-1]。原因：表达式含 a[i - 1]，却没有反推 i 的最小值。修正：从 i = 1 开始。复验：第一对是 a[0] 与 a[1]，最后一对是 a[n - 2] 与 a[n - 1]。
  7. 最大值初始化为 0。 现象：全负数输入得到不存在的最大值 0。原因：初值不是任何真实候选。修正：使用 a[0] 初始化。复验：-8 -3 -5 必须得到 -3。
  8. 相等时覆盖第一次位置。 现象：4 -2 7 7 1 得到位置 3。原因：更新条件写成了 >=。修正：只在 a[i] > maximum 时更新。复验：两个 7 中保留下标 2。
  9. 直接整体赋值。 现象：写出 destination = source;。原因：原生数组不能用普通赋值语句整体复制。修正：按相同合法位置逐项赋值。复验：逐轮核对 destination[i] = source[i]。
  10. 把任意数值当位置。 现象：负数或大于 100 的值直接用于 appeared[value]。原因：没有证明值域落在 0 到 100。修正：只在题目保证或程序检查值域后访问。复验：分别检查最小值 0、最大值 100 和两个范围外反例。

本课收束为三个动作：先用容量、n 和合法位置保证安全存取；再在遍历中维护真实状态；最后根据访问式和值域反推限制。计数、查找、最值、相邻、移动和按值记录都只是这三个动作的不同应用。
