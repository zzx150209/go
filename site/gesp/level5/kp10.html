分治与排序

10
GESP 5级知识字典 · 知识点 10

掌握分治三步，实现归并排序与快速排序。

检索词：分治三步归并快排
10

分治把一个大问题拆成结构相同的小问题，分别解决后再组合结果；归并排序和快速排序展示了两种不同的组合方式。

本课先记住

核心结论

分治先把一个大问题分成定义相同、规模更小的子问题，分别解决后再组合子结果；每个子问题都必须严格变小。

常用语法

闭区间只剩一个元素时直接返回；右半段从 middle + 1 开始，避免与左半段重叠。

if (left == right) {
    return numbers[left];
}
int middle = left + (right - left) / 2;
最小示例

把 [7, -2, 5, 4] 分成左右两段：左段和为 5，右段和为 9，组合后得到 14。

[7, -2] -> 5
[5, 4] -> 9
5 + 9 -> 14
关键易错点
  • 不能漏掉递归出口
  • 两个子区间不能重叠或漏元素
  • 区间和要用 long long
  • 用了分治不表示程序一定更快。

知识范围与官方定位

五级需要理解分治的分解、解决、合并过程，并掌握归并排序与快速排序的递归终止条件、递归树、划分或合并过程、复杂度及稳定性特点；还要理解归并统计逆序对的基本入口。

本页先建立共同基础并比较各方法；完整过程、C++ 写法与复杂度请进入对应子知识点学习。

问题和范围

要解决的问题

现在要计算一组整数的总和。用循环从左到右累加当然能做对，但它看不出一个大问题怎样交给同一个函数去解决更小的同类问题。

本课先用区间求和看清分治的共同骨架：分解、解决、组合。这个例子故意很简单，重点不是用递归打败循环，而是让每次调用的范围、返回值和组合位置都能看见。

归并排序和快速排序的具体合并、划分与完整代码仍放在两个子知识点中；父页只建立它们共同需要的分治思考方式。

本课范围

  • 本教学程序支持 1 ≤ n ≤ 100000，每个整数满足 -1000000000 ≤ numbers[i] ≤ 1000000000。
  • 数组使用 0 下标，整个数组对应闭区间 [0, n - 1]；容量为 100005，最大合法下标 99999 不会越界。
  • 总和的最大绝对值是 100000 × 1000000000 = 100000000000000，也就是 10^14，超过常见 32 位 int，因此数组元素、子结果和返回值都使用 long long。
  • 本课只处理非空区间，不展开空数组；也不在父页重讲归并排序、快速排序和逆序对的具体实现。

共同基础

  • 递归函数必须先写清最小问题的终止条件。
  • 每次递归调用都要处理严格更小的区间。
  • 排序正确性来自子区间处理正确，以及合并或划分规则保持正确。
  • 递归树中，归并排序每层处理元素总数都是 n，约有 log₂n 层；快速排序的树高取决于每次划分是否均衡。
  • 合并两个有序段时，若左段当前值大于右段当前值，那么左段当前值及其后面的数都与这个右段值构成逆序对，可一次统计。
  • 除了比较时间，还要检查临时数组和递归栈占用。

方法对比

归并排序

主要用途：先分别排好左右两段，再合并两个有序区间。

使用提醒：稳定，时间 O(n log n)，需要 O(n) 临时数组。

快速排序

主要用途：先按基准划分，再递归处理左右两侧。

使用提醒：通常很快但不稳定，最坏时间可能达到 O(n²)。

算法怎样形成

先观察主样例 7、-2、5、4。我们给每个调用同一个任务：rangeSum(left, right) 返回闭区间 [left, right] 中所有元素的和。只要子调用仍在完成这件事，得到的答案就能按同一种方式组合。

  1. 分解：最外层区间是 [0, 3]。中点 middle = 1，把它分为 [0, 1] 和 [2, 3]。两段相邻、不重叠，合起来又恰好覆盖 [0, 3]。
  2. 解决：两个子区间仍然在求“闭区间内所有元素的和”，所以继续调用 rangeSum。遇到 [0, 0] 这样的单元素区间时，不必再分，直接返回这个元素。
  3. 组合：[0, 1] 返回 7 + (-2) = 5，[2, 3] 返回 5 + 4 = 9。原区间的每个元素恰好属于其中一段，所以 5 + 9 = 14 就是 [0, 3] 的答案。
  4. 严格缩小：当 left < right 时，middle 一定满足 left ≤ middle < right。因此 [left, middle] 和 [middle + 1, right] 都比原区间短，递归最终一定到达 left == right。
  5. 适用判断：只有当大问题能拆成定义相同的小问题，而且子结果能可靠地组合成原答案时，分治才提供了清楚的结构。若拆分后仍要重复完成同样的大量工作，就不能只因“用了递归”断言它更快。

自然语言步骤

  1. 读入 n 个整数，保存在 numbers[0] 到 numbers[n - 1]，然后调用 rangeSum(0, n - 1)。
  2. 进入 rangeSum(left, right) 后，先检查 left == right。若成立，当前区间只有一个元素，直接返回 numbers[left]。
  3. 若区间中至少有两个元素，计算 middle = left + (right - left) / 2。
  4. 先调用 rangeSum(left, middle)，把返回值保存为 leftSum。
  5. 再调用 rangeSum(middle + 1, right)，把返回值保存为 rightSum。
  6. 返回 leftSum + rightSum。这个返回值就是当前闭区间的元素和。
  7. 最外层调用返回后，main() 输出得到的总和，程序结束。

完整程序

用分治计算整个数组的和

下面是本页唯一一份完整程序。它只使用普通全局数组和已经解释过的闭区间递归；D1 保证 n 至少为 1，因此初始调用 [0, n - 1] 一定非空。

示例输入

4
7 -2 5 4

示例输出

14

样例说明：rangeSum(0, 1) 得到 5，rangeSum(2, 3) 得到 9；最外层把两个子结果相加，输出 14。

#include <bits/stdc++.h>
using namespace std;

const int MAX_N = 100005;

long long numbers[MAX_N];

long long rangeSum(int left, int right) {
  if (left == right) {
      return numbers[left];
  }

  int middle = left + (right - left) / 2;
  long long leftSum = rangeSum(left, middle);
  long long rightSum = rangeSum(middle + 1, right);
  return leftSum + rightSum;
}

int main() {
  int n;
  cin >> n;

  for (int i = 0; i < n; i++) {
      cin >> numbers[i];
  }

  cout << rangeSum(0, n - 1) << '\n';
  return 0;
}

复杂度

这份区间求和程序会到达每个元素一次。分治在这里帮助我们组织问题，却没有减少必须读取的元素，因此它和普通循环求和的时间复杂度都是 O(n)；递归调用还会带来额外开销，分治不自动更快。

时间与空间复杂度
项目复杂度说明
分治求和时间O(n)n 个单元素区间都要被访问；整棵调用树共有 2n - 1 个调用，仍是线性数量。
普通循环求和时间O(n)循环也必须读取 n 个元素，所以本例不能靠分治降低时间复杂度。
数组存储O(n)numbers 保存全部输入；最大合法下标是 99999。
额外递归栈O(log n)每次把区间大约分成两半，从 100000 个元素缩到 1 个元素只需对数层调用。

常见错误

漏掉单元素出口

long long rangeSum(int left, int right) {
  int middle = left + (right - left) / 2;
  return rangeSum(left, middle) + rangeSum(middle + 1, right);
}

为什么错：区间缩到 [0, 0] 后还会继续计算 middle 并调用自己，递归无法在最小问题处停止。

怎样改：把 left == right 的判断放在分解之前，并直接返回 numbers[left]。

右半段仍从 middle 开始

long long rightSum = rangeSum(middle, right);

为什么错：在 [0, 1] 中 middle = 0，错误右段仍是 [0, 1]，与原区间一样大；中点还与左段重叠。

怎样改：右半段固定写成 [middle + 1, right]，这样两段不重叠且都严格缩小。

调用了两边，却没有组合返回值

rangeSum(left, middle);
rangeSum(middle + 1, right);
return 0;

为什么错：两个子调用确实算出了答案，但返回值没有保存和相加，当前区间最后只能错误地返回 0。

怎样改：分别保存 leftSum、rightSum，再返回 leftSum + rightSum。

用 int 保存区间和

int leftSum = rangeSum(left, middle);
int rightSum = rangeSum(middle + 1, right);

为什么错：D1 下最大绝对和是 10^14，远超常见 32 位 int 的可表示范围，转换后可能溢出。

怎样改：数组元素、函数返回类型、leftSum 和 rightSum 全部使用 long long。

看到递归就认为一定更快

为什么错：这份程序仍会访问全部 n 个元素，时间是 O(n)；普通循环求和也是 O(n)，递归还有调用开销。

怎样改：分别计算每层做了多少工作、总共有多少状态，再判断复杂度；不要把“用了分治”当作速度证明。

练习与自检

练习一：手算分解与返回

对数组 [3, 1, 4, 2] 调用 rangeSum(0, 3)。写出两个长度为 2 的子区间各自返回什么，以及根区间最后返回什么。

提示：先写四个单元素返回值，再从较小区间向上组合。

练习二：检查会卡住的边界

有人把右子区间写成 [middle, right]。请代入 [0, 1]，说明哪次调用没有缩小，并写出正确右边界。

提示：先算 middle，再比较错误子区间与原区间。

练习三：迁移到区间最大值

若任务改为求一个闭区间中的最大值，三个分治阶段分别做什么？它会不会因此比一次线性扫描更低阶？

提示：单元素答案就是该元素；组合两个子结果时只需保留较大者。

练习四：判断整数类型

当 n = 100000 且每个数都是 1000000000 时，总和是多少？说明为什么 int 不够。

提示：先计算 n 与单个数的乘积，再与常见 32 位 int 上限约 2.1 × 10^9 比较。
