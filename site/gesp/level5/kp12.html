复杂度与数据范围

12
GESP 5级知识字典 · 知识点 12

根据数据范围判断算法是否可行，选择合适复杂度。

检索词：数据范围复杂度判断

本课先记住

核心结论

先确定输入规模 n 和关键操作，数出操作次数怎样随 n 增长，再用 O 表示增长数量级；最后还要检查额外空间和数据范围。

常用语法

顺序段次数相加，独立嵌套次数相乘；规模每轮减半时，轮数通常是对数级。

while (remaining > 1) {
    remaining /= 2;
}
最小示例

n=8 时，每轮除以 2 的轨迹是 8→4→2→1，共执行 3 轮，因此是 O(log n)。

8 -> 4 -> 2 -> 1
3 rounds
关键易错点
  • 不能按代码行数猜复杂度
  • 前后相邻的循环次数相加，不是相乘
  • O 表示增长趋势，不是精确秒数
  • 只看时间而漏掉数组和递归栈仍可能失败

从同样很快到差距巨大

输入规模只有 n=8 时，扫描一次、两层循环甚至三层循环都能很快结束。可是当 n 增长到 100000，不同写法的工作量会拉开巨大差距：一次扫描约十万次，两层各跑 n 次的循环却会达到一百亿次。

因此，判断程序能不能完成，不能只看代码短不短，也不能只在自己的电脑上试一个小数据。本课只新增三项能力：

  1. **K1：**确定输入规模 n 和关键操作，先数实际次数，再写复杂度。
  2. **K2：**根据顺序、嵌套、减半和二叉分支，判断常见增长数量级。
  3. **K3：**把时间、额外空间和数据范围放在一起检查。

循环、数组、函数、递归、二分和分治都已经学过。本课只借这些已学结构观察工作量，不重新讲算法本身，也不展开大 O 的严格数学证明、主定理、摊还分析、NP 问题或六级以上内容。

现行官方材料有两个呈现层级：总表列出“多项式、指数、对数复杂度”，另一处详述与知识块表重点展开多项式和对数。本站按两处内容的并集讲清三类增长，不把指数内容扩大成新的算法教学；其中 O(1) 用作比较的起点，O(n log n) 用来连接已经学过的分治过程。

01 输入规模与基本操作

K1：先确定 n，再选择要数的操作

输入规模是会随输入变大的数量，通常记作 n。处理长度为 n 的数组时，n 是元素个数，不是数组中某个元素的数值。

接着选择最能代表工作量、并且会重复执行的关键操作，例如一次比较、一次赋值或一次递归分支。代码行数不能代替执行次数：循环体里只有一行，这一行仍可能执行 n 次、n^2 次，甚至更多。

下面的局部代码把 count++ 当作关键操作：

long long count = 0;for (int i = 0; i < n; i++) {    count++;}

循环变量依次是 0, 1, ..., n - 1，所以关键操作执行 n 次。我们先得到“实际次数是 n”，再说它的时间复杂度是 O(n)。

从次数表达式得到 O

大 O 记录的是：n 继续增长时，工作量属于哪一种增长数量级。化简时保留增长最快的部分，并忽略固定倍数。

实际次数表达式 观察 数量级
5 不随 n 改变 O(1)
3n + 5 主导增长的是 n O(n)
n^2 + 2n n 很大时，n^2 增长更快 O(n^2)

这不表示常数永远不重要，也不表示 O(n) 一定在任意小数据上比 O(n^2) 快。它只让我们比较输入继续变大时的增长趋势，不是某台机器上的精确秒数，更不是一定通过的保证。

02 从程序结构判断增长

K2：顺序相加，独立嵌套相乘

两个循环前后执行时，先做 n 次，再做 n 次，总次数是 n + n = 2n，化简为 O(n)：

for (int i = 0; i < n; i++) {    count++;}for (int j = 0; j < n; j++) {    count++;}

如果第二个循环在第一个循环里面，并且每一层都独立跑满 n 次，才是 n * n = n^2。三层独立循环同理是 n^3。所以不能看见两个或三个 for 就直接相乘，必须先看它们是前后关系还是包含关系，以及每层实际循环多少次。

每轮减半：O(log n)

当剩余规模每轮除以 2，只需很少的轮数就会缩到 1。正式样例取 n=8，最终程序真实运行的减半过程如下。

判断 判断前 remaining remaining > 1 本轮动作 累计 logarithmic
第 1 次 8 成立 remaining = 8 / 2 = 4 1
第 2 次 4 成立 remaining = 4 / 2 = 2 2
第 3 次 2 成立 remaining = 2 / 2 = 1 3
停止判断 1 第一次不成立 不再执行循环体 3

轨迹是 8 -> 4 -> 2 -> 1，共执行 3 轮。因为 2^3 = 8，这种每轮按固定比例缩小的轮数随 n 呈对数增长，记作 O(log n)。在复杂度中，若底数是固定常数，通常不必专门写底数。

如果每个减半层还完整扫描 n 项，总次数就是“约 log n 层 × 每层约 n 次”，得到 O(n log n)。不能因为外层会减半，就漏掉每层的线性工作。

二叉分支：O(2^n)

当 n 个位置都各有两种选择时，完整方案数为 2^n。最终程序中的递归在深度达到 n 时返回 1，表示找到一个叶子方案；否则进入两个 depth + 1 分支，并把两边的叶子数相加。

n=8 时叶子数是 2^8 = 256。这里的 256 只表示叶子数，不是整棵递归树的总调用数；总调用数虽然不是恰好 2^n，增长数量级仍是 O(2^n)。如果还要在每个叶子输出最多 n 项内容，输出量可能达到 O(n * 2^n)。

03 七种次数放到同一个输入中

下面七段结构彼此独立，每一段只数自己的关键操作。它们是一个“操作次数实验室”，不能把七项相加后说成某个真实解法同时具有七种复杂度。

增长数量级 n=8 时的真实结构 精确次数
O(1) 固定执行一次 1
O(log n) 8 -> 4 -> 2 -> 1 3
O(n) 扫描 8 项 8
O(n log n) 3 层，每层扫描 8 项 24
O(n^2) 两层各执行 8 次 64
O(n^3) 三层各执行 8 次 512
O(2^n) 8 个位置各有两种选择，统计叶子 256

这个表说明三种不同的判断方法：前后执行先相加，独立嵌套才相乘，每轮减半先数层数。七项按常见增长速度排列，但这仍是“大数据增长趋势”的顺序，不保证任意小数据的真实耗时严格照此排序。

04 用程序真实计数

先建立每一段自己的计数变量。减半段用 remaining 保存当前剩余规模；每完成一轮，计数加 1，再把规模除以 2。指数段只统计递归叶子，避免把叶子数和总调用数混在一起。

下面的教学程序只接受 1 <= n <= 12。上界设得小，是为了让三层循环和二叉递归都能在实验中安全、快速地真实执行；这不表示实际题目的 n 只能到 12。计数统一使用 long long。

完成程序

#include <bits/stdc++.h>using namespace std;
long long countExponentialLeaves(int depth, int n) {    if (depth == n) {        return 1;    }    return countExponentialLeaves(depth + 1, n) + countExponentialLeaves(depth + 1, n);}
int main() {    int n;    cin >> n;    if (n < 1 || n > 12) {        cout << "invalid\n";        return 0;    }
    long long constantCount = 0;    constantCount++;
    long long logarithmicCount = 0;    int remaining = n;    while (remaining > 1) {        remaining /= 2;        logarithmicCount++;    }
    long long linearCount = 0;    for (int i = 0; i < n; i++) {        linearCount++;    }
    long long linearLogCount = 0;    remaining = n;    while (remaining > 1) {        for (int i = 0; i < n; i++) {            linearLogCount++;        }        remaining /= 2;    }
    long long quadraticCount = 0;    for (int i = 0; i < n; i++) {        for (int j = 0; j < n; j++) {            quadraticCount++;        }    }
    long long cubicCount = 0;    for (int i = 0; i < n; i++) {        for (int j = 0; j < n; j++) {            for (int k = 0; k < n; k++) {                cubicCount++;            }        }    }
    long long exponentialCount = countExponentialLeaves(0, n);
    cout << "constant " << constantCount << '\n';    cout << "logarithmic " << logarithmicCount << '\n';    cout << "linear " << linearCount << '\n';    cout << "linear_log " << linearLogCount << '\n';    cout << "quadratic " << quadraticCount << '\n';    cout << "cubic " << cubicCount << '\n';    cout << "exponential " << exponentialCount << '\n';    return 0;}

样例输入

8

样例输出

constant 1logarithmic 3linear 8linear_log 24quadratic 64cubic 512exponential 256

样例输入、减半过程表、七项对比表和程序输出使用同一个 n=8。程序整体顺序执行七段，所以若把它当成一个程序分析，运行量由增长最快的指数计数段主导；本课观察的是每一段各自的增长方式。

05 时间、空间与数据范围

K3：时间和额外空间分开检查

时间复杂度看累计执行量怎样增长。额外空间复杂度看程序为了处理问题又使用了多少存储，例如辅助数组和同时存在的递归调用层。输入数组本身是否计入空间，要看题目采用的口径；无论采用哪种口径，都应把输入存储和新增辅助空间分开说清。

递归不是“调用过多少次，就同时占多少层栈”。栈空间看的是某一时刻最多有多少层调用没有返回。每层还会保存参数、局部变量和返回位置，所以真实字节数受编译器、平台与函数内容影响；如果最大同时调用深度随 n 线性增长，栈空间数量级通常是 O(n)。

用 n=100000 做粗略判断

方案 关键操作的粗略量级 判断
O(n) 约 100000 次 十万级
O(n log n) log2(100000) 约为 17，因此不到 2000000 次 约两百万级以内
O(n^2) 100000 * 100000 = 10000000000 次 一百亿级，通常明显不可行

这些数只用于比较数量级，不能据此承诺固定运行秒数。还要看测试组数、每次关键操作的常数、时间限制以及实际实现。

把数组换算成近似字节数

在常见 GCC/OJ 环境中，int 通常占 4 字节：

  • int a[100000] 约占 100000 * 4 = 400000 字节，约 390.6 KiB；
  • int grid[1000][1000] 约占 1000 * 1000 * 4 = 4000000 字节，约 3.81 MiB。

这只是常见环境的估算，实际大小以编译器、平台和评测环境为准。还要另算其他数组、递归栈和对象开销，并检查计数或乘法结果是否会超出整数范围。

统一的判断顺序是：先看最大输入规模和测试组数，再估关键操作次数；随后估主要数组、递归栈和整数范围。三者都符合题目限制，方案才有通过的可能。

常见错误怎样改正

错误判断 最早原因与实际后果 修正方法 重新检查
“代码只有几行，所以是 O(1)” 把源代码行数当成运行次数，漏掉循环和递归的重复执行 先确定 n，再挑关键操作并写出实际次数 单循环的 count++ 应数出 n 次
“两个 for 一定是 O(n^2)” 没看循环的包含关系，前后两个循环被错误相乘 前后执行次数相加；内层每轮独立跑满时才相乘 两个相邻 n 次循环应得到 2n -> O(n)
“循环体只有一次比较，所以二分是 O(1)” 只数一轮，漏掉规模反复减半的轮数 列出完整减半轨迹，并保留第一次条件不成立 8 -> 4 -> 2 -> 1 应记录 3 轮和停止判断
“2n 和 2^n 都有 2，增长差不多” 没分清固定倍数与指数位置 代入相邻的 n 比较：2n 每次加 2，2^n 每次翻倍 n=8 时分别是 16 和 256
“时间能过，内存一定能过” 忽略辅助数组和最大递归深度，可能超内存或爆栈 分开估算时间、数组字节数和递归栈深度 写出主要数组元素数 × 单个元素字节数，并说明最大同时递归层数
“写出 O(n log n) 就能保证通过” 把增长数量级当成精确秒数，漏掉测试组数、常数和限制 用最大数据粗算次数，再核对时间、空间和整数范围 结论中必须带数据范围和评测限制，而不是只写一个 O 符号

练习与答案

引导练习：顺序还是相乘

有两个前后相邻的循环，每个都执行 n 次。写出总次数和复杂度。

**答案：**总次数是 n + n = 2n，忽略固定倍数后为 O(n)。它们没有相互包含，所以不能写成 n * n。

独立练习：改变内层结构

先判断外层、内层都独立执行 n 次的两层循环；再把内层改成每轮把 remaining 除以 2。

**答案：**第一种每个外层轮次都完成 n 次内层操作，总量为 n * n = n^2，即 O(n^2)。第二种外层有 n 轮，每轮内层约执行 log n 次，总量为 n * log n，即 O(n log n)。

迁移练习：为十万规模选方案

当 n=100000 时，在 O(n log n) 和 O(n^2) 两个方案中选择更可行的一项，并给出数量比较。

**答案：**优先选择 O(n log n)：按 log2(100000) 约为 17 粗算，不到两百万次；O(n^2) 达到 10000000000 次，即一百亿级。最终仍需结合实际限制测试。

空间练习：数量级和 MiB 都要会说

常见 GCC/OJ 环境中按一个 int 为 4 字节估算，int a[200000] 约占多少字节、多少 MiB？数组空间的数量级是什么？

**答案：**约 200000 * 4 = 800000 字节，约 0.76 MiB；元素个数随 n 线性增长时，数组空间是 O(n)。O(n) 回答增长趋势，0.76 MiB 回答这个具体规模下的近似占用，两者不能互相替代。
