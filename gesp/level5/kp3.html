素数筛法

03
GESP 5级知识字典 · 知识点 03

掌握埃氏筛与线性筛，实现素数表查询。

检索词：埃氏筛线性筛

当题目要反复判断一个范围内的数是否为素数时，筛法会把逐个试除改成一次预处理、随后快速查询。筛表时先证明哪些数是合数，再把结果保存在标记数组中。以后每次查询只读一个数组位置，不必重新寻找因数。

本课先记住

核心结论

查询很多次时，先用筛法建立 0 到 n 的素数表，再用 isPrime[x] 直接回答；埃氏筛和线性筛得到同一类结果，只是证明合数的方式不同。

常用语法

预处理函数只调用一次，后面的每次查询只读取对应下标。

buildPrimeTable(n);
if (isPrime[x]) {
    cout << "YES";
}
最小示例

筛到 16 后，2 和 7 的标记为真，0、1、9、16 的标记为假。

isPrime[2] = true
isPrime[9] = false
关键易错点
  • 0 和 1 必须设为非素数
  • 数组要覆盖下标 n
  • 先判断 p <= n / p 再计算 p * p
  • 不要混淆 isPrime 与 isComposite 的真假含义。

知识范围与官方定位

五级需要理解并会使用埃拉托斯特尼筛法与线性筛：前者批量标记素数的倍数，后者借助素数表和最小质因数让每个合数只被筛一次。

本页先建立共同基础并比较各方法；完整过程、C++ 写法与复杂度请进入对应子知识点学习。

问题和范围

要解决的问题

如果只有一个数 x，可以尝试从 2 开始寻找它的因数。但当 q 个问题都在问 0 到 n 中的数时，每次重新试除会反复做相同工作：例如判断 9 和 15 时，都会再次检查它们是否能被 3 整除。

更合适的目标是先回答一个共同问题：0 到 n 中每个数是不是素数？我们把全部结果保存为 isPrime[0..n]，以后查询 x 时只读 isPrime[x]，一次预处理就能服务后面的所有问题。

本页用埃氏筛完成一份最小程序，让你看清“建表一次，查询多次”的共同流程，并比较何时继续学习埃氏筛或线性筛。两种方法各自的完整推导、证明和实现仍在对应子知识点中。

本课范围

  • 本教学程序先输入 n、q，再输入 q 个查询值 x；支持 0 ≤ n ≤ 1000000、0 ≤ q ≤ 100000，并保证每个查询满足 0 ≤ x ≤ n。
  • 使用全局 bool isPrime[1000001]，合法下标是 0 到 1000000。n = 0 时只访问 isPrime[0]；只有 n ≥ 1 时才访问 isPrime[1]。
  • 常见 GCC/OJ 环境中 bool 通常占 1 字节，这张表约占 0.95 MiB，实际大小仍以编译器和平台为准。程序最多输出 q 行 YES 或 NO，连同换行约不超过 400000 个字符。
  • 在 D1 范围内 p、p * p 和 multiple + p 都能放入 int。程序仍先判断 p <= n / p，再计算 p * p，避免把不安全的乘法条件带到更大范围。
  • 父页只建立共同结果表、查询闭环和方法选择；埃氏筛子页负责 p * p 的完整形成与标记证明，线性筛子页负责素数表、最小质因数唯一标记和 break 的完整推导。

共同基础

  • 素数是大于 1 且只有 1 和自身两个正因数的整数，因此 0 和 1 都不是素数。
  • 筛法先建立 isPrime 等标记数组，再按从小到大的顺序排除合数。
  • 前缀计数 cnt[i] 表示 1 到 i 中的素数个数；令 cnt[0] = 0，并递推 cnt[i] = cnt[i - 1] + (isPrime[i] ? 1 : 0)。
  • 区间 [l, r] 中的素数个数是 cnt[r] - cnt[l - 1]；这里要求 1 <= l <= r，l = 1 时会使用 cnt[0]。
  • 数组下标必须覆盖 0 到 n。常见 GCC/OJ 环境中 bool 通常占 1 字节，bool isPrime[1000001] 约占 0.95 MiB；若再用两个 int 数组保存最小质因数和素数表，约再占 7.63 MiB。实际大小仍以编译器和平台为准。
  • 标记 p 的倍数时要防止乘法越界：可先保证 p <= n / p，再计算 p * p；线性筛也应先判断 p > n / i。

方法对比

埃拉托斯特尼筛法

主要用途：用每个已确认素数批量标记它的倍数。

使用提醒：写法直观，时间复杂度为 O(n log log n)。

线性筛

主要用途：维护素数表，并用最小质因数唯一地筛掉每个合数。

使用提醒：必须理解整除后 break 的原因，时间复杂度为 O(n)。

算法怎样形成

以 n = 16、连续查询 0、1、2、7、9、16 为例。逐个试除能回答每一问，却会一遍遍寻找因数；六次查询真正共享的是同一份“0 到 16 哪些数是素数”的结果。

  1. 先把重复工作移到查询前：只要预先确定 0 到 n 中每个数的真假，后面无论查询多少次，都不需要再次寻找因数。这就是“一次预处理，多次查询”。
  2. 用 isPrime[x] 保存共同结果最直接：true 表示 x 筛完后仍可能是素数，false 表示 x 已确定不是素数。数组必须覆盖 0 到 n，因为查询值可能正好是 0 或 n。
  3. 初始化不能只依赖全局数组原来的 false：建表开始时先把 0 到 n 全设为 true，再明确把 0 设为 false；只有 n ≥ 1 时再把 1 设为 false。这样 0 和 1 的数学边界与数组访问边界同时正确。
  4. 接下来需要一种方法证明合数。埃氏筛从一个已确认素数出发，批量标记它的倍数；线性筛维护素数表，让每个合数只由最小质因数筛掉一次。两者最终都建立能直接查询的素数标记表。
  5. 本页的最小程序选择埃氏筛演示共同流程：p = 2 时标记 4、6、8、10、12、14、16；p = 3 时检查 9、12、15。为什么从 p * p 开始以及更小倍数为何已处理，留到埃氏筛子页完整推导。
  6. 安全停止也属于共同边界意识：先检查 p <= n / p，条件成立后才计算 p * p。主样例到 p = 5 时，5 <= 16 / 5 不成立，筛表停止；不会先计算一个未经保护的平方条件。
  7. 查询阶段不再改变表：依次读取 x，isPrime[x] 为 true 输出 YES，否则输出 NO。主样例最终为真的下标是 2、3、5、7、11、13，所以六次查询得到 NO、NO、YES、YES、NO、NO。
  8. 选择方法时看任务需要：先求稳、写法直观，进入埃氏筛；要求线性预处理或后续要使用素数表，进入线性筛。父页只帮助选择，不把两个子页的循环和证明复制一遍。
  9. 筛完还可以做一次简短应用：令 cnt[0] = 0，cnt[i] = cnt[i - 1] + (isPrime[i] ? 1 : 0)。当 1 ≤ l ≤ r 时，[l, r] 的素数个数是 cnt[r] - cnt[l - 1]；l = 1 时正好读取 cnt[0]。

自然语言步骤

  1. 读入范围上界 n 和查询数量 q，确认每个查询值 x 都在 0 到 n 内。
  2. 调用 buildPrimeTable(n) 一次。先把 isPrime[0..n] 全部设为 true，再令 isPrime[0] = false；若 n ≥ 1，再令 isPrime[1] = false。
  3. 令 p = 2。每轮先判断 p <= n / p；若不成立，说明不再需要用新的 p 标记倍数，筛表结束。
  4. 若 isPrime[p] 为 true，就从 p * p 开始，每次增加 p，把不超过 n 的倍数设为 false；若 isPrime[p] 已为 false，本轮跳过标记。
  5. 让 p 增加 1，回到安全条件继续检查。筛表结束后，isPrime[x] 就是查询 x 的固定答案。
  6. 回到 main()，按输入顺序处理 q 次查询。每次读入 x，只检查 isPrime[x]：为 true 输出 YES，否则输出 NO。
  7. 若题目改问区间素数个数，可以在筛表后另建 cnt：从 1 到 n 递推一次，再用 cnt[r] - cnt[l - 1] 回答；这不是本页 C1 的第二个目标。
  8. 需要完整理解批量标记及 p * p 时先学埃氏筛；需要理解素数表、最小质因数和 break 时再学线性筛。

完整程序

共同模型的最小完整示例：建表一次，查询多次

下面是本页唯一一份完整 C++14 程序。它用最小埃氏筛实现 buildPrimeTable(n)，只为闭合共享预处理与查询流程；线性筛的素数表、最小质因数和 break 不在这里实现。

示例输入

16 6
0 1 2 7 9 16

示例输出

NO
NO
YES
YES
NO
NO

样例说明：筛表完成后，0、1、9、16 对应 false，2、7 对应 true；0 到 16 的素数是 2、3、5、7、11、13，因此按查询顺序输出六行结果。

#include <bits/stdc++.h>
using namespace std;

const int MAX_N = 1000000;
bool isPrime[MAX_N + 1];

void buildPrimeTable(int n) {
  for (int value = 0; value <= n; value++) {
      isPrime[value] = true;
  }
  isPrime[0] = false;
  if (n >= 1) {
      isPrime[1] = false;
  }

  int p = 2;
  while (p <= n / p) {
      if (isPrime[p]) {
          for (int multiple = p * p; multiple <= n; multiple += p) {
              isPrime[multiple] = false;
          }
      }
      p++;
  }
}

int main() {
  int n, q;
  cin >> n >> q;

  buildPrimeTable(n);

  for (int queryIndex = 1; queryIndex <= q; queryIndex++) {
      int x;
      cin >> x;
      if (isPrime[x]) {
          cout << "YES\n";
      } else {
          cout << "NO\n";
      }
  }

  return 0;
}

复杂度

要把“预处理”和“查询”分开计算。C1 先建立整张表，再回答 q 次查询；查询再多，也不会重新执行筛法。

时间与空间复杂度
项目复杂度说明
初始化标记数组O(n)把 isPrime[0..n] 写入一次；这部分包含在整个预处理量级中。
C1 埃氏筛预处理O(n log log n)按素数批量标记倍数；这是本页最小程序采用的方法。
单次点查询O(1)只读取 isPrime[x] 并输出一行。
q 次点查询O(q)每个查询只做常数次操作。
C1 总时间O(n log log n + q)一次埃氏筛预处理加 q 次查询。
线性筛方案总时间O(n + q)线性筛预处理为 O(n)，之后同样每次 O(1) 查询；线性筛维护素数表，但不要求必须另存 minPrime 数组。
标记表空间O(n)isPrime 有 n + 1 个有效位置；固定上限数组约 0.95 MiB，实际以平台为准。
区间计数扩展预处理 O(n)，查询 O(1)筛表后再建 cnt；每个区间用 cnt[r] - cnt[l - 1]。

常见错误

每次查询都重新试除

为什么错：可观察的症状是 q 增大后程序重复检查相同因数，查询时间随每个 x 的大小继续增加；根因是没有利用所有查询共享同一范围。

怎样改：先调用 buildPrimeTable(n) 一次，再让每次查询只读 isPrime[x]。修正后用同一个 x 连续查询多次，确认只有一次筛表而输出每次都相同。

把 0 或 1 留成 true

isPrime[0] = true;
isPrime[1] = true;

为什么错：可观察的症状是查询 0 或 1 时输出 YES；根因是“没有被倍数循环标记”不等于“它是素数”，素数定义要求大于 1。

怎样改：始终令 isPrime[0] = false；只有 n ≥ 1 时再令 isPrime[1] = false。修正后分别运行 n = 0 和 n = 1 的端点查询，都应输出 NO。

数组没有给下标 n 留位置

bool isPrime[1000000];

为什么错：可观察的症状是 n = 1000000 或查询 x = n 时越界；根因是 0 到 n 一共有 n + 1 个下标。

怎样改：按 D1 使用 bool isPrime[1000001]，最大合法下标正好是 1000000。修正后重测 n = 1000000 且查询两个端点 0 和 n。

先计算平方再判断范围

while (p * p <= n) {

为什么错：在本课 D1 内通常看不出错误，但放大范围后 p * p 可能先发生 int 溢出，条件结果就不可靠；根因是保护判断发生得太晚。

怎样改：先写 p <= n / p，只有条件成立后才在循环体中计算 p * p。修正后检查主样例在 p = 5 时因 5 <= 16 / 5 为假而停止。

混淆 isPrime 与 isComposite

if (isPrime[x]) {
  cout << "NO";
}

为什么错：可观察的症状是素数 2 输出 NO、合数 9 反而输出 YES；根因是把“为真表示素数”和“为真表示合数”两套命名混在一起。

怎样改：本页统一规定 isPrime[x] 为 true 才输出 YES；若改用 isComposite，就要同步反转初始化、标记和查询判断。修正后用 2 与 9 成对复测。

没有把 0 到 n 初始化为 true

bool isPrime[MAX_N + 1];
isPrime[0] = false;

为什么错：可观察的症状是几乎所有查询都输出 NO；根因是全局 bool 数组初始为 false，而筛法需要先把 2 到 n 看作候选素数。

怎样改：buildPrimeTable 开始先逐个把 isPrime[0..n] 设为 true，再覆盖 0 和 1。修正后运行 n = 2，查询 0、1、2，应依次得到 NO、NO、YES。

把一次查询也说成筛法复杂度

为什么错：可观察的症状是把每次 isPrime[x] 查询误写成 O(n log log n)，或只写 O(1) 却漏掉建表；根因是没有区分预处理、单次查询和总流程。

怎样改：分别记录 C1 预处理 O(n log log n)、单次查询 O(1)、q 次查询 O(q)、总时间 O(n log log n + q)。修正后用 q = 0 与 q = 100000 对照哪些步骤仍会执行。

在父页同时背两份完整筛法代码

为什么错：可观察的症状是还没有看清共同结果表，就要同时处理两套循环、两套证明和两个停止条件；根因是把父页的模型选择职责与子页的完整实现职责混在一起。

怎样改：父页只保留一份最小埃氏筛 C1 和准确比较；先到埃氏筛子页学完整批量标记，再到线性筛子页学最小质因数与 break。复核时确认父页只有一个 main 且没有线性筛内层循环。
