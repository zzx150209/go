递推

07
GESP 4级知识字典 · 知识点 07

确定初始状态与递推关系，按顺序计算得到结果。

检索词：初始状态递推关系

递推先给出初始状态，再用已经算出的状态推出后面的状态。遇到序列、台阶方案数或按天增长等“当前结果依赖较早结果”的问题时，要先确定“先算谁、依赖谁”。

本课先记住

核心结论

递推必须先定义状态，再找初值和从小状态到大状态的关系；公式中的依赖项必须先算好。

常用语法

ways[0] = 1; // 到第 0 级视为有一种“什么也不做”的方案
ways[1] = 1; // 到第 1 级只有走一步这一种方案
for (int i = 2; i <= n; i++) { // 从第一个能由前两项推出的状态开始
    ways[i] = ways[i - 1] + ways[i - 2]; // 按最后一步的两种来源合并方案
} // 完成下标 2 到 n 的递推

最小示例

sequence[1] = 2; // 给出不能继续向前推的首项
for (int i = 2; i <= n; i++) { // 按从小到大的依赖顺序计算
    sequence[i] = sequence[i - 1] + 3; // 用已知前一项推出当前项
} // 完成第 2 项到第 n 项

关键易错点

  • 状态含义没有写清就直接套公式
  • 初始值与递推式不一致
  • 计算当前状态时依赖的前项还没有得到

这节课要会什么

学完后，你能用“状态含义—初始状态—最后一步—递推式—计算顺序”五步独立写出简单递推。

从这个场景开始

爬到第 i 级台阶的最后一步不可能凭空出现：要么从 i-1 走 1 级，要么从 i-2 走 2 级。把所有方案按最后一步分类，就能从已经算出的较小答案推出当前答案。

知识范围与官方定位

四级需要根据问题确定递推状态、初始条件和递推关系，按依赖顺序计算，能够处理斐波那契型、台阶型等基础递推。

算法是怎样形成的

  1. 定义状态：ways[i] 表示“恰好到达第 i 级台阶”的方案数，不能只写成含义模糊的“第 i 项”。
  2. 确定初始状态：到第 1 级只有 1 种走法，到第 2 级有 1+1 和 2 两种走法，所以 ways[1]=1、ways[2]=2。
  3. 分析最后一步：到 i 的方案分成“从 i-1 走 1 级”和“从 i-2 走 2 级”两类，两类不重不漏。
  4. 写出关系并确定顺序：ways[i]=ways[i-1]+ways[i-2]，因此必须从小到大计算。
  5. 最后核对边界与数值：n=1 时应直接使用初值，n=2 才第一次使用两来源公式；方案数增长很快，还要让数组容量和整数类型覆盖题目范围。

01 状态、初始值与递推关系

状态要说明下标代表什么、数值代表什么。初始值是不能再由更早状态推出的起点。

递推关系写清当前状态依赖哪些已知状态；三者缺一，递推就无法正确开始。

  • 先定义 f[i] 的含义
  • 写出所有必要初始值
  • 确认右侧状态在计算当前项前已经得到

02 斐波那契型递推

若每一项等于前两项之和，就要准备两个初始值，再从第三项开始。这里的“像斐波那契”只描述依赖形状，初值仍必须由题意确定。

数组最大合法下标要覆盖 n，数值类型也要覆盖结果。增长很快的序列即使下标不大也可能超过 int；本页完整程序把 n 限制为 90 并使用 long long。

f[1] = 1; // 设置第一项初值
f[2] = 1; // 设置第二项初值
for (int i = 3; i <= n; i++) { // 从第三项开始按依赖顺序计算
    f[i] = f[i - 1] + f[i - 2]; // 当前项等于前两项之和
} // 完成第 3 项到第 n 项

03 台阶型递推

每次走 1 级或 2 级时，到达第 i 级的最后一步只能来自 i-1 或 i-2；两类最后一步不同，互不重复，且覆盖所有方案，所以方案数相加。

把 ways[0] 定义为 1 种空方案后，ways[1]=1，统一关系可从 i=2 开始。若换一种状态定义，初值也会跟着变，不能脱离含义只背公式。

ways[0] = 1; // 空台阶只有一种不移动方案
ways[1] = 1; // 到第 1 级只有走 1 级的方案
for (int i = 2; i <= n; i++) { // 从第 2 级开始合并两个来源
    ways[i] = ways[i - 1] + ways[i - 2]; // 最后走 1 级或 2 级
} // 完成到第 n 级的全部状态

04 存储与计算顺序

数组可以保存每个状态，便于输出中间值或让后续多次使用。

循环方向必须满足依赖关系。若 f[i] 依赖 f[i-1]，通常按 i 递增计算；倒序会读取尚未得到的值。

  • 已知 f[1]=2，关系为 f[i]=f[i-1]+i
  • 必须先算 f[2]=4，才能算 f[3]=7，再算 f[4]=11
  • 第一次填表若从 i=4 倒推，会读取尚未计算的 f[3]，结果没有依据

05 常见递推序列

等差型可写成前一项加固定差；前缀和可写成前一段和加当前数；增长过程也可根据上一时刻状态推下一时刻。它们共同点是当前状态依赖已经算出的较早状态。

简单路径也能递推：只能向右或向下走时，到达 `(row, column)` 的最后一步只能来自上方或左方，所以两个来源相加。

杨辉三角的两个边界数先设为 1，内部数字由上一行左上方与右上方相加。它与网格路径都是“两来源合并”，但状态含义和边界初值不同，不能只看公式相似就混用。

下面只演示固定 2×3 小网格，结果都在 long long 范围内。更大网格的方案数增长很快，不能因为数组开得下就默认数值也不会溢出。

  • 2×3 网格第一行和第一列都只有 1 种走法
  • ways[2][2]=1+1=2，ways[2][3]=1+2=3
  • 因此从左上角到右下角共有 3 条简单路径；每个右侧状态都来自已经算出的上方和左方
long long ways[3][4] = {}; // 为 1 下标的 2 行 3 列小网格分配空间
for (int row = 1; row <= 2; row++) { // 遍历第一列的两个位置
    ways[row][1] = 1; // 第一列只能一直向下到达
} // 完成第一列边界初始化
for (int column = 1; column <= 3; column++) { // 遍历第一行的三个位置
    ways[1][column] = 1; // 第一行只能一直向右到达
} // 完成第一行边界初始化
for (int row = 2; row <= 2; row++) { // 从第 2 行开始填内部状态
    for (int column = 2; column <= 3; column++) { // 从第 2 列填到第 3 列
        ways[row][column] = ways[row - 1][column] + ways[row][column - 1]; // 合并上方和左方来源
    } // 结束当前行内部状态计算
} // 完成整个 2×3 网格递推

典型例题

计算爬到第 n 级台阶的方案数

教学程序约定 1≤n≤90，每次走 1 级或 2 级，求恰好到达第 n 级台阶的方案数。

完成程序

#include <bits/stdc++.h> // 引入本程序需要的标准库
using namespace std; // 允许直接使用 cin、cout、string 等标准库名称

int main() { // 主函数是程序的入口
    int n; // 定义目标台阶编号
    cin >> n; // 读入需要到达的台阶数
    long long ways[105] = {}; // 创建递推数组并初始化为 0
    ways[0] = 1; // 设置第 0 级为一种什么也不做的空方案
    ways[1] = 1; // 到第 1 级只有直接走 1 级这一种方案
    for (int i = 2; i <= n; i++) { // 从第一个能由前两项推出的位置开始
        ways[i] = ways[i - 1] + ways[i - 2]; // 按最后一步分类并合并两类方案
    } // 结束递推填表循环
    cout << ways[n] << '\n'; // 输出恰好到达第 n 级的方案数
    return 0; // 返回 0，表示程序正常结束
} // 结束 main 函数
示例输入
5
示例输出
8

解题与执行过程

  1. 先定义状态：ways[i] 表示恰好到达第 i 级的方案数；空台阶有一种不移动方案，所以 ways[0]=1，ways[1]=1。
  2. i=2 时按最后一步分类，ways[2]=ways[1]+ways[0]=2；这也对应 1+1 和 2 两种走法。
  3. 随后依次得到 ways[3]=3、ways[4]=5、ways[5]=8，每一步只读取已经算好的两个较小下标。
  4. i 增加到 6 时条件 6≤5 首次失败，循环停止并输出 ways[5]；n=1 时循环一开始就失败，仍能正确输出初值 1。

常见错误

初始值不足

错误写法：f[i] 依赖前两项，却只设置 f[1]。原因：计算 f[3] 时缺少 f[2]。正确写法：写全所有不能由关系式继续向前推出的初始状态。

循环起点错误

错误写法：已经给出 f[1]、f[2]，循环仍从 i = 2 开始套用前两项关系。原因：会访问 f[0] 或覆盖初值。正确写法：从第一个能由关系式推出的位置开始。

下标越界

错误写法：数组只开到 f[100]，却计算并访问 f[100]。原因：0 下标数组最后位置是 f[99]。正确写法：按最大下标多开足够空间。

计算方向违背依赖

错误写法：f[i] 依赖 f[i-1] 却从大下标向小下标首次计算。原因：右侧状态尚未得到。正确写法：先画依赖关系，再按小下标到大下标填表。
