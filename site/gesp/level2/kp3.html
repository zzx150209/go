流程图

03
GESP 2级知识字典 · 知识点 03

识别流程图符号，追踪流程走向，并在流程图与代码之间互相翻译。

检索词：符号辨认流程追踪

本课先记住

  • 核心结论： 起止框、输入输出框、处理框、判断框和箭头各有固定职责；顺序、分支、循环都要沿箭头执行，判断框必须算出真或假。
  • 常用语法： 读图时把图形职责与控制方向一一对应：平行四边形表示输入或输出，矩形表示处理，菱形表示判断，箭头表示下一步方向。
  • 最小示例： 循环追踪要记录状态变化，并补上最后一次失败判断：i = 1 且 i <= 3 为真时输出并更新；到 i = 4 时条件为假，沿出口结束。
  • 关键易错点： 不要凭感觉选分支，要代入条件；不要漏掉循环更新；不要漏写最后一次为假的判断。

知识范围与官方定位

本页对应二级大纲中的流程图：认识开始结束、输入输出、处理、判断和流程线等常用表示，能够读懂并描述顺序、分支、循环三种基本结构。

流程图用统一图形和箭头描述程序步骤。读图时沿箭头逐步追踪，遇到判断框先计算条件，再选择对应路径。

本页先认识起止、输入输出、处理、判断和流程线五类符号，再沿箭头追踪顺序、分支与循环。重点不是背图形名称，而是把每个框还原成一次真实操作，并记录判断条件的实际值、选择的出口、变量变化和最后一次失败判断。

算法是解决问题的一组有限、明确步骤；流程图是把这些步骤画出来的一种表示方法。流程图不是程序本身，也不会自动运行，但它能在写代码前暴露“漏了输入”“分支没有出口”“循环没有更新”等结构问题。

先认识符号与三种结构

画图和读图前，先把图形的固定职责说清楚：

图形 表示的步骤 读到它时做什么
圆角矩形或椭圆 开始、结束 确认流程入口或出口
平行四边形 输入、输出 读入数据或显示结果
矩形 处理 执行计算、赋值等操作
菱形 判断 算出条件真假，再选择一个出口
箭头 流程方向 决定下一步到哪个图形

三种基本结构也要先形成再看图：顺序结构按箭头依次执行，每一步通常只做一次；分支结构先判断，只选择符合条件的一条路径；循环结构在条件成立时沿返回箭头重复，条件不成立时从出口离开。

过程演示

下面十张标准图按“符号 → 顺序 → 分支 → 循环 → 嵌套 → 综合”的顺序，把前面的定义落到具体流程中。每张图都沿箭头阅读，判断框的“是/否”必须由具体条件值决定。

从符号、顺序到分支

if (x > 0) {  // 第一个判断框先检查正数路径    cout << "正数";} else if (x < 0) {  // 只有第一问为假才检查负数路径    cout << "负数";} else {  // 前两问都为假时只剩 x 等于 0    cout << "零";}

从循环追踪到嵌套与综合

if (x >= 0) {  // 判断框决定从哪一个出口离开    cout << "non-negative" << endl;} else {    cout << "negative" << endl;}

对应流程是“开始 → 输入 x → 判断 x>=0 → 两条输出路径 → 结束”。代码中的条件、真假分支和汇合位置都应在图中找到对应关系。

把具体输入代入后，路径可以这样追踪：

输入 x >= 0 选择出口 执行结果
x = 5 真 是 输出 non-negative
x = -2 假 否 输出 negative

判断框只选择其中一条路径，不会把两个输出都执行。

循环流程“i=1 → 判断 i<=3 → 输出 i → i=i+1 → 返回判断”可以写成：

int i = 1;while (i <= 3) {  // 判断框先检查当前 i 是否仍在范围内    cout << i << endl;    i++;  // 更新后返回判断，避免停在同一个状态}

也可以把初始化、条件和更新集中写成 for (int i = 1; i <= 3; i++)。互译时不是看到返回箭头就固定写某一种循环，而是确认初始化、判断、循环体和更新分别在哪里。

从代码反推流程图

先看一段“计算 1 到 n 的和”的局部代码：

int i = 1;int sum = 0;while (i <= n) {  // 判断为真才进入本轮    sum = sum + i;  // 保存加入当前 i 后的新结果    i++;}cout << sum << endl;

反推时不要一行代码随意画一个框，而要先判断每行承担什么职责：

代码部分 对应图形或箭头
i=1、sum=0 一个或两个处理框
i<=n 有“是/否”两个出口的判断框
sum=sum+i、i++ “是”出口上的处理框
循环体末尾 返回 i<=n 判断框的箭头
cout<<sum “否”出口之后的输入输出框

完整流程是“开始 → 初始化 → 判断 i<=n → 是：累加、更新、返回判断；否：输出 sum → 结束”。最后一次失败判断也必须画出来，否则“什么时候离开循环”没有图形依据。

从题意设计流程图

题目要求“输入成绩 score，达到 60 输出通过，否则输出继续练习”时，可以按五步设计：先圈出输入 score 和两种输出；再把 score>=60 写进判断菱形；给真出口连接“输出通过”，给假出口连接“输出继续练习”；让两条路径都通向结束；最后代入 59、60 两个边界值沿箭头检查。也就是先从题意提取“输入—判断—输出”，再选择图形和连接顺序，不要先画形状再猜每个框里写什么。

典型例题

**题目：**流程为“输入 x、y → 判断 x>y → 是：a=x,b=y；否：a=y,b=x → 输出 a、b”。输入 x=7、y=5 时输出什么？

推演：

  1. 输入后变量表为 x=7、y=5；
  2. 判断 7>5，结果为真；
  3. 沿“是”出口执行 a=x，得到 a=7；
  4. 再执行 b=y，得到 b=5；
  5. 两条分支汇合后输出 7 5，没有执行“否”路径。

**结论：**输出 7 5。读分支流程图必须先代入具体值判断真假，再沿唯一一条路径更新变量。

**引导练习：**请把“输入 n，计算 1 到 n 的和并输出”补成完整流程。纸上已经有“开始 → 输入 n → i=1,sum=0”以及判断框 i<=n，你需要补出“是”出口上的两个处理步骤、返回箭头和“否”出口。提示：每轮既要累加也要更新 i。用 n=3 核对时，sum 应依次变为 1、3、6，随后在 i=4 时判断为假并输出 6；若缺少 i=i+1 或最后一次失败判断，就还没有完成。

容易混淆的几个问题

  • 把平行四边形和处理矩形混淆；
  • 遇到判断框不计算条件，直接选择看起来更顺的路径；
  • 把“是”和“否”的出口标反，导致代码条件与流程图路径不一致；
  • 循环追踪时忘记变量更新；
  • 漏画离开循环的出口，使流程只能不断返回判断；
  • 箭头方向画反，阅读顺序与实际执行顺序相反；
  • 把只执行一次的分支误认成循环；
  • 互译时遗漏输入、输出或结束位置。

**错误写法：**判断框写 x >= 0，却把“是”箭头连到输出 negative。

**错误原因：**条件成立时选择“是”出口。x >= 0 为真表示非负数，出口含义与输出内容相反。

正确写法：“是”出口连接 non-negative，“否”出口连接 negative；再分别用 x=5 和 x=-2 追踪一次。

**错误写法：**循环流程只有“判断 → 输出 → 返回判断”，没有 i=i+1，也没有条件为假时的出口。

**错误原因：**变量不变化会让条件一直成立；没有“否”出口也无法表示离开循环。

**正确写法：**返回判断之前先更新 i，并让条件为假的箭头指向循环后的步骤或结束框。

本节总结

读流程图始终遵守四步：确认当前框的作用，执行框内操作，记录变量或输出，再沿唯一箭头前进。分支要写出条件实际值和未执行路径；循环要记录初始化、每轮判断、循环体、更新以及最后一次失败判断。流程图与代码互译时，结构和执行顺序必须一一对应。

关联学习

多层分支和多层循环页面会把更复杂代码还原为执行路径；流程图是检查这些路径是否完整的直观工具。
