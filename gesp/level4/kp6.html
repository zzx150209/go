二维数组

06
GESP 4级知识字典 · 知识点 06

定义二维数组，完成行列遍历与矩阵基本操作。

检索词：行列遍历矩阵操作

二维数组把同一类型的数据排成“行×列”的表格，矩阵、棋盘、座位表和字符地图都可以这样保存。学会它的关键不是多写一层中括号，而是始终说清：两个下标各表示什么、循环现在走到哪个格子、这个格子在内存中的真实位置怎样计算。

本课先记住

核心结论

二维数组先看行、再看列；元素总数等于各维长度相乘，字节数还要乘 `sizeof(元素类型)`；访问任何格子前，两个下标都必须合法。

常用语法

int grid[105][105] = {}; // 声明固定容量并把所有元素清零
for (int row = 1; row <= rows; row++) { // 从第 1 行遍历到实际最后一行
    for (int column = 1; column <= columns; column++) { // 遍历当前行的所有实际列
        cin >> grid[row][column]; // 把数据存入“当前行、当前列”
    } // 当前行的列全部读完
} // 所有实际行全部读完

最小示例

int score[2][3] = {{1, 7, 3}, {4, 2, 9}}; // 创建 2 行 3 列的成绩表
cout << score[0][1] << '\n'; // 0 下标下输出第 0 行第 1 列的 7

关键易错点

  • 把声明容量当成实际使用量
  • 把 0 下标与 1 下标写法混在一起
  • 用实际列数 m 代替声明时第二维长度计算内存位置
  • 先访问邻格，再检查它是否越界

这节课要会什么

本课只建立三个核心：用两个下标表示和定位表格；用双重循环按坐标安全遍历；用声明的各维长度解释连续存储、内存大小、函数传参和更多维数组。

从这个场景开始

先看同一张 2×3 成绩表：第一行是 1、7、3，第二行是 4、2、9。问“数字 7 在哪里”，必须回答第 1 行第 2 列；问“所有数之和”，必须让程序按顺序访问 6 个格子。后面的定义、遍历、内存和转置都继续使用这张表，不在每一步更换问题。

知识范围与官方定位

四级需要掌握二维及多维数组的定义、初始化、存储和遍历，能够把二维数组传入函数，完成行列、对角线、转置、字符地图、坐标边界、四方向和简单三维数组等基础处理。

01 二维数组定义与初始化

一维数组像一排抽屉，只用一个下标；二维数组像一张表格，要用“行下标”和“列下标”共同确定一个格子。`int score[2][3]` 中，`int` 是每个元素的类型，`score` 是数组名，第一个长度 2 表示行数，第二个长度 3 表示每行有 3 列，因此一共有 2×3=6 个 `int` 元素。

按照 C++ 原生的 0 下标，`score[0][0]` 是左上角，合法行下标是 0..1，合法列下标是 0..2；`score[0][1]` 对应第一行中间的 7。两个下标必须分别合法，只要一个越界，访问就不合法。

初始化有三种常见形式：完整初始化给出每个值；部分初始化只写前面若干值，没写到的元素自动补 0；`={}` 或 `={0}` 会把全部元素置 0。花括号按“每一行一组”书写，最容易看出表格结构。

要特别区分“声明后未初始化”和“部分初始化”：函数内部的普通局部数组 `int a[3][4];` 不会自动清零，读取尚未赋值的元素没有可靠结果；写成 `int a[3][4] = {};` 才明确全部为 0。全局数组和静态数组会自动初始化为 0，但初学阶段仍建议把意图写清楚。

本站处理行列编号时常使用 1 下标：例如实际要用 1..4 行、1..5 列，就声明 `int table[5][6] = {};`，把第 0 行和第 0 列留空。这样更接近题目坐标，但数组实际仍分配 5×6=30 个元素，不是 4×5=20 个。

完整、部分、全零和 1 下标容量的写法

int score[2][3] = { // 开始完整初始化 2 行 3 列的成绩表
    {1, 7, 3}, // 给第 0 行的 3 个元素依次赋值
    {4, 2, 9} // 给第 1 行的 3 个元素依次赋值
}; // 完成 score 的全部初始化
int partial[3][4] = { // 开始部分初始化 3 行 4 列的数组
    {1, 2}, // 第 0 行成为 1、2、0、0
    {3} // 第 1 行成为 3、0、0、0，第 2 行全部补 0
}; // 完成 partial 的部分初始化
int zeroed[3][4] = {}; // 把 3 行 4 列的全部元素初始化为 0
int table[5][6] = {}; // 分配 30 个元素，逻辑上使用第 1..4 行和第 1..5 列
关键提醒：数组各维长度必须在编译时确定。不要把运行时读入的 n、m 直接写进固定数组的中括号；本课统一使用编译期固定上限，再另外记录实际行数和列数。

02 双重循环、行优先存储与内存计算

行列遍历 n 行 m 列时，外层循环控制行，内层循环控制列。固定 row 后，column 从 1 走到 m；内层结束后，row 增加 1，column 再从 1 开始。这样正好得到“先走完第一行，再走第二行”的顺序。

输入和输出必须使用完全相同的坐标约定。若声明了 1 下标网格，输入循环、计算循环和输出循环都应使用 1..n、1..m；若使用 C++ 原生 0 下标，就统一使用 0..n-1、0..m-1，不能中途混用。

C++ 固定二维数组按行优先连续存储。对声明 `T a[R][C]`，`a[i][j]` 相对 `a[0][0]` 的元素偏移是 `i×C+j`；这里的 C 必须是声明时第二维长度，不是输入的实际列数 m。字节偏移再乘 `sizeof(T)`。

例如 `int grid[3][4]` 有 3×4=12 个元素，占 `12×sizeof(int)` 字节。在常见 GCC/OJ 环境中 `sizeof(int)==4`，此时共 48 字节；`grid[1][2]` 的元素偏移是 1×4+2=6，字节偏移是 `6×sizeof(int)`，常见环境下为 24 字节。C++ 标准没有保证 `int` 永远是 4 字节，程序应以实际 `sizeof(int)` 为准。

1 下标不会改变真实存储。`int table[5][6]` 永远分配 30 个元素，每一行的跨度永远是 6；即使只使用第 1..4 行、第 1..5 列的 20 个格子，第 0 行、第 0 列和每行的保留位置仍占空间。

同理，`int grid[105][105]` 分配 11025 个 `int`，占 `11025×sizeof(int)` 字节；常见 4 字节环境下是 44100 字节，约 43.1 KiB。`char map[105][105]` 有 11025 个 `char`，而 `sizeof(char)` 按定义等于 1 字节，所以占 11025 字节。`sizeof(grid)` 在数组仍是完整数组的作用域中得到声明容量，不是 n×m 的实际使用量。

  • 元素数量 = 各维声明长度相乘；内存字节数 = 元素数量 × sizeof(元素类型)
  • `sizeof(grid[0])` 表示一整行的字节数；对 `int grid[3][4]`，它等于 `4×sizeof(int)`
  • 声明容量回答“实际分配多少”，n、m 回答“题目本次使用多少”，二者不能互相替代

按行输入并按原表格格式输出

for (int row = 1; row <= n; row++) { // 外层依次选择第 1..n 行
    for (int column = 1; column <= m; column++) { // 内层走过当前行的第 1..m 列
        cin >> grid[row][column]; // 把输入值保存到当前坐标
    } // 当前行输入完成，column 下一次会重新从 1 开始
} // n 行数据全部输入完成
for (int row = 1; row <= n; row++) { // 再按相同行顺序准备输出
    for (int column = 1; column <= m; column++) { // 依次读取当前行的每个元素
        cout << grid[row][column] << ' '; // 输出当前格子并用空格分隔
    } // 当前行的 m 个元素全部输出
    cout << '\n'; // 当前行结束后换行，恢复表格形状
} // n 行数据全部输出完成
关键提醒：地址公式中的列宽来自声明。对 `table[5][6]`，真实行跨度是 6；绝不能因为本次只用了 5 列就把公式写成 `row×5+column`。

03 二维数组作为函数参数

二维数组作为参数时，函数要访问 `grid[row][column]`，必须知道一行在内存中跨过多少个元素。调用函数时，二维数组会把首元素位置交给函数，第一维长度可以省略；但是第二维长度决定行跨度，必须在参数类型中写出。

固定容量和实际范围是两组不同信息。`MAX_COLUMN=105` 告诉编译器每一行固定有 105 个位置；rows、columns 告诉函数这次只处理多少行、多少列。函数循环必须使用实际范围，位置计算则依赖固定列宽。

只读函数应在元素类型前加 `const`，表示函数可以查看网格但不能改写它。数组作为参数后不再是函数内部的完整数组，因此不能在函数里用 `sizeof(grid)` 推回调用处的总容量；需要的行数、列数必须明确传入。

固定第二维长度，并另外传入实际行列

const int MAX_COLUMN = 105; // 统一规定每一行的固定容量
int sumGrid(const int grid[][MAX_COLUMN], int rows, int columns) { // 接收只读二维数组和实际范围
    int sum = 0; // 从 0 开始累计全部实际元素
    for (int row = 1; row <= rows; row++) { // 只遍历本次实际使用的行
        for (int column = 1; column <= columns; column++) { // 只遍历本次实际使用的列
            sum = sum + grid[row][column]; // 读取当前格子并加入总和
        } // 当前行的实际列处理完成
    } // 所有实际行处理完成
    return sum; // 把矩阵元素总和交还调用处
} // 结束只读二维数组求和函数
关键提醒：参数不能写成 `int grid[][]`，也不要把 `MAX_COLUMN` 换成运行时读入的 columns；标准 C++ 固定数组的后续维长度必须在编译时确定。

04 从行列处理到字符地图与四方向

行最大值与列最大值看起来是两类任务，其实和网格邻格处理一样，核心都是把题目的“位置条件”翻译成行列下标。求某一行最大值，就是固定 row、改变 column；求某一列最大值，就是固定 column、改变 row。最大值必须从当前行或列的第一个合法元素开始，不能从 0 开始，否则全负数时会得到并不存在的 0。

继续使用 2×3 矩阵 `1 7 3 / 4 2 9`：两行最大值是 7、9，三列最大值是 4、7、9。计算第二列最大值时，先令结果等于 `grid[1][2]=7`，再与 `grid[2][2]=2` 比较，最终仍为 7。

方阵主对角线满足 `row==column`；1 下标副对角线满足 `row+column==n+1`。矩形边框满足 `row==1 || row==n || column==1 || column==m`。棋盘交错格可以观察 `row+column` 的奇偶性：和的奇偶性相同，就属于同一种颜色。

字符地图只是把元素类型换成 `char`，常用固定容量可以写成 `char map[105][105]`。例如 `.` 表示可走、`#` 表示障碍，坐标 `(row,column)` 的含义与数值矩阵完全相同；先确认 1≤row≤n 且 1≤column≤m，再读取地图字符。

检查上、下、左、右时，项目统一用 `fx` 保存行变化、`fy` 保存列变化，下标 0 占位，从方向 1 开始。每个方向都先计算 nextRow、nextColumn，再判边界，最后才访问 `terrain[nextRow][nextColumn]`。顺序颠倒会在边角位置先访问数组外部。

  • 3×4 网格的内部位置 (2,2) 四个候选坐标是 (1,2)、(3,2)、(2,1)、(2,3)，全部在边界内
  • 左上角 (1,1) 向上得到 (0,1)、向左得到 (1,0)，必须在访问地图之前丢弃
  • 主对角线判断行列相等；1 下标副对角线判断行列之和等于 n+1；边框判断是否位于首末行或首末列

行最大值与列最大值、字符地图四方向的独立片段

int targetRow = 1; // 选择要处理的第 1 行
int rowMaximum = grid[targetRow][1]; // 用目标行第一个合法元素初始化最大值
for (int column = 2; column <= m; column++) { // 从目标行第 2 列继续比较
    if (grid[targetRow][column] > rowMaximum) { // 判断当前格子是否更大
        rowMaximum = grid[targetRow][column]; // 更新目标行的最大值
    } // 结束本格子的大小判断
} // 目标行的所有列比较完成
int targetColumn = 2; // 选择要处理的第 2 列
int columnMaximum = grid[1][targetColumn]; // 用目标列第一个合法元素初始化最大值
for (int row = 2; row <= n; row++) { // 从目标列第 2 行继续比较
    if (grid[row][targetColumn] > columnMaximum) { // 判断当前格子是否更大
        columnMaximum = grid[row][targetColumn]; // 更新目标列的最大值
    } // 结束本格子的大小判断
} // 目标列的所有行比较完成
char terrain[105][105] = {}; // 创建 1 下标字符地图并清零
for (int row = 1; row <= n; row++) { // 依次读入地图的每一行
    for (int column = 1; column <= m; column++) { // 依次读入当前行的每个字符
        cin >> terrain[row][column]; // 保存当前坐标的地图字符
    } // 当前地图行读入完成
} // 整张字符地图读入完成
int x = 1, y = 1; // 设当前位置为第 1 行第 1 列
int fx[5] = {0, -1, 1, 0, 0}; // 记录占位、上、下、左、右的行变化
int fy[5] = {0, 0, 0, -1, 1}; // 记录占位、上、下、左、右的列变化
for (int direction = 1; direction <= 4; direction++) { // 依次尝试四个方向
    int nextRow = x + fx[direction]; // 计算候选格子的行号
    int nextColumn = y + fy[direction]; // 计算候选格子的列号
    bool inside = 1 <= nextRow && nextRow <= n && 1 <= nextColumn && nextColumn <= m; // 先判断两个下标是否都在地图内
    if (inside && terrain[nextRow][nextColumn] == '.') { // 只在合法后访问字符并判断是否可走
        cout << nextRow << ' ' << nextColumn << '\n'; // 输出边界内且可走的邻格坐标
    } // 结束当前候选格子的检查
} // 四个方向全部检查完成
关键提醒：若 n、m 至少为 1，行最大值从 `grid[row][1]` 开始，列最大值从 `grid[1][column]` 开始。写成 0 会让全负数矩阵得到错误答案。

05 矩阵转置与翻转

转置不是把数值重新排序，而是交换每个元素的行列身份：原来的 `grid[row][column]` 放到 `transposed[column][row]`。因此 rows×columns 的矩阵会变成 columns×rows。

2×3 矩阵 `1 7 3 / 4 2 9` 转置后是 3×2：三行依次为 `1 4`、`7 2`、`3 9`。例如原位置 `(1,3)` 的 3 进入新位置 `(3,1)`。只有方阵才能在同一数组里简单交换对称位置；初学阶段处理非方阵应另开结果数组。

翻转只改变一个坐标。1 下标水平翻转保持 row 不变，把 column 变为 `m+1-column`；垂直翻转保持 column 不变，把 row 变为 `n+1-row`。先写出坐标变化，再决定是直接倒序输出，还是存入另一个数组。

把 n×m 矩阵转置并按 m×n 输出

int transposed[105][105] = {}; // 创建保存转置结果的固定容量数组
for (int row = 1; row <= n; row++) { // 枚举原矩阵的每一行
    for (int column = 1; column <= m; column++) { // 枚举原矩阵当前行的每一列
        transposed[column][row] = grid[row][column]; // 交换行列坐标后保存当前元素
    } // 原矩阵当前行的所有列转置完成
} // 原矩阵全部元素转置完成
for (int row = 1; row <= m; row++) { // 转置结果共有 m 行
    for (int column = 1; column <= n; column++) { // 转置结果每行共有 n 列
        cout << transposed[row][column] << ' '; // 输出转置后的当前格子
    } // 转置结果当前行输出完成
    cout << '\n'; // 一行结束后换行
} // 按 m 行 n 列输出完整转置结果
关键提醒：原矩阵不是方阵时，转置后的行数和列数必然互换；仍按 n 行 m 列输出会漏元素、重复元素或访问错误范围。

06 三维及更多维数组

二维数组用“行、列”定位，三维数组再增加一个有实际含义的下标。例如 `box[layer][row][column]` 可以表示第几层、第几行、第几列；`state[time][row][column]` 可以入门表示不同时刻的同一张网格。名字必须说明每一维含义。

`int box[2][3][4]` 有 2 层，每层 3 行，每行 4 列，总元素数是 2×3×4=24，占 `24×sizeof(int)` 字节；常见 4 字节 int 环境下为 96 字节。三个合法下标范围依次是 0..1、0..2、0..3。

行优先规则继续向外扩展：`box[layer][row][column]` 的元素偏移是 `layer×3×4 + row×4 + column`。最后一个元素 `box[1][2][3]` 的偏移为 1×12+2×4+3=23，正好是第 24 个元素。字节偏移仍要再乘 `sizeof(int)`。

完整遍历三维数组需要三层循环，分别控制层、行、列。每增加一维，就多一组长度、边界和循环；四级只要求理解这种表示与计算，不引入动态多维数组、二级指针或更复杂的状态压缩。

  • 元素数量 2×3×4=24，最后合法坐标是 [1][2][3]
  • `box[2][0][0]` 的第一维越界，即使后两维合法，整体访问仍不合法
  • 多维数组的内存字节数仍是“各维长度相乘，再乘 sizeof(元素类型)”

按“层—行—列”顺序给三维数组编号

int box[2][3][4] = {}; // 创建 2 层、3 行、4 列的三维数组并清零
int value = 1; // 准备从 1 开始给每个位置编号
for (int layer = 0; layer < 2; layer++) { // 依次遍历第 0 层和第 1 层
    for (int row = 0; row < 3; row++) { // 遍历当前层的 3 行
        for (int column = 0; column < 4; column++) { // 遍历当前行的 4 列
            box[layer][row][column] = value; // 把当前编号保存到对应三维坐标
            value = value + 1; // 为下一个位置准备新的编号
        } // 当前行的 4 列编号完成
    } // 当前层的 3 行编号完成
} // 两层的 24 个元素全部编号完成

`T a[R][C]`R 行、每行 C 列，共 R×C 个 T 元素R、C 是声明容量
`a[i][j]`0 下标下第 i 行第 j 列0≤i<R 且 0≤j<C
元素偏移`i×C+j`C 是声明时第二维长度
内存字节数`R×C×sizeof(T)`不要把逻辑使用量当声明容量
行/列最大值固定一个维度，遍历另一个维度从首个合法元素初始化
字符地图四方向`fx` 改行、`fy` 改列先判新坐标边界，再访问字符
主/副对角线`r==c` / `r+c==n+1`公式使用同一种下标约定
转置`result[c][r]=grid[r][c]`结果尺寸是 m×n

典型例题

求矩阵所有元素之和

输入 n 行 m 列的整数矩阵，1≤n,m≤100，每个元素绝对值不超过 1000。程序使用 1 下标固定数组，按行读入每个格子，再输出所有元素之和。最大绝对总和为 100×100×1000=10000000，在 int 范围内。

完成程序

#include <bits/stdc++.h> // 引入本程序需要的标准库
using namespace std; // 允许直接使用 cin、cout、string 等标准库名称

int main() { // 主函数是程序的入口
    int n, m; // 定义实际使用的行数和列数
    cin >> n >> m; // 读入矩阵尺寸
    int grid[105][105] = {}; // 分配固定容量并把包括第 0 行第 0 列在内的元素清零

    for (int row = 1; row <= n; row++) { // 按 1 下标依次遍历每一行
        for (int column = 1; column <= m; column++) { // 从左到右遍历当前行的每一列
            cin >> grid[row][column]; // 把当前输入保存到唯一的行列坐标
        } // 结束当前行的列遍历，下一行的 column 会重新从 1 开始
    } // 结束矩阵输入的行遍历，n×m 个值全部保存完成

    int sum = 0; // 在访问第一个格子前把累计总和设为 0
    for (int row = 1; row <= n; row++) { // 按输入时相同的顺序再次遍历每一行
        for (int column = 1; column <= m; column++) { // 从左到右读取当前行的每个元素
            sum = sum + grid[row][column]; // 把当前格子的值准确加入累计总和
        } // 结束当前行的列遍历，本行每个元素恰好累加一次
    } // 结束矩阵求和的行遍历，全部实际元素恰好累加一次
    cout << sum << '\n'; // 输出最终总和并换行
    return 0; // 返回 0，表示程序正常结束
} // 结束 main 函数
示例输入
2 3
1 7 3
4 2 9
示例输出
26

解题与执行过程

  1. 声明容量是 105×105=11025 个 int；示例实际只使用第 1..2 行和第 1..3 列的 6 个格子，保留空间仍然存在。
  2. 第一行访问顺序是 grid[1][1]、grid[1][2]、grid[1][3]，读到 1、7、3，sum 从 0 变为 11。
  3. 第一行内层结束后，row 变为 2，column 重新从 1 开始，再读到 4、2、9。
  4. sum 的完整变化是 0→1→8→11→15→17→26；当 row 变为 3 时外层条件失败，最终输出 26。

常见错误

行列边界混用

错误写法：n 行 m 列却让 row <= m、column <= n。原因：两个下标含义颠倒。正确写法：row 控制 n 行，column 控制 m 列。

0 下标与 1 下标混用

错误写法：输入使用 1..n，求和却使用 0..n-1。原因：两次遍历访问的不是同一组格子。正确写法：先选定约定，再让声明容量、输入、计算和输出保持一致。

只看一个下标

错误写法：认为 `int grid[2][3]` 的 `grid[1][3]` 合法，因为第一维没有越界。原因：第二维合法范围是 0..2。正确写法：每一维都单独核对。

1 下标却没有多开空间

错误写法：最多 100 行却声明 `int grid[100][100]`，再访问下标 1..100。原因：下标 100 已越界。正确写法：使用固定上限 101 或留出余量的 105，并清楚区分容量与实际范围。

把未初始化当成 0

错误写法：在函数内声明 `int grid[3][4];` 后直接读取。原因：普通局部数组不会自动清零。正确写法：先完整赋值，或写成 `int grid[3][4] = {};`。

内存计算使用实际列数

错误写法：对 `int table[5][6]` 使用本次 m=5，认为 `table[3][4]` 的偏移是 3×5+4。原因：真实行跨度由声明第二维 6 决定。正确写法：偏移按 3×6+4 计算。

最大值初始为 0

错误写法：全负数矩阵求最大值时令 maximum=0。原因：0 可能根本不在矩阵中。正确写法：从当前行或列的第一个合法元素初始化。

先访问邻格再判边界

错误写法：先读取 terrain[nextRow][nextColumn]，再判断 nextRow、nextColumn。原因：边角方向可能已经越界。正确写法：先计算、再判两个边界、最后访问。

转置后仍按原尺寸输出

错误写法：原 n×m 矩阵转置后仍输出 n 行 m 列。原因：行列已经互换。正确写法：按 m 行 n 列输出结果。
