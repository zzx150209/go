哈希表与集合

09
GESP 7级知识字典 · 知识点 09

统计元素出现次数，判断存在性，比较有序与无序关联容器。

检索词：键值统计关联容器

知识范围与官方定位

官方七级大纲要求掌握哈希表。哈希表通过哈希函数把键映射到存储位置，适合快速查找和计数。C++ 关联容器是常见实现工具，但必须理解有序与无序、键是否存在以及平均复杂度和最坏情况的区别。

01 键、值与映射

键用于查找，值保存与键关联的信息。例如统计单词次数时，单词是键，出现次数是值。相同键对应同一个统计位置，不能把“键”和“出现次序”混为一谈。计数、去重、快速查找和建立映射关系，是关联容器最常见的四类应用。

具体推演： 依次读入 apple、banana、apple。第一次读取 apple 时建立 apple→1，读取 banana 后得到 banana→1，再次读取 apple 时找到原来的同一个键并更新为 apple→2。最终只有两个键，而不是三个“输入位置”。

02 哈希函数、冲突与复杂度

不同键可能映射到相同位置，这称为哈希冲突，实际实现必须处理冲突。哈希表的查找、插入平均可视为 O(1)，但不能宣称任何情况下都绝对是 O(1)；数据分布和实现会影响最坏情况。

具体推演： 假设教学用哈希位置是 key % 5，键 2 和 7 都落到位置 2，这就是冲突。容器必须继续区分两个真实键；查找 7 时先定位这个位置，再核对键本身。多数位置分布均匀时检查很少，若许多键都冲突到同一位置，最坏就可能逐个检查。

03 map 与 unordered_map

map 按键有序，常见操作复杂度为 O(log n)；unordered_map 不保证遍历顺序，平均查找和插入为 O(1)。若题目要求按键从小到大输出，应使用 map 或另行排序，不能依赖 unordered_map 的显示顺序。

访问 count[key] 时，如果键不存在，会插入默认值 0，很适合计数；若只想判断而不想插入，可使用 find。

具体推演： 插入键值 3→30、1→10、2→20 后，遍历 map 会按键输出 1、2、3；遍历 unordered_map 只能保证三组键值仍存在，不能预测顺序。若只执行 count[5] 查询，不存在的键 5 还会被创建并取默认值 0；使用 find(5) 则不会改变容器。

04 set、unordered_set 与去重

集合只保存键，不保存对应值。set 中元素有序，unordered_set 不保证顺序。插入重复元素不会增加集合大小，因此可用于去重和存在性判断。

具体推演： 把 5,2,5,3,2 依次插入 set，集合大小变化为 1,2,2,3,3，最终元素按序为 2,3,5。换成 unordered_set 后大小仍是 3，存在性判断结果也相同，但遍历顺序不能作为答案的一部分。

容器 内容 顺序 常见操作

unordered_map 键值对 不保证 快速计数

典型例题

基础例题

依次读入 1 2 2 3。第一次看到一个键时，它的旧计数是 0；再次看到键 2 时，只更新同一个键对应的值。最后得到映射 {1:1, 2:2, 3:1}。哈希或映射结构解决的是“按键找到对应信息”，不是保存每次出现的独立副本。

典型应用例题

统计输入整数的出现次数并按数值从小到大输出：

#include <bits/stdc++.h>using namespace std;
int main() {    int n;    cin >> n;    map<int, int> count;    // 下标访问不存在的键会插入默认值 0，因此可以直接累加次数。    for (int i = 1; i <= n; i++) {        int value;        cin >> value;        count[value]++;    }    // map 按键有序遍历，所以输出自然按数值从小到大排列。    for (auto item : count) {        cout << item.first << " " << item.second << endl;    }    return 0;}

使用 map 是因为输出要求有序。若只查询次数而不要求顺序，可按题目范围考虑 unordered_map。

映射追踪

对输入 1 2 2 3，每次读取后的键与当前计数如下：

输入的键 操作前计数 操作后当前计数
1 0 1
2 0 1
2 1 2
3 0 1

若使用 map，最终遍历顺序按键从小到大；若换成 unordered_map，计数结果相同，但不能据此预测输出顺序。

建议测试案例

测试类型 输入或条件 预期结果
基础 4 个数：1 2 2 3 输出 1 1、2 2、3 1
边界 n = 0 不输出任何键值对
易错 使用 unordered_map 统计后直接遍历 计数正确，但不能要求按键有序

常见错误

错误做法 为什么错 正确方法
依赖 unordered_map 或 unordered_set 的遍历顺序 无序容器不承诺按键或插入顺序输出 需要有序输出时使用 map、set 或另行排序
只想查询却使用下标访问 不存在的键会被插入并赋默认值 使用 find 判断是否存在
把平均 O(1) 写成最坏也一定 O(1) 冲突和实现会影响最坏情况 准确表述为平均查找、插入 O(1)
需要保存“键对应次数”却使用 set 集合只保存唯一键，没有对应值 使用 map 或 unordered_map
小范围整数也强行使用哈希 增加实现复杂度和常数开销 数据范围小时优先考虑直接计数数组

错误反例推演

容器初始为空，只想判断键 "cat" 是否存在。错误写法读取 count["cat"]，得到数值 0 的同时把 "cat" 插入容器，随后 count.size() 从 0 变成 1；程序会把“查询”变成“修改”。正确写法使用 count.find("cat") == count.end()，判断结果仍是不存在，容器大小保持 0。
