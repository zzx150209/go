程序基本结构

03
GESP 1级知识字典 · 知识点 03

理解头文件、命名空间、main 函数、语句、代码块和注释。

检索词：main函数程序框架

本课先记住

  • 核心结论： 一份一级 C++ 完整程序通常由头文件、命名空间和 main 代码块组成；运行从 main 开始，普通语句按顺序执行。
  • 常用骨架： #include <bits/stdc++.h> 提供常用声明，下一行写 using namespace std;，再用 int main() { ... return 0; } 放置主程序。
  • 最小示例： int main() { cout << "Hello" << endl; return 0; } 从输出语句执行到 return 0; 后正常结束。
  • 关键易错点： 预处理指令后不写分号，普通语句通常要用分号结束；大括号必须按层配对，未结束的多行注释会遮住后续代码。

知识范围与官方定位

本页对应 GESP C++ 一级大纲中的“C++ 程序基本结构”。前一页已经走过编辑、保存、编译、运行的开发流程；这一页要看懂编译器正在处理的源代码由哪些部分组成。

学完本页，你应当能解决三个核心问题：

  1. 怎样写出一份结构完整、可以编译运行的 C++ 程序？
  2. 源代码中哪些内容参与编译，程序运行时又从哪里开始执行？
  3. 怎样检查分号、括号、代码块和注释造成的结构问题？

本页只讲一级完整程序的公共骨架，不展开自定义函数、类、头文件内部实现等内容。输入输出语句会出现在代表程序中，但它怎样读取和组织数据，留到下一页专门讲。

先看一张职责图：

源文件顶部：准备编译需要的声明与名称规则        ↓int main()：标出程序运行入口        ↓main 的 { }：装入真正依次执行的语句        ↓return 0;：正常结束 main

这几层缺一处关键结构，编译器就可能无法把源文件正确分段。

01 头文件与命名空间

为什么使用头文件

C++ 标准库已经准备了许多常用工具。使用这些工具前，源文件需要引入相应的声明，让编译器知道名称和基本用法。

一级完整程序在本站统一写：

#include <bits/stdc++.h>using namespace std;

第一行是预处理指令。#include 表示引入头文件，尖括号中是头文件名。这一行从 # 开始，行末不写分号。

<bits/stdc++.h> 汇集了许多常用标准库头文件，在常见 GCC 和在线评测环境中通常可用。它不是 C++ 标准规定每个编译器都必须提供的头文件；换到不支持它的环境时，需要改用实际需要的标准头文件。

例如，标准头文件 <iostream> 提供 cin、cout、endl 等输入输出工具所需的声明：

#include <iostream>

因此，自测题中看到 #include <iostream> 时，应判断它是在引入输入输出相关声明，而不是在定义 main 或创建循环。本站完整程序继续按照项目约定使用 <bits/stdc++.h>。

using namespace std; 解决什么问题

标准库中的名称位于名为 std 的命名空间中。命名空间可以把不同来源的名称分开，减少重名冲突。

写上：

using namespace std;

以后就可以在本页程序里直接写 cout、endl 等标准库名称。这一行属于 using 指令，末尾需要分号。

如果省略这行，标准库并没有消失，只是通常要在名称前写出 std::。一级主教学先统一保留 using namespace std;，不展开命名空间的更多用法。

两行的位置和执行边界

头文件与命名空间相关内容写在 main 之前，因为编译器需要先认识这些声明和名称规则，再检查后面的代码。

它们参与源文件的处理，却不是“运行后从上到下打印到屏幕的两条语句”：

内容 主要在哪个阶段起作用 会不会直接产生屏幕输出
#include <...> 预处理阶段，引入头文件内容 不会
using namespace std; 编译时帮助查找名称 不会
main 代码块内的输出语句 程序运行阶段 会按语句要求输出

这就解释了一个常见误会：源文件的第一行是 #include，不表示程序运行时先“执行一次 include”。程序真正开始运行的位置是 main。

02 关键字与基本组成

关键字和普通名称要分开

关键字是 C++ 语言已经规定用途的单词，不能拿来给变量随意命名。一级常见关键字有 int、double、char、bool、if、else、while、for、using、namespace、return。

有些常见单词不是关键字：

名称 属于什么 为什么容易误认
main 有特殊规则的程序入口名称 每个普通 C++ 程序都会看到它
cout 标准库提供的名称 经常与输出语句一起出现
endl 标准库提供的输出操纵符 看起来像语言命令，其实不是关键字
number 程序员可以选择的标识符 只在当前程序中承担约定的含义

所以，在 double、else、while、endl 四个选项中，endl 不是 C++ 关键字。

从外到内拆开 int main()

看到 int main() 时，不要把它背成一串不能拆开的字符。每个部分都有职责：

部分 本页先这样理解 书写检查
int main 结束时交回一个整数状态码 必须小写
main 程序规定的入口名称 必须写成小写 main，不能写成 Main 或 mian
() main 名称后的参数列表，本页保持空 左右圆括号必须成对
{} main 的函数体，也就是一个代码块 左右大括号必须成对，内部统一缩进

int 与代码块末尾的 return 0; 前后呼应：return 0; 把整数 0 作为结束状态交回运行环境，通常表示程序正常结束。

C++ 允许 main 执行到末尾时省略显式的 return 0;，其效果仍按正常返回 0 处理。不过一级学习阶段建议把它完整写出，这样入口、执行语句和结束位置更容易辨认。

一份完整程序有哪些层

可以把一级程序分成三层：

层次 典型内容 主要职责
编译准备层 #include <bits/stdc++.h> 提供标准库声明
名称规则层 using namespace std; 允许直接使用标准库名称
程序主体层 int main() { ... } 给出运行入口和实际执行内容

“完整”并不等于代码很长。只要必要结构齐全，即使 main 中只有 return 0;，也可以编译和正常结束；只是它没有安排任何屏幕输出。

03 main 函数与执行顺序

main 是运行入口

编译器检查的是整个源文件，而运行环境启动程序时会寻找 main，进入它的大括号，再按照控制结构规定的顺序执行其中的语句。

一级程序中，普通执行语句都应写在 main 的代码块内。把一条输出或计算语句随意放在 main 外面，编译器不会把它当成“提前执行的一步”，通常会报告结构错误。

从源代码到 main 经历了什么

上一页学过“保存 → 编译 → 运行”，现在把程序结构放进这条链：

阶段 处理对象 发生的事 是否已经在执行 main
保存 编辑器中的内容 写入 .cpp 源文件 否
预处理 #include 等预处理指令 处理头文件相关内容 否
编译与链接 整个处理后的程序 检查结构和名称，生成可执行程序 否
启动运行 可执行程序 运行环境找到程序入口 即将进入
执行主体 main 的代码块 按顺序执行其中的语句 是
正常结束 return 0; 或到达 main 末尾 结束 main 并交回状态 已结束

实际开发工具可能把“预处理、编译、链接”合并显示为一次“构建”或“编译”。一级只需掌握它们都发生在运行之前；编译成功后，才有本次源代码对应的新程序可运行。

怎样追踪一次运行

追踪程序时，先把不会作为普通语句执行的部分排除，再看 main 内部：

  1. #include 为编译准备声明，不会在运行窗口显示文字。
  2. using namespace std; 帮助编译器查找名称，也不会产生输出。
  3. 运行从 main 的左大括号进入。
  4. 注释只给读者看，不作为普通语句执行。
  5. main 内的普通语句按顺序执行。
  6. 执行 return 0; 后，main 结束；写在它后面的普通语句不会再执行。

因此，追踪输出顺序时，应先找到 main，再沿着它的实际执行路径检查。

04 语句、分号与代码块

分号结束一条普通语句

语句描述程序要完成的一项操作。很多简单语句以分号 ; 结束，例如：

int age = 12;return 0;

第一行定义一个整数并保存 12，第二行结束 main 并交回状态 0。两个分号都表示对应语句已经结束。

但不能总结成“C++ 每一行都写分号”。是否需要分号取决于这段内容的语法职责：

写法 行末是否写分号 原因
#include <bits/stdc++.h> 不写 它是预处理指令，不是普通语句
using namespace std; 要写 using 指令以分号结束
int main() 此处不写 后面紧跟函数体代码块
cout << ...; 要写 这是一条输出语句
return 0; 要写 这是一条返回语句
单独的 { 或 } 通常不写 大括号负责围成代码块

如果 return 0 后漏写分号，编译器可能在下一行或右大括号附近才确定结构不完整。仍应沿用上一页的方法：先看第一条错误，再检查提示行和上一行。

大括号围成代码块

左大括号 { 表示代码块开始，右大括号 } 表示代码块结束。当前最重要的代码块是 main 的函数体。

int main() {    这里写属于 main 的语句}

左右大括号必须配对。漏写右大括号会让 main 的代码块结构不完整；多写一个右大括号，也会让编译器找不到与它配对的开始位置。

缩进不改变 C++ 的执行结果，但能把从属关系显示出来。本站代码统一使用 4 个空格缩进：main 内的语句向右缩进一级，左右大括号保持对齐。这样检查配对时，比把所有内容挤在一列更可靠。

用“结构配对”检查编译错误

遇到程序结构相关报错时，可以从外到内检查：

  1. #include 的 #、尖括号和头文件名是否完整；
  2. using namespace std; 是否拼写正确并写了分号；
  3. int main() 的大小写与圆括号是否正确；
  4. main 的左右大括号是否配对；
  5. 块内需要分号的普通语句是否写全；
  6. 注释标记是否正确结束，是否意外遮住了代码。

这套顺序从程序外层检查到内层。外层结构恢复以后，后面的连带报错往往会一起减少。

05 注释

两种基本注释

注释用于给读代码的人补充说明，不作为普通语句执行。C++ 常见两种注释：

// 单行注释：从双斜杠开始，到这一行末尾结束
/* 多行注释：从斜杠星号开始，   到星号斜杠结束 */

单行注释适合说明一行代码或一个短步骤。多行注释可以跨越多行，但必须同时有开始标记 /* 和结束标记 */，而且不能随意嵌套另一组多行注释。

注释行末不因为“像一句话”就补分号。若注释写在一条语句后面，需要分号的是前面的语句本身：

int age = 12; // age 保存学生年龄，初始值是 12

注释不会执行，但会影响代码边界

编译器不会把注释内容当作普通 C++ 语句执行。因此，注释里写“输出答案”，屏幕不会真的出现答案。

反过来，如果把真正需要执行的代码放进注释，它也不会执行。例如临时注释掉一条输出语句后，程序可能正常结束，却没有预期输出。

多行注释忘记写 */ 时，后面一大片代码都可能被继续当作注释，报错位置也可能远离真正遗漏标记的地方。检查时应先找到最近的 /*，确认它是否有对应的 */。

注释应解释“为什么”或“这一步做什么”

好的注释帮助读者理解关键职责，例如“输出问候，确认程序已经进入 main”。如果注释只是把代码逐字重复一遍，就没有增加信息。

调试时可以暂时注释某一行，但要注意两点：

  1. 不要把必要的大括号一起注释掉，破坏代码块配对；
  2. 提交前恢复正式逻辑，并重新编译运行，不能只凭记忆判断已经恢复。

把各部分合成一个完整程序

完成程序

下面是本页唯一的完整程序。它的任务很简单：在屏幕上输出一行问候，用来验证程序骨架能够正常编译、进入 main、执行语句并结束。

#include <bits/stdc++.h>using namespace std;
int main() {    // 输出一句问候，确认程序已经进入 main    cout << "Hello, C++!" << endl;    return 0;}

运行时不需要输入。输出为：

Hello, C++!

这里先把 cout << "Hello, C++!" << endl; 整体看作“一条输出语句”：它把问候文字送到屏幕并换行，末尾分号结束这条语句。cout 从左到右怎样连接内容、endl 为什么换行，会在下一页详细讲解。

从编译到结束逐步追踪

顺序 当前部分 实际发生的事 屏幕变化
1 #include <bits/stdc++.h> 在运行前准备常用标准库声明 无
2 using namespace std; 让编译器能直接查找标准库名称 无
3 int main() { 程序运行时进入 main 代码块 无
4 // ... 注释只供读者理解 无
5 cout << ...; 执行输出语句 出现 Hello, C++! 并换行
6 return 0; 立即结束 main，交回状态 0，程序结束 不再新增文字，也不再执行后续语句

这张表同时验证了三个结论：运行入口是 main，注释不作为普通语句执行，return 0; 后本程序正常结束。

表中的右大括号 } 是源代码里标记函数体结束的边界，不是 return 0; 后还会继续执行的一条语句。

怎样验证这份骨架

不要只看代码“长得像示例”，要真正走一遍开发流程：

  1. 把完整代码保存为 .cpp 文件；
  2. 使用 C++14 编译，确认没有编译错误；
  3. 运行时不输入任何数据；
  4. 检查屏幕是否只有 Hello, C++! 和行末换行；
  5. 再检查程序是否正常结束，没有额外调试文字。

如果漏写输出语句末尾的分号，应该在编译阶段发现；如果把输出语句放到 return 0; 后面，结构可能仍能编译，但那条语句不会执行。两种现象分别说明“语法结构”和“执行顺序”是不同问题。

知识点速查表

写法 职责 关键边界
#include <bits/stdc++.h> 在常见 GCC/OJ 环境引入常用标准库声明 行末不写分号；有的编译器不提供
#include <iostream> 引入标准输入输出相关声明 C++ 标准头文件，行末不写分号
using namespace std; 允许本页直接使用标准库名称 行末写分号
int main() 定义程序运行入口 main 小写，圆括号成对
{ } 围成 main 的代码块 左右大括号成对，内部缩进 4 个空格
return 0; 正常结束 main 是普通语句，末尾写分号
// 注释到当前行末 下一行恢复为普通代码
/* */ 注释两个标记之间的内容 必须闭合，不随意嵌套

典型例题

下面几种现象分别应先检查哪里？

现象 先检查 判断依据
编译器提示 main 附近结构不完整 main 的圆括号、大括号和拼写 入口结构必须完整，main 必须小写
第一条错误出现在右大括号附近 上一条普通语句是否漏写分号 编译器可能到代码块结束才发现语句未结束
程序成功运行但没有问候文字 输出语句是否被注释，或是否写在 return 0; 后 注释不执行，返回后也不继续执行后续语句
出现很多连续报错 第一条错误是否破坏了外层结构 漏括号或未闭合注释可能引发连带错误

解决这类题的顺序是：先找程序入口与代码块，再查普通语句边界，最后判断注释和执行顺序。不要只凭报错数量猜程序“全都写错了”。

引导练习（不记录进度）

检查这段骨架中的三个位置：头文件行后是否误写分号、cout 普通语句是否有分号、main 的左右大括号是否成对。按“预处理 → main 入口 → 语句 → 正常结束”顺序逐项打勾，再编译验证。

成功标准： 修正后的程序能够编译，运行时只输出预定文字，并从 return 0; 正常结束。完成后不看提示独立完成页末“整页综合测试”；提交后用首条报错和结构配对规则复核错题。

常见错误

把 main 写成近似拼法

错误： 写成 Main、mian，或者漏掉一边圆括号。

原因： C++ 区分大小写，程序入口的名称和结构必须准确。

检查： 对照 int main() 逐字符确认，并配对左右圆括号。

认为每一行末尾都要分号

错误： 不分结构地逐行补分号，或者因为 int main() 后没有分号就认定它错误。

原因： 预处理指令、函数头、代码块和普通语句的职责不同。

检查： 先判断这一段属于哪种结构；普通语句和 using 指令要分号，#include 与紧跟代码块的 int main() 不这样写。

大括号数量相同，却配对层次错误

错误： 只数左、右大括号个数，不看它们围住了哪些语句。

原因： 大括号的数量和闭合层次都必须正确。

检查： 从 main 的左大括号开始向下追踪，使用统一缩进，让配对关系可见。

把注释当成待执行的说明

错误： 在注释里写“输出答案”，却没有真正的输出语句。

原因： 注释只供读者阅读，不作为普通语句执行。

检查： 暂时忽略注释文字，沿 main 内真正的语句重新追踪执行路径。

多行注释没有结束

错误： 写了 /*，忘记补上 */。

原因： 后续内容可能继续被当作注释，真正原因与报错行相距很远。

检查： 为每个 /* 找到对应的 */，并避免嵌套多行注释。
