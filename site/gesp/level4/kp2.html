参数与作用域

02
GESP 4级知识字典 · 知识点 02

区分形参与实参，理解局部与全局变量、作用域与遮蔽。

检索词：形参实参作用域

参数负责把数据送进函数，作用域决定一个名字在程序的哪些位置有效。调用函数、阅读同名变量或排查“变量未定义”时，要先找参数，再看局部变量和外层变量。

本课先记住

核心结论

实参在调用处提供数据，形参在函数内接收数据；查找同名变量时，从使用位置向外找最近的声明。

常用语法

int add(int left, int right) { // left、right 是本次调用的形参
    int sum = left + right; // sum 是只在函数体内有效的局部变量
    return sum; // 返回结果并结束本次调用
} // 离开函数体后，本次形参和局部变量的生命周期结束

最小示例

int value = 10; // 定义外层 value，值为 10
{ // 进入一个新的内层作用域
    int value = 3; // 定义内层同名变量并暂时遮蔽外层 value
    cout << value; // 最近声明是内层 value，因此输出 3
} // 内层 value 的作用域和生命周期在此结束

关键易错点

  • 把值参数当成调用处的原变量
  • 离开大括号后仍使用其中的局部变量
  • 看到同名变量就默认它是全局变量

这节课要会什么

本课建立三个核心：分清实参与形参；同时判断名字的作用域和对象的生命周期；遇到同名变量时从使用位置向外找到真正对象。

从这个场景开始

学校里可以同时有“全校积分”“班级积分”和“小组积分”三个同名概念。程序里的名字也有自己的有效范围：站在不同的大括号里，看到的可能不是同一个变量。

知识范围与官方定位

四级需要掌握形参与实参、局部变量、全局变量、作用域和生命周期，并能判断同名变量的遮蔽关系。

01 形参与实参

函数定义中用于接收数据的变量叫形参，调用表达式中真正提供数据的值、变量或表达式叫实参。`add(3, 5)` 里的 3、5 是实参，函数体里的 left、right 是形参。

一次调用开始时，程序先计算实参，再按位置把结果交给形参：第一个实参给第一个形参，第二个给第二个；并不是按名字对应。

每次调用都会重新创建一组形参。第一次 add(3,5) 的 left 与第二次 add(8,2) 的 left 名字相同，却是两次调用中的不同对象。

int add(int left, int right) { // 定义接收两个整数形参的加法函数
    return left + right; // 返回本次调用中两个形参之和
} // 本次调用结束时，left 和 right 随之销毁

int result = add(3, 5); // 3、5 是实参，按位置创建 left=3、right=5
关键提醒：不要只看变量名是否相同。实参与形参按位置和类型对应。

02 局部变量与生命周期

在函数体或一对大括号内部定义的普通变量是局部变量。作用域回答“源代码的哪些位置能使用这个名字”，生命周期回答“程序运行的哪段时间这个对象真实存在”，二者不能混为一句“括号里有效”。

局部变量通常从声明处开始可见；程序执行到声明并完成初始化后，对象才产生。离开所属代码块，对象销毁，名字也不能在块外使用。

若 if 条件为假，块内声明根本不会执行，bonus 对象不会产生；若条件为真，它只在本次进入代码块期间存在。

if (score >= 60) { // 条件成立时才进入这个局部作用域
    int bonus = 5; // 执行到此处才创建并初始化局部变量 bonus
    score = score + bonus; // 在 bonus 的作用域内读取它并更新 score
} // 离开代码块时 bonus 被销毁，名字也不再可用

03 全局变量与作用域

在所有函数外定义的变量通常具有全局作用域。从它的声明之后，后续函数可以按规则访问同一个对象；这个对象在程序开始阶段就存在，直到程序结束。

例如全局 count 初值为 2，函数执行 `count = count + 3` 后，main 再读取的是同一对象，因此得到 5。这与值参数“创建副本”不同。

全局变量共享范围大，任何能访问它的函数都可能改变它，排错时很难确认修改来源。能通过参数和返回值传递的数据，不应只为少写参数而改成全局变量。

  • 程序开始后，全局变量 count 先存在并初始化为 2
  • 函数执行 count = count + 3 后，共享的同一个 count 变为 5
  • 若改用参数和返回值，数据从哪里来、到哪里去会更清楚
关键提醒：全局可见不等于任何位置都可以随意修改。设计程序时仍应缩小可修改范围。

04 同名变量与遮蔽

内层作用域定义与外层同名的变量后，内层名字会暂时遮蔽外层名字。遮蔽不等于删除或修改：外层对象仍存在，只是这个名字在内层优先指向更近的对象。

阅读每一次使用时，从当前位置所在代码块开始，逐层向外寻找最近的同名声明。离开内层作用域后，内层对象销毁，外层名字重新成为最近声明。

同名写法合法却容易读错。教学和竞赛主程序应优先使用含义清楚的不同名字；这里保留同名只为训练识别规则。

int value = 10; // 创建外层 value，保存 10
{ // 进入内层作用域
    int value = 3; // 创建新的内层 value，暂时遮蔽外层同名变量
    cout << value << '\n'; // 最近声明是内层 value，因此输出 3
} // 内层 value 销毁，外层 value 重新可见
cout << value << '\n'; // 读取仍为 10 的外层 value

典型例题

追踪两次函数调用中的局部变量

程序使用固定数据 10 和 20，观察函数每次都从自己的局部变量开始计算。

完成程序

#include <bits/stdc++.h> // 引入本程序需要的标准库
using namespace std; // 允许直接使用 cin、cout、string 等标准库名称

int increase(int value) { // 定义把一个整数增加 1 的函数
    int result = value + 1; // 用本次调用的形参计算局部结果
    return result; // 把局部结果返回给调用处
} // 结束 increase 函数，本次调用的局部变量随之结束

int main() { // 主函数是程序的入口
    int value = 10; // 定义 main 作用域中的 value
    cout << increase(value) << '\n'; // 第一次调用使用实参 10，输出 11
    cout << increase(20) << '\n'; // 第二次调用重新创建形参并输出 21
    cout << value << '\n'; // 输出 main 中未被值传递修改的 value
    return 0; // 返回 0，表示程序正常结束
} // 结束 main 函数

解题与执行过程

  1. 第一次进入 increase 时，创建局部形参 value = 10。
  2. 函数内再创建局部变量 result = 11，return 把 11 交回 main。
  3. 第一次调用结束后，形参 value 和局部变量 result 的生命周期结束；第二次调用会重新创建它们。
  4. main 中的 value 属于另一个作用域，始终保持 10。

常见错误

把形参当成实参本身

错误写法：认为普通值参数 value 改变后，main 中同名变量也会改变。原因：值参数是副本。正确写法：先判断传递方式，再分别追踪实参与形参。

在作用域外使用局部变量

错误写法：在右大括号之后继续使用块内定义的 bonus。原因：名字已经超出作用域。正确写法：只在声明所在代码块内使用，或把变量定义到确实需要的外层。

同名变量遮蔽判断错误

错误写法：在函数内看到 x 就直接当成全局 x。原因：内层同名声明会遮蔽外层名字。正确写法：从使用位置向外寻找最近的同名声明。

滥用全局变量

错误写法：所有函数都直接读写同一个全局结果。原因：修改来源难追踪。正确写法：优先通过参数传入，通过返回值或引用明确传出。
