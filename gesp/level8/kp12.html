知识范围与官方定位

官方八级要求理解常见算法优化思路，能够从时间和空间角度改进算法。优化的前提是结果正确：先写清基础解法、分析瓶颈，再选择有依据的改进方法，并重新验证边界和复杂度。

01 基础解法与瓶颈

先写出能保证正确的直接方法，再分析最耗时或最占空间的部分。瓶颈可能来自重复计算、无效枚举、不合适的数据结构、过大的状态表或不必要的高复杂度算法。

优化目标必须具体。例如把两层枚举的 O(n²) 降为排序后的 O(n log n)，或者把只依赖上一行的 O(n²) 状态表压缩成 O(n) 空间。

02 剪枝

剪枝是在搜索过程中提前停止不可能得到合法答案或更优答案的分支。常见条件有：

  • 当前选择已经违反限制；
  • 即使使用剩余全部资源也无法达到目标；
  • 当前代价已经不小于已知最优答案；
  • 相同状态已经处理过，不必重复搜索。

剪枝必须有严格理由。错误地删除仍可能产生答案的分支，会让程序更快地得到错误结果。

03 预处理与数学规律

当许多询问反复使用相同信息时，可以先统一计算一次。例如前缀和把每次区间求和从 O(n) 降为 O(1)；杨辉三角预处理后可以多次查询组合数。

发现数学规律也能减少枚举。使用公式前必须核对适用条件、整数范围和取模要求，不能为了“看起来更快”直接套用未经证明的结论。

04 数据结构与算法替换

如果基础方法的瓶颈是反复查找，可以选择更合适的查找方式；如果图很稀疏，可以用邻接表替代邻接矩阵；如果问题目标已经有成熟算法，应使用与条件匹配的算法，而不是继续暴力枚举。

例如在有序数组中寻找和为目标值的一对数，可以用左右指针从两端向中间移动，把两层枚举的 O(n²) 降为排序后的 O(n log n)。

05 时间与空间的权衡

有些优化用更多空间换时间，例如预处理表；有些优化用更多计算换空间，例如不保存全部中间结果。选择时要同时满足时间限制和内存限制。

滚动数组可以降低空间，但可能让恢复完整方案变得困难；预处理可以加快询问，但若只查询一次，预处理成本未必划算。优化不是越复杂越好，而是让整体方案在题目约束下稳定通过。

优化前后追踪。 “判断数组中是否存在两个不同位置的数之和为目标值”的基线方案枚举所有数对，最多检查 n(n-1)/2 对，时间为 O(n²)。优化方案先排序，再用左右指针：

当前和与目标的关系 为什么这样移动 排除的范围
相等 已找到答案 结束
小于目标 左端太小，左指针右移 当前左端与更小右端的组合
大于目标 右端太大，右指针左移 当前右端与更大左端的组合

排序后扫描只移动至多 n-1 次，总时间变为 O(n log n)。优化后必须做反例验证：包含重复元素、全为负数、只有一个元素、答案不存在；还要检查排序是否会破坏题目要求保留原下标的附加条件。

逐段具体推演（对应 01—05）。

01 先量化基线。 对 n=100000、q=100000 的区间和查询，每次扫描整个区间最坏约做 nq=10¹⁰ 次加法。结果虽然正确，但数量级说明瓶颈就在重复扫描，而不是输入输出格式。

02 剪枝。 从正整数中搜索和为 10 的方案，当前和已经是 12 时，后面继续加入正数只会更大，这条分支可以立刻返回。若允许负数，就不能用同一条件剪枝，因为后面可能用负数把和降回 10。

03 预处理、公式与差分数组。 静态区间和可先建前缀和，把一次查询从 O(n) 降为 O(1)。若有多次区间加法，可在差分数组中对区间 [l,r] 执行 diff[l]+=x、diff[r+1]-=x，最后一次前缀累加还原全部值；素数查询很多时则可先筛出素数表。

04 更换数据结构或算法。 有序数组中查一个数，顺序扫描最多比较 n 次，二分查找每次排除一半，只需约 log₂n 次。两数之和从双重枚举 O(n²) 改为排序加双指针后是 O(n log n)，但必须保留“两个不同位置”等边界。

05 时间与空间权衡。 长度 n 的前缀和多用 O(n) 空间，换来每次 O(1) 查询；滚动数组则在依赖允许时减少空间。优化后要用普通、边界和极限数据比较新旧答案，再确认复杂度确实下降。

典型例题

输入 n 个整数和目标值，判断是否存在两个不同位置的数之和等于目标值。先排序，再用左右指针判断：

#include <bits/stdc++.h>using namespace std;
int main() {    int n;    long long target;    cin >> n >> target;
    vector<long long> a(n);    for (int i = 0; i < n; i++) {        cin >> a[i];    }    // 双指针依赖单调性，必须先排序。    sort(a.begin(), a.end());
    int left = 0;    int right = n - 1;    bool found = false;    while (left < right) {        long long sum = a[left] + a[right];        if (sum == target) {            found = true;            break;        } else if (sum < target) {            // 当前和偏小，左端右移才可能增大总和。            left++;        } else {            // 当前和偏大，右端左移才可能减小总和。            right--;        }    }
    if (found) {        cout << "YES\n";    } else {        cout << "NO\n";    }    return 0;}

排序为 O(n log n)，双指针扫描为 O(n)，总时间复杂度为 O(n log n)。

常见错误

优化后漏解反例。 两数之和目标为 6，数组是 [3,3]。若优化后错误规定“两个数值不能相等”，就会漏掉两个不同位置上的 3；正确限制是下标不同，而不是数值不同。新算法必须与基线在这个反例上都返回存在解。

  • 未证明剪枝条件正确就删除搜索分支。
  • 只比较某一行代码，不分析整体复杂度。
  • 优化后忘记重新检查边界、重复元素和整数溢出。
  • 为一次查询做代价很大的预处理，反而更慢。
  • 用超出内存限制的大表换取速度。

关联学习

  • 时间效率分析：定位操作次数增长最快的部分。
  • 空间效率分析：检查优化后的额外存储。

7 题

第 1 题准备优化一个已经能得到正确答案的程序时，最合理的第一步是什么？

答案：B
优化应从正确基线出发，先结合数据范围写出当前复杂度，再找到执行次数最多的瓶颈。否则即使代码变化很大，也不一定更快或仍然正确。
对应知识点：01

第 2 题需要回答大量静态数组区间和查询时，哪种做法最适合消除重复计算？

答案：B
前缀和把每个位置之前的累计结果预先保存。之后一次闭区间查询只需两个前缀值相减，可把每次线性求和优化为 O(1) 查询。
对应知识点：03

第 3 题使用左右双指针判断两数之和前，最关键的前提通常是什么？

答案：A
双指针根据当前和偏小或偏大来排除一侧候选，这个推理依赖数组的单调有序性。无序数组中直接移动指针可能跳过正确答案。
对应知识点：04

第 4 题用长度为 n 的前缀和数组把 q 次区间查询从 O(nq) 优化到 O(n+q)，还必须检查什么？

答案：B
该优化用额外 O(n) 空间换取时间，并会累计许多数值。必须同时核对内存限制与整数范围，不能只看到时间复杂度下降。
对应知识点：05

第 5 题搜索中已经确定当前分支不可能得到合法答案，最合适的处理是什么？

答案：B
提前识别不可能成功的状态并立即返回，可以避免继续枚举无效后续，这正是搜索剪枝减少工作量的基本思想。
对应知识点：02

第 6 题把两数之和算法改成“排序+双指针”后，哪组案例最能检查重复元素边界？

答案：A
两个不同位置可以保存相同数值。[3,3]、目标 6 能检查优化后是否错误地把“数值相同”当成“位置相同”，对应页内知识点 04。
对应知识点：04

第 7 题对数组区间 [l,r] 内每个数都加 x，使用差分数组时应怎样记录？

答案：A
diff[l]+=x 表示从 l 开始增加 x，diff[r+1]-=x 表示从 r+1 起取消这次增加。完成所有修改后做一次前缀累加即可还原结果。对应页内知识点 03。
对应知识点：03
